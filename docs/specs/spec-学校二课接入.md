> **术语**：一律取自 [GLOSSARY.md](../../GLOSSARY.md) 第 ④ 段——**学校二课** / **请求配方** / **请求配方下发** / **PU 平台凭据** / **记录**。

## 1. Problem Statement

学校二课（PU / 口袋校园，川农定制版「i川农」）是学生查询第二课堂学分、浏览并报名活动、现场扫码签到的**第三方平台**。它通过公网 `jk.sicau.edu.cn` 提供 JSON API，用 header `x-access-token` 认证，与教务（`jiaowu`）是两套完全独立的系统与凭据。

学生的现实困难：

- **要装第二个 App**。二课功能只在 i川农里，与农屿并列，学生被迫在两个 App 间切换。
- **毕业硬要求看不见**。第二课堂学分是毕业条件，农屿只展示教务成绩，学生无法一站式知道「还差多少」。
- **不知道怎么参加**。报名、现场扫码签到、签退的链路不透明。
- **后端拿不到任何二课数据**，将来做活动聚合无从下手。

同时，这个平台有两个让实现者容易踩空的特点：

- **离线 APK 样本不可信为契约**。`work/iciannong-apk/` 是 2024-03 的离线样本，实测已证实**三处漂移**（见 §7）。
- **凭据本身没有派生层**。`x-access-token` 就是凭据，平台**无 refresh / renew / logout 端点**，拿到即用到底。

---

## 2. Solution

**客户端的读写都在客户端，后端只做两件事：下发请求配方、记录。**

- **客户端**持本人 **PU 平台凭据**（`x-access-token`），直接向二课平台发起全部读写请求。
- **后端**：
  1. **请求配方下发**——告诉客户端「这个逻辑动作要请求哪个地址、用什么方法、有哪些参数槽位」，**只给槽位不给值**。
  2. **记录**——审计流水（必有）+ 数据副本（尽力而为）。

**后端对二课零出站、零凭据。** 这既不是性能选择也不是架构洁癖，是安全边界：后端不持有凭据，就不存在「库泄露 = 二课账号泄露」的风险；后端不代发，就不存在「代用户做了他没授权的事」的可能。

覆盖范围：**A 二课学分/成绩单（13 接口）+ B 活动（48 接口）= 61 接口**。其中**读 47 / 写 14**（学生视角 47:10，读占 82%），因此读类走缓存形态、写类走独立配方。

## 3. 横切口径

本节定义所有能力共享的规则，下文各节直接引用，不重复。

### 3.1 信封

- 本仓**不复制**二课平台的响应壳。二课响应由客户端直接消费，后端完全不接触。
- 后端自己的响应：错误用 `{code: string, message: string}`（camelCase）；**成功响应不带 `code` 字段**。
- **二课 `content` 里的业务字段后端完全不接触**（零出站的推论）。

### 3.2 错误码两张表

**表 A · 后端产生的**（本仓定义，可枚举）：

| code | 触发 |
| --- | --- |
| `target_denied` | 请求的逻辑目标不在白名单 |
| `unauthorized` | 无有效农屿会话 |
| `session_expired` | 会话过期 |
| `cache_unavailable` | 缓存未配置（Redis 缺失） |
| `rate_limited` | 触发限流 |
| `invalid_payload` | 回传体超限或 schema 不合格 |
| `unknown_datatype` | dataType 不在受控词表 |
| `internal_error` | 其他 |

**表 B · 客户端本地错误态**（后端**不定义、不可能看到**）：

- PU 平台返回的非零 `code`（含 `5` token 失效）。
- **本仓不为 `code=5` 定义任何错误码**。后端永远看不到它——它是客户端拿到二课响应后自己判定的状态。定义了纯属噪声且会误导实现者以为后端能处理。

### 3.3 鉴权

- 新增端点**全部需农屿会话**，一个都不进 `publicPaths`。
- **不新增** `publicReadablePaths` 条目——二课数据全是本人视角，没有公开可读内容。
- 两份清单**共用同一个 `IsPublicPath`**，不新增第三份。
- `userID` **只从上下文取**，绝不接受请求体里的 userID。

### 3.4 盲区（须原样进实现与文档）

> **后端对二课全部请求无观测能力，不代发、不转发、不缓存其响应，无法限流、无法记审计、无法判定失败原因；不得声称已限流或已审计。**

- 审计 action：`secondclass.recipe_issue`（配方下发）、`secondclass.record`（副本写入）。只记 `AuditEntry` 六字段，不加字段。
- 任何对外文案、日志、埋点**不得出现**「所有请求均已限流」「已全量审计」这类表述。

### 3.5 NY1 签名

- **配方端点与记录端点都要签**，**不新增豁免**（`IsAppSignExempt` 仍只豁免 `/healthz` 与 `/admin/*`）。
- 客户端直连二课那一段与 NY1 无关——它不经过本仓。

### 3.6 脱敏

- **全禁入日志/审计/埋点/错误信息/接口响应**：`x-access-token`、GPS 坐标、扫码时间戳、二维码内容、二课响应体。
- **配方只给「槽位」不给「值」**：参数名 `actId` 可以出现，`actId=12345` 不可以。

## 4. User Stories

### 4.1 二课学分与成绩单

1. 作为学生，我想在农屿看到累计与本周期的第二课堂学时，这样我不用打开第二个 App 就知道离毕业要求还差多少。
2. 作为学生，我想看到学时按「德智体美劳」分项的占比，这样我知道自己偏科在哪。
3. 作为学生，我想按学期查看学分明细（哪个活动给了多少分），这样我能核对某次活动到底有没有被计入。
4. 作为学生，我想看到申请类学分的处理状态，这样我知道提交的学分申请走到哪一步。
5. 作为学生，我想看到诚信值以及它是怎么被扣的，这样我知道报名后爽约的代价。
6. 作为学生，我想看到学分规则说明，这样我理解「什么算、怎么算」，而不是只看到一个不解释的数字。
7. 作为学生，我想看综测明细与班级/专业/年级/全校排名，这样我知道自己的相对位置。
8. 作为学生，我想按类别查看学分明细（如只看体育类），这样我能针对性地补短板。
9. 作为学生，我想生成并预览个人成绩单，这样我能在评优评先前确认它长什么样。
10. 作为学生，我想自己决定成绩单上展示哪些项（总分/班级排名/专业排名/年级排名/全校排名/分项/具体记录），这样我控制对外展示的信息量。
11. 作为学生，我想保存成绩单设置后下次进来还是我选的样子，这样我不用每次重设。
12. 作为学生，我想看到导入类学分的批次明细，这样我知道学校批量导入的学分有哪几批。
13. 作为学生，我想在没有任何二课记录时看到「暂无记录」而不是报错或空白，这样我知道是没数据而不是坏了。

### 4.2 活动浏览

14. 作为学生，我想按类型、等级、部落、关键词筛选活动列表，这样我能快速找到自己能参加且感兴趣的活动。
15. 作为学生，我想按活动名称搜索，这样我知道活动名就能直接找到它。
16. 作为学生，我想看到活动详情（时间、地点、名额、主办方、主办部落、主办学院、报名条件、已报名人数），这样我判断是否值得报名。
17. 作为学生，我想看到活动当前状态（报名中/进行中/已结束/已取消），这样我不会点进一个已经结束的活动。
18. 作为学生，我想看到活动已报名成员列表，这样我了解参与人群。
19. 作为学生，我想看到活动的评价列表与评价标签，这样我报名前能参考别人的反馈。
20. 作为学生，我想看到活动花絮（图文记录），这样我能了解活动实际是什么样。
21. 作为学生，我想看到我校的活动类型、等级、标签字典，这样筛选器里出现的是我校实际有的选项。
22. 作为学生，我想看到可选的部落分组与学校分组，这样我能按组织维度浏览。
23. 作为学生，我想看到我的收藏活动列表，这样我能回到之前标记过的活动。
24. 作为学生，我想看到我参与过的活动列表，这样我能回顾自己的二课履历。
25. 作为学生，我想看到我的报名/签到状态，这样我确认自己到底报上没有。
26. 作为学生，我想看到我所在学院与班级信息（用于活动报名范围判定），这样我知道哪些活动对我是可见的。
27. 作为组织者，我想看到我管理/可审核的活动列表，这样我能集中处理待办。

### 4.3 活动报名与签到（写类）

28. 作为学生，我想在 App 内完成活动报名，这样我不用切到 PU 客户端。
29. 作为学生，我想到现场扫码签到，这样我的到场被如实记录、诚信值不受影响。
30. 作为学生，我想在现场签退，这样完整参与的活动能拿到全部学分。
31. 作为学生，我想在扫码时由 App 现场生成时间戳，这样签到时间反映的是我真实到场的那一刻，而不是某个可被预填的值。
32. 作为学生，我想让 App 用我的真实 GPS 坐标完成位置签到，这样我不用手动填地点。
33. 作为学生，我想在活动结束后提交评价（标签 + 文字 + 评分），这样我的反馈能影响后续活动质量。
34. 作为学生，我想收藏/取消收藏活动，这样我能管理自己的关注列表。
35. 作为学生，我想一键清空我的收藏，这样我不用一个个取消。
36. 作为学生，我想上传活动花絮，这样活动留下可回溯的记录。
37. 作为学生，我想删除自己发过的花絮，这样我能撤回发错的内容。
38. 作为组织者，我想在农屿内发布活动，这样我不必切回 PU 客户端准备活动。
39. 作为组织者，我想编辑已发布活动的信息（时间、地点、名额、可见范围），这样我能应对临时变更。
40. 作为组织者，我想调整报名成员的审核状态，这样我能处理报名审批。

### 4.4 凭据与登录

41. 作为学生，我想明确知道「农屿不需要我的二课密码」，这样我敢用这个功能。
42. 作为学生，我想在二课凭据失效时被明确提示并引导重新登录 PU，而不是看到一个含糊的「请求失败」。
43. 作为学生，我想退出农屿登录后，任何二课相关凭据都不残留在服务端，这样我换设备后不担心被人接着用。
44. 作为运维者，我想在服务端代码里搜不到任何二课凭据的存储路径，这样我能确认边界没被破坏。

### 4.5 记录与可观测

45. 作为维护者，我想知道「谁在什么时候问了哪个请求配方」，这样出现问题能追溯。
46. 作为维护者，我想在后端留有二课数据的只读副本（当客户端愿意回传时），这样将来做活动聚合有数据基础。
47. 作为维护者，我想清楚知道后端**没有**观测到客户端直连那一段，这样我不会误以为已有全量限流与审计。
48. 作为维护者，我想看到某个 dataType 的副本是「从未回传」还是「回传过但已过期」，这样我能区分「客户端没分享」和「缓存过期」。
49. 作为维护者，我想审计记录不因为磁盘满而阻断业务请求，这样记录失败不会变成功能故障。

### 4.6 失败与边界

50. 作为学生，我想在网络不可达时看到「这是本地网络问题」而不是「服务器错误」，这样我知道该找谁。
51. 作为学生，我想在我重复扫码时得到明确结果（成功 / 已签到），而不是不确定状态。
52. 作为学生，我想在 token 失效时被引导重新登录 PU 而不是重试到天荒地老。
53. 作为维护者，我想在文档里看到「二课 token 无 refresh/吊销、有效期未知」，这样我做安全评估时不高估防护。
54. 作为维护者，我想在客户端回传了形状不符的 JSON 时，旧数据仍然可读，这样一次坏回传不会毁掉已缓存的正确数据。
55. 作为维护者，我想在未配置 Redis 时，配方端点仍然可用，这样部署环境不完整时核心功能不瘫。
56. 作为维护者，我想在请求未知 dataType 时得到明确拒绝，而不是把它拼进缓存键，这样我不会被构造 key 攻击。

## 6. 数据契约

**本节是 Spec 与 PRD 的真正分界。** 第 7 节记录了本节哪些结论来自实测、哪些曾是错的，**读本节时必须同时读第 7 节**。

### 6.1 端点（三 + 一）

全部需农屿会话 + NY1 签名，全部落在 `/school/secondclass/` 前缀下。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/school/secondclass/cache/:dataType` | 读副本。命中直返；未命中回 `cache_miss` **并捎带配方** |
| `POST` | `/school/secondclass/cache/:dataType` | 客户端自愿回传数据副本（schema 校验后写入） |
| `DELETE` | `/school/secondclass/cache/:dataType` | 副本失效（60 秒节流） |
| `GET` | `/school/secondclass/recipe/:recipeId` | **仅写类**配方下发 |

**为什么读类合并进 `cache_miss`、写类独立**：读类请求本来就要先 GET，未命中时正好捎带配方，客户端一次往返拿到；写类（报名/签到）不经过 GET，**没有「未命中」这个时机**，必须独立入口。

**与教务对称**：`/school/jiaowu/cache/:dataType` 与本节的 `/school/secondclass/cache/:dataType` 形状同构，客户端可复用同一套处理逻辑。

### 6.2 成功响应形状

**读副本（命中）**：

```
{
  "payload": <客户端回传的原始 JSON，原样透出>,
  "schemaVersion": <int>,
  "fetchedAt": "<RFC3339>",
  "stale": <bool>
}
```

- `payload` 用 raw JSON 透出，**不重新序列化**——它可能是数组、单对象或 null，用 `map` 接会丢掉数组形态。字段名沿用教务侧的既有形状（`payload`/`schemaVersion`/`fetchedAt`/`stale`），不新增。
- `stale: true` 表示已过新鲜度窗口但仍可读。

**未命中（`cache_miss`）**：

```
{
  "code": "cache_miss",
  "message": "<人读文案>",
  "recipe": { <见 6.3> }
}
```

**配方（写类）**：直接返回 6.3 的 `recipe` 对象。

### 6.3 配方形状（七字段）

```jsonc
{
  "id": "secondclass.activity.signInOrOut",
  "target": "secondclass",
  "method": "POST",
  "path": "/act/actInfo/v1.0.0/signInOrOut",
  "contentType": "form",
  "auth": { "in": "header", "name": "x-access-token", "from": "client" },
  "params": [ /* 见 6.4 */ ],
  "fields": [ /* 见 6.5；无文件时为空 */ ],
  "headers": [ /* 见 6.6 */ ]
}
```

| 字段 | 说明 |
| --- | --- |
| `id` | 稳定标识，形如 `secondclass.<资源>.<动作>`。**客户端按 id 要配方，不按 URL**——这样后端能改路径而不破坏客户端 |
| `target` | 逻辑目标名，固定 `secondclass`。**调用方永不传 host** |
| `method` | `GET` / `POST`（二课写操作全是 POST） |
| `path` | 二课端点路径。**注意部分路径含双斜杠**（如 `/act//credit/…`），属上游原样，不得「修正」 |
| `contentType` | `form` / `multipart` / `none` |
| `auth` | 凭据放哪、叫什么、谁提供。`from: "client"` 表示客户端持有 |
| `params` | 参数槽位数组 |
| `fields` | multipart 文件字段 |
| `headers` | 必需请求头（见 6.6，**实测必需**） |

**明确不含**（相对教务侧的删减）：

- **不含 `parser`**——二课是 JSON API，没有解析 HTML 这一步。
- **不含 `session` 状态位**——后端不建会话，此态不存在。
- **不含 `cookies[]`**——二课凭据是 header，不是 cookie。

### 6.4 参数槽位

```jsonc
{ "name": "qrCodeTimestamp", "required": true, "origin": "client_local", "note": "扫码瞬间的毫秒时间戳" }
```

`origin` 三值：

| 值 | 含义 | 实例 |
| --- | --- | --- |
| `client_local` | **必须客户端现场产生，后端绝不代填、绝不伪造** | `qrCodeTimestamp`、`signUpLong`/`signUpLat`、`codeTime`、`gpsCode` |
| `fixed` | 配方直接给的常量，客户端照填 | 某些固定 `type`/`version` |
| `optional` | 可选 | 分页 `page`、筛选 `status` |

**硬约束**：`origin: client_local` 的参数，**后端既没有它的值，也不该有**。GPS 坐标、扫码时间戳、诚信值扣分是「本人当场发生」的事实，后端伪造即为造假——这是整个设计的第一性理由。

### 6.5 文件字段

```jsonc
{ "name": "file", "required": false, "kind": "file", "note": "封面图；客户端直传，后端不中转" }
```

活动花絮、活动封面走 multipart。**字节流由客户端直传二课，后端不碰。**

### 6.6 必需请求头

**实测：以下 7 个设备头全部必需，缺任一个服务端会返回误导性错误码。**

| 头 | 说明 |
| --- | --- |
| `pu-version` | 客户端版本，如 `12.10.0.10010599` |
| `client-dev-brand` | 设备品牌 |
| `client-dev-type` | 设备型号 |
| `client-os-type` | 固定 `android` |
| `client-os-version` | 系统版本 |
| `client-long` | 经度（无 GPS 时 `0`） |
| `client-lat` | 纬度（无 GPS 时 `0`） |

配方以 `headers` 数组表达，形状：`{ "name": "...", "value": "..." }`；其中 `pu-version` 等属 `fixed`（由配方给常量），`client-long`/`client-lat` 属 `client_local`。

### 6.7 多跳（`steps`）

**默认单跳。** 仅在「先取再写」确实需要时使用：

```jsonc
{
  "id": "secondclass.activity.signInWithLookup",
  "steps": [
    { "ref": "secondclass.activity.getActMemberList" },
    { "ref": "secondclass.activity.signInOrOut",
      "params_from": { "memberId": "$.steps[0].content[0].memberId" } }
  ]
}
```

**三条边界**：

1. `steps` 只是「引用 + 取值路径」，**不是后端驱动的控制流**（无重试、无分支、无条件跳转）。
2. 取值路径由**客户端自己解析**——后端拿不到响应。
3. **能不写多跳就不写。**

### 6.8 dataType 受控词表

**必须过白名单**（`ParseDataType`），未知名一律拒绝，**绝不把用户输入直接拼进缓存键**。

按能力分组（每组对应一个 dataType）：

**A 组（13 个接口 → 按数据形态归并为若干 dataType）**

| dataType | 语义 | 覆盖接口 | TTL 组 |
| --- | --- | --- | --- |
| `secondclassCredit` | 学期学时总览（单对象） | `getSecondActivityCredit` | 长 |
| `applyCredit` | 申请类学分 | `getApplyCredit` | 长 |
| `creditRule` | 学分规则说明 | `getCreditRuleExplain` | 最长 |
| `goodFaithValue` | 诚信值 | `getGoodFaithValue` | 中 |
| `creditRecordDetail` | 学分明细（数组，两层嵌套） | `getCreditRecordDetail` | 长 |
| `importCreditDetail` | 导入批次明细 | `getImportCreditDetail` | 长 |
| `perIntegrateDetail` | 综测明细 | `getPerIntegrateDetail` | 长 |
| `ranking` | 排名 | `getRanking` | 长 |
| `reportCard` | 成绩单 | `myReportCard` | 长 |
| `reportCardSetting` | 成绩单设置 | `reportCardSettingView` | 长 |
| `creditDetailOfType` | 按类别学分明细 | `getCreditDetailOfType` | 长 |
| `reportCardPreview` | 成绩单预览 | `previewReportCard` | 短（不入缓存亦可） |

**写类 14 个不建 dataType**——写不落缓存，只走配方。

### 6.9 缓存键

```
nongyu:cache:<userID>:<dataType>
```

**全部按用户隔离，不做共享键。**

理由：实测 `ActDetailVo` 混有用户态字段（`collectFlag`、`signInTime`、`signBackTime`、`currentUserButton`、`evaluationScore`、`triviaStatus` 等），`ActivityMainVo` 命中 7 个用户态字段。**共享键必然串数据**——甲的收藏状态会显示给乙，这是数据错误不是性能问题。

**已知代价（明确接受）**：N 个用户看同一个活动就存 N 份几乎相同的 JSON，存储放大 N 倍。

**优化口子（不在本期）**：`GroupListVo` 与 `MemberListVo` 实测 **0 个用户态字段**，量上来后**只拆这几类**为共享键；`getActDetail` 这类混合类仍按用户存（拆两份的复杂度不值）。触发条件：Redis 内存或缓存命中率指标显示需要时。

### 6.10 TTL 与新鲜度

**两组语义必须分开**（沿用教务侧既有区分）：

- **缓存 TTL**：键多久后消失、变 `cache_miss`。
- **新鲜度窗口**：多久后标记 `stale: true`，但仍可读。

按**数据变化频率**分组（不是按接口分组）：

| 组 | 范围 | 建议区间 |
| --- | --- | --- |
| 短 | 活动列表、活动详情（名额/状态变化快） | 10~15 分钟 |
| 中 | 诚信值、活动评价 | 30~60 分钟 |
| 长 | 学分、综测、排名、成绩单、基础字典 | 6~12 小时 |
| 最长 | 规则说明 | 24 小时 |

具体数值在实施时定（见 §9 ②）。

### 6.11 两条记录线

| | 线 A：审计流水（**必有**） | 线 B：数据副本（**尽力而为**） |
| --- | --- | --- |
| 记什么 | `requestID`/`userID`/`action`/`target`/`result`/`occurredAt`（沿用 `AuditEntry` 六字段，**不加字段**） | 客户端回传的 JSON，按 dataType 存 |
| 何时 | 每次配方下发 + 每次副本写入 | 客户端真取了并回传时 |
| 失败 | 不阻断主流程，满则丢弃计数 | **本就是常态**，不得当错误 |
| 可信度 | 后端亲眼所见 | **不可验证真伪** |
| 用途 | 追溯 | **只能作「已知内容的只读副本」，不能作权威来源** |

**两条线不可合成**：触发条件不同（必然 vs 可能）、可信度不同（可靠 vs 自述）、失败语义不同（旁路丢弃 vs 常态）。合成必然出现「把不可信副本当审计用」或「把必然的审计降级为尽力而为」，两种都错。

**硬约束**：不得把数据副本用于对外展示、榜单一类统计或任何需要权威性的场景。

### 6.12 回传体限制

- 单次回传 ≤ **1 MiB**，超限返回 `invalid_payload`。
- 失效（DELETE）节流 **60 秒**。
- stale 上限 **7 天**（超过视为不存在）。
- schema 校验不通过 → 返回 `invalid_payload` **且不写入**，旧数据仍可读。

## 7. 一手实测与静态分析的差异

> **本节必须存在。** 本 effort 与前三个 effort 收口时的关键不同：前三个（#1/#30/#43）上游事实全来自 DEX 静态分析、**没有真实响应**；本 effort 有 #70 的真实采集，且**推翻了三条静态结论**。
>
> **散写进第 6 节会让读者把修正后的值当既定事实**，看不出它曾是另一个样子、也看不出静态分析错过；只放附录又会被当脚注忽略。因此单列本节，**第 6 节已显式引用它**。

### 7.1 三条被推翻的假设

| # | 离线样本说 | **线上实测** | 影响 |
| --- | --- | --- | --- |
| 1 | 信封字段叫 `data` | **`content`** | §6 的 `payload` 透出的是 `content` 的内容；schema 顶层结构按实测 |
| 2 | `code` 是 `int`（`BaseResponse`）或 `String`（`RespVO`），二选一 | **两者并存**：成功 `"0"`（字符串）、未登录 `6`（数字） | 客户端必须按**双类型**判；本仓不为它定义错误码 |
| 3 | 登录路径 `login/v1.0.0/…`；`sid` 是数字 `3074421` | **`/user/login/v1.0.0/…`**（多 `user/` 前缀）；**`sid` 是学校 UUID**（川农 `f1c97a0e81c24e98adb1ebdadca0699b`） | 登录类端点是 D 组（客户端自理），但**路径漂移说明整个 APK 已过时** |

### 7.2 四条只有实测才能拿到的事实

1. **7 个设备头全部必需**（§6.6）。缺任一个，服务端返回**误导性错误**——同一请求缺头时报「用户不存在 `2`」，补齐后报「手机格式错误 `104`」。**这会让排查者误判成账号问题。**
2. **失败时 HTTP 仍是 200**，业务码在 body。错误映射不能只看 HTTP 状态码。
3. **上游字段拼写错误须原样保留**：`fistActTypeId`（缺 `r`），旁边却叫 `firstActTypeName`。**schema 不得「修正」它。**
4. **字段类型与 VO 声明不符**：`totalScore` 实测是**数字** `11.0`，VO 声明 `String`。→ **schema 一律以实测为准。**

### 7.3 证据等级铁律（约束本 Spec 全文）

- 离线 APK 是 **2024-03** 产物，**契约会漂移**。
- 凡「按离线样本写死」的结论，**必须标注「待真网络确认」**；能实测就实测。
- 声称「产物里没有 X」之前，先过：接口清单的返回泛型 → VO 字段清单 → 网络层 IL。
  **证据等级铁律不只是「别编」，也是「别漏查」。**
- **本节只记 #70 实测「确证 / 推翻」了什么，不记它需要但没拿到的事实。** #70 是有数据态、无 token 态与读/写参数的采集，**没有**覆盖空态、过期 token、写操作副作用、二维码时效、GPS 校验、限流维度与运行时字段值。那 8 项在 **§10.1 ④「需实测」** 逐条标「未验证 + 保守设计」，**不因本节有「实测」二字就被当作已验证**（#78 逐条复核，全部保持未验证）。

### 7.4 与教务的语义差异（形态同构，约束强度不同）

| | 教务 | 二课 |
| --- | --- | --- |
| cache 性质 | **必须回传**——前端解析 HTML 后不回传，下一个人拿不到 | **愿意才回传**——客户端拿到 JSON 就能直接用，回传纯属分享 |
| 数据副本命运 | 通常有数据 | **可能一直是空** |

**不写清这一点，实施者会误以为二课的数据副本也一定有，实际可能是空表。**

## 8. Testing Decisions

### 8.1 什么算好测试

**只测外部行为，不测实现细节。** 判据：

- 断言 HTTP 状态码、响应体、可观察副作用，**不断言内部函数被调用几次**。
- 一个测试只表达一条业务规则。
- 测试名描述行为（「未命中时响应体含配方」），不描述实现（「调用 buildRecipe」）。

### 8.2 两层接缝（沿用 #60 已确认的口径）

**层一 · 纯函数单测**（无 IO）：

- 配方表完整性：61 个 `id` 唯一、槽位合法、`origin` 取值合法。
- dataType 受控词表与 TTL 分组映射。
- `go:embed` schema 在启动期全部编译通过（fail-fast）。
- **`code` 双类型解析**：字符串 `"0"` 与数字 `6` 都要能正确判定。
- 脱敏规则：确认 token/GPS/扫码时间戳/响应体不出现在任何输出路径。

**层二 · HTTP 集成测**（fake `CacheStore` + fake `AuditStore`）：

- 未认证 → 401。
- 未知 recipeId → 400；未知 dataType → 400。
- **读类未命中：响应体内必须含完整配方**（这是与教务同构的关键断言）。
- 命中：`payload` 原样透出，数组形态不被破坏。
- 回传体超 1 MiB → `invalid_payload`。
- schema 不合格 → `invalid_payload` **且旧数据仍可读**。
- stale 回落在新鲜度窗口过后生效。
- 未配置 Redis → 配方端点仍可用，记录端点不挂。

**唯一用真实外部依赖的一处**：TTL 与新鲜度窗口拆两个语义的那段行为，用真 Redis 验证。

### 8.3 测试夹具

**二课响应一律用 `testdata/secondclass/` 的真实采集样本替代**，不访问真实平台。

已备：`real-2026-11-16/` 下 3 份（学期学分单对象、学分明细数组、未登录失败），README 记录采集日期与脱敏口径。

### 8.4 不进本仓测试接缝

- **客户端直连二课那一段**——后端零出站，测不到也不该测。
- 任何依赖真实二课网络行为的用例。

### 8.5 先例

`schoool/jiaowu` 的 cache 子域已有 25 个同类集成用例，本 Spec 的测试形状与之对齐（同构端点、同构断言），便于复用测试辅助函数。

## 9. Out of Scope

**以地图 #58 的 Out of Scope 段为准**（比 PRD 摘录更全）。

- **配方按角色分发**（组织者 vs 学生）——本期 61 个配方全量下发，不按角色裁剪。

| 项 | 已知什么 | 缺什么 | 保守设计 |
| --- | --- | --- | --- |

| 二维码 `qrCodeTimestamp` 时效 | 知道它是扫码瞬间时间戳 | 有效时长 | 客户端取当前时刻填入；不做事后重放校验（后端无值） |
| GPS 校验规则 | 知道 `gpsCode`/`signUpLong`/`signUpLat` 是设备产生 | 学校侧的校验半径与容差 | 只透传客户端真实值，**绝不代填**（§6.4） |
| 限流按账号还是 IP | 知道平台有风控 | 维度与阈值 | **不得声称已限流**（§3.4 盲区措辞）；不因「推给客户端」而放松本仓鉴权 |
| 活动详情运行时是否带 `gid`/`groupName` | 静态已确认 `ActDetailVo` 有 `gid`/`groupName`/`schoolName`/`allowCollegeNames` 字段 | 运行时是否真有值 | schema 按「可空」写，不要求必填 |

> **#78 收敛结论（逐条核对，全部「保持未验证 + 保守设计」）**：本票按 [PRD §7.1](<prd-学校二课接入.md>) 与 #70 采集记录逐条复核了上表 8 项，**没有一项毕业为已验证**。消掉不确定性的正确方式是查证，不是改口径——#70 只测了有数据态、无 token 态与读类写类参数，无法覆盖空态、过期 token、写操作副作用、二维码时效、GPS 校验、限流维度与运行时字段值；这些都要真账号现场或真网络，且测写操作会污染真实数据，本 effort 明确不做。逐条结论：
>
> 1. **空态 `content` 是 `[]` 还是 `null`** — 保持未验证；schema 继续 `oneOf: [array, null]`（当前 schema 已是此形状）。#70 采的是有数据态。
> 2. **分页响应总数字段名** — 保持未验证；schema 继续不写死总数字段（`actList.json` 等只校验 `content` 是数组）。
> 3. **`code=5`（token 失效）真实形态** — 保持未验证，且**本仓不定义该错误码**（后端看不到它，§3.2 表 B）。#70 测的是「无 token」→ `6 用户未登录`，过期 token 未测。
> 4. **写操作副作用与重复提交** — 保持未验证；幂等责任在客户端 + 二课侧，后端不承接（§6.3 无重试）。
> 5. **二维码 `qrCodeTimestamp` 时效** — 保持未验证；客户端取当前时刻，后端无值、不做事后重放校验。
> 6. **GPS 校验规则** — 保持未验证；只透传客户端真实值，绝不代填（§6.4）。
> 7. **限流按账号还是 IP** — 保持未验证；无论结论如何**不得声称本仓已限流**（§3.4 盲区措辞）。
> 8. **活动详情运行时是否带 `gid`/`groupName`** — 保持未验证；静态已确认 VO 有字段，但运行时是否有值未验，schema 保持可空。
>
> 本票**不为了消除这张列表而把任何未验证写成已验证**；文档该写「未验证」的地方继续写「未验证」。PRD §7.1 里被 #70 / 静态清单毕业的那几条本就不在这 8 项 pending 里（见 §7 与 PRD §7.1 的分级说明）。

### 10.2 依赖策略

本 Spec **不引入任何新第三方依赖**——`jsonschema` 已在 `go.mod`，缓存/审计/时钟全是现成的。故**不产生根 `AGENTS.md` 的「停用即删」删除义务**。

### 10.3 与教务的复用边界

**复用**：`CacheStore`（从 `jiaowu` 上移到 `platform`，`jiaowu` 改为类型别名）、两层测试形状、schema 启动期编译、TTL 与新鲜度拆两语义。

**不复用**：`parser`（HTML 解析器名）、`session` 状态位、`cookies[]`——三项都是教务场景专有。

**不 import 兄弟域**：需要画像走 `platform.UserRepo`，需要缓存走 `platform.CacheStore`，不 `import` `internal/identity` 或 `internal/school/jiaowu`。

### 10.4 实施顺序建议

1. **先做 `CacheStore` 上移到 `platform`**（接口搬家，方法集一字不改，`jiaowu` 改别名）——这是唯一触及既有代码的 prefactoring，先做完再动新域。
2. 再建 `school/secondclass/` 骨架：配方表 + dataType 词表 + schema 编译。
3. 再挂端点（读三写一）。
4. 最后接记录子域（审计 + 副本）。

## 11. 与既有设施的关系（不动清单）

**本节原样收录 [决策-二课横切口径.md](<../tech/决策-二课横切口径.md>) §七的 11 条，一条不漏。实施时不得改动任何一条。**

1. **`publicPaths` 现为四条**（`/healthz`、`/identity/login`、`/identity/mailcode`、`/identity/register`），本 effort **不增不减**。
2. **`/status` 不在 `publicPaths`、不免 NY1 签名**——它是内部基础设施测绘面。**2026-11-16 前的「五条含 /status」说法已作废，不得按旧口径写回。**
3. **`publicReadablePaths` 不新增条目**（二课数据全是本人视角）。
4. **两份清单共用同一个 `IsPublicPath`**，不新增第三份。
5. **`IsAppSignExempt` 只豁免 `/healthz` 与 `/admin/*`**，本 effort 不加豁免。
6. **不新增限流实现**：沿用既有 `RateLimitMiddleware`（默认 60/分钟，进程内滑动窗口）。
7. **中间件链顺序不变**：`RequestID → NY1（适用时）→ 鉴权 → AdminOnly（仅 /admin）→ 限流`。
8. **信封不动**：错误用 `{code, message}`，**成功不带 `code`**，camelCase。
9. **`CtxUserID` 契约键与「只从上下文取身份」不动**。
10. **审计 `AuditEntry` 六字段不动**，不为其加字段。
11. **`/status` 的 5 个字段**（process/postgres/redis/breaker/storage）**不增不减**——只是它现在要签名+会话才能读。

> **⚠️ 与 #51 先例的差异（必须记录）**：#51（六类功能）的不动清单第 1 条写「`/status` 保持公开且限流豁免」。**那条现已作废**——`/status` 已在 0-day 修复中移出 `publicPaths` 且取消免签。**照抄 #51 会把这个已修的安全问题写回契约。**
