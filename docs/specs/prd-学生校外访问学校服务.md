# PRD：学生校外访问学校服务（WebVPN 承载能力）

> 本 PRD 是 SDD 链路（`README.md:79` PRD → Spec → 技术方案 → 实施计划 → 编码）的第一环，先于规格存在。
> 规格见 GitHub issue #10（`Spec：新后端承载学校 WebVPN 能力`）；本文只回答「为谁、解决什么问题、做到什么程度算成」，不描述实现。
> 术语一律取自 [GLOSSARY.md](../../GLOSSARY.md)，边界一律引用 [ADR-0001](../adr/0001-服务端代请求边界由新后端重写.md)。
## 一、背景

四川农业大学学生在校内可以直接访问教务系统；离校后（宿舍、实习、通勤、假期）必须经学校 WebVPN 网关才能到达。旧农屿客户端把这段路完整地写在移动端里：URL 编码、直连判定、门户与教务两套 CAS 换票、HttpOnly 票据持久化，全部绑死在客户端与 Android 原生 Cookie 罐上。

这带来三个现实问题：

1. **换客户端等于重写**：任何新的前端形态都得把整套 WebVPN 与换票逻辑再抄一遍。
2. **换设备等于重新登录**：票据只存在客户端，冷启动失败或换机就要重输验证码。
3. **加业务线没有落点**：后勤、二课等新业务要接学校服务时，没有可复用的服务端能力。

## 二、目标用户与场景

| 用户 | 场景 | 现在怎么受苦 |
| --- | --- | --- |
| 学生（校外） | 查课表、成绩、考试、通知 | 要自己打开浏览器登录学校 VPN；票据丢了就重输验证码 |
| 学生（校内/校外切换） | 从宿舍网切到 4G，或反之 | 需要重新登录，状态判断全靠客户端猜 |
| 后续接手的开发者 | 新增客户端或业务线 | 没有可复用能力，只能再抄一遍旧代码 |
| 运维 | 上线与扩缩容 | 状态在客户端，后端无法统一限流、审计、排障 |

## 三、需求（按优先级）

### P0：必须做到

1. **调用方不需要认识 WebVPN**。客户端只传「我要访问谁」这样的逻辑目标名，不自己拼网关地址、不自己判断校内校外。
2. **主路径一定能用**。账密 + 图形验证码必须始终可用；任何加速手段失效都要能回落到它。
3. **票据能跨会话复用**。登录态外置保存，换设备/冷启动不必重新输码；票据不得进日志、不得进埋点，退出即清。
4. **失败要能区分**。「票据失效」「业务会话失效」「校园网不可达」「目标不被允许」必须是不同信号，客户端才能给出不同提示。
5. **安全边界可执行**。调用方无法把它变成任意 URL 代理；上游指向真站的重定向必须立刻失败而不是跟过去；网关会话不得外泄给调用方。

### P1：应该做到

6. **校内校外自动判定**。由客户端上报 + 后端配置共同决定，上报过期能自愈，不做周期性探测。
7. **免除重复输入验证码**。在已登录态下可直接换票，把「每次输码」降为「首次输码」。
8. **可审计**。每次经后端的交互都留一条「谁、何时、访问了哪个目标、结果如何」的记录。

### P2：可以后做

9. 免密续期做成可开关的加速路径，且被证伪时零成本回退。
10. 续期周期靠真实成败观测反推，不猜学校的未公开超时。
11. 为后勤、二课等后续业务线预留结构位置。

## 四、范围

**包含**：教务（课表/成绩/考试/通知）经 WebVPN 的访问能力；CAS 换票；票据保管；校内校外判定；审计。

**不包含**：旧 monorepo 的其它业务（鉴权、会话、内容、广场）、埋点服务、Web 管理端、数据与表结构迁移、部署链路切换、iOS 端实现、学校业务线本身（仅预留结构位置）。

## 五、验收标准（从用户视角）

1. 校外学生第一次使用时输入一次验证码即可登录，之后 9~10 天内重复使用不再要求输码。
2. 学生在校内/校外之间切换网络后不需要重新登录，判定在一分钟内自愈。
3. 票据过期时，客户端收到的是「请重新输码」这一明确引导，而不是一条无法理解的错误。
4. 退出登录后，服务端不再保留该用户的任何票据。
5. 后端日志与审计中不出现任何票据值、验证码、或上游响应体原文。
6. 任何调用方都无法让后端请求一个白名单之外的目标；该拒绝发生在任何出站请求之前。

## 六、已知风险与开放项

1. **学校限流维度未知**：「1 分钟内间隔 <15 秒 / 连续 5 次停 1 小时」这条限制按账号还是按 IP 施加，目前无一手证据。若按 IP，把高频只读请求推给客户端也未必降低被拉黑风险。
2. **保活属违约**：不做周期性保活轮询，也不探测学校未公开的空闲超时；只按观测到的真实成败调整周期。
3. **免密换票不跨 appid 外推**：门户 appid 的实测通过不构成教务 appid 的结论，反之亦然。
4. **后端对客户端直连的只读请求既无限流也无审计**——这是被显式接受的代价，不写成「所有请求均已限流」。
5. **单枚长期凭据不足**：实测表明只用单枚 `go-admin-tgt` 无法复现登录态，需要整套会话 cookie；这直接影响「加速路径」何时可开启。
