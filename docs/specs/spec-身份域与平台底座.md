## Problem Statement

上一份 Spec 交付了 `school/` 域与 CAS 换票，但随之落地了一大批它范围之外的代码：身份域（登录/会话/用户画像）、学校认证适配器（ywtb 取数与教务取数）、以及平台底座（Postgres 仓储、Redis 缓存与会话副本、审计、邮件、邮箱验证码）。这批代码**没有规格依据**——`README.md:80` 写的是「业务接口开发前须先补 PRD 与 `docs/specs/` 下的规格，禁止无规格直接写业务代码」，这批代码违反了这条。

它们目前的状态是**「逻辑绿、跑不起来」**：

1. 装配层用的是 `platform.MockHTTPDoer`，且从未调用 `SetResponder`。它的默认行为是返回 200 空响应，**不发任何真实网络请求**。于是所有「后端代请求」的路径（取验证码、换票、取学籍）在生产装配下都是空转。
2. 装配层的 `store` 是 `platform.NewMockStore()`，进程重启后票据、会话、用户数据全部归零。Redis 与 Postgres 实现都写好了，但没接。
3. 认证中间件默认关闭（`AUTH_KEY` 为空时只打一条 WARN），此时所有业务端点无身份校验。
4. `migrations/*.sql` 存在但没有自动执行机制；Elasticsearch 完全未接；没有 metrics/tracing；HTTP 只设了 `ReadHeaderTimeout`。

这里有一个**判定口径问题**必须承认：上一份 Spec 关闭时「检查全绿」指的是 `go test ./...` 全绿，而它验证的是逻辑正确性，不是可运行性。多张实施票的验收判据写的是「端到端可用」，在那个装配状态下并不成立。

## Solution

把这一层收口成一份有据可依、且有**可执行验收判据**的规格。核心是把「绿」的定义从「单测过」改成「真实进程启动、真实出站、真实落库各有一条可复现的检查」。

分四块：

- **身份域**（`internal/identity/`）：四种登录方式、无感注册约束、三档权限、可吊销会话、用户画像。
- **学校认证**（`internal/school/schoolauth/`）：用客户端交来的凭据向 ywtb 与教务取数，产出身份与学籍字段。
- **平台底座**（`internal/platform/`）：Postgres 仓储、Redis 缓存/会话副本/验证码、审计旁路、SMTP 发信、缓存四防护。
- **装配与可运行性**（`internal/app/`、`cmd/server/`）：真实实现注入、迁移执行、超时、配置校验、优雅关停。

## User Stories

**登录与注册**

1. 作为学生，我想用学校账号密码登录（客户端已完成学校登录后交凭据上来），这样第一次用就能进。
2. 作为学生，我想用农屿密码登录，这样之后不必每次都走学校认证。
3. 作为学生，我想用邮箱验证码登录，这样密码忘了也能进。
4. 作为学生，我想用学号 + 身份证后四位 + 姓名首字母登录，这样在没带手机、也不记得密码时仍能进。
5. 作为学生，我只有通过学校认证才能完成注册，这样别人无法拿我的学号注册一个号。
6. 作为学生，我用非学校方式登录而账号尚不存在时，应被明确告知「需要先完成学校认证」，而不是看到一个笼统失败。
7. 作为学生，我想学校账号密码登录成功后，我的农屿密码被镜像成同一个，这样之后用农屿密码也能登。
8. 作为学生，我不想农屿密码被明文保存，这样即使数据库被看到也不泄露我的学校密码。

**会话与权限**

9. 作为学生，我想登录后拿到一个令牌，且令牌本身不含我的密码、身份证等敏感内容。
10. 作为学生，我想退出登录后令牌立即失效，且是在**服务端**失效而不只是客户端删掉，这样别人拿到旧令牌也用不了。
11. 作为学生，我想在一台设备退出时，可以选择只退这一台或退掉全部设备。
12. 作为学生，我的普通会话有效期长（约 30 天），管理端会话短（约 12 小时），这样日常使用不必反复登录，而管理操作风险可控。
13. 作为用户，我想权限分三档（普通 / 管理员 / 超管），且判定以数据库为准，数据库读不到就当作无权限（fail-closed）。
14. 作为管理员，我想管理端登录要求我确实具备管理员权限，否则拒绝，这样不会出现「登录成功但实际无权」的错位状态。

**用户画像**

15. 作为学生，我想看到自己的学号、姓名、学院、专业、班级、年级、手机号，这样资料一目了然。
16. 作为学生，我想专业/班级/年级来自教务而不是我自报，这样这些字段可信。
17. 作为学生，我想可以在画像里补充自己的扩展字段（昵称、简介等），这些不会被学校数据覆盖。**前提是画像已建立**（走过一次学校认证）；否则应被明确拒绝，而不是造出一条学校字段全空的画像。
18. 作为学生，我想学校数据同步时**保留**我填的扩展字段，而不是整条覆盖。
19. 作为管理员，我想按学号查某个学生的公开画像，但不能看到身份证与家庭住址。

**学校认证取数**

20. 作为接入方，我想用客户端的 Bearer 令牌 + 会话 cookie 向 ywtb 取身份（学号、姓名、学院、手机号、身份证），这样不必让用户重输密码。
21. 作为接入方，我想 ywtb 返回的数据能被正确解密，这样我不用自己实现那套算法。
22. 作为接入方，我想在拿到统一认证的长期凭据后，能换到教务的票并抓取学籍，这样专业/班级/年级能自动补齐。
23. 作为接入方，我想服务端把长期凭据加密保管并按期续期，这样客户端不必每次重交凭据。
24. 作为接入方，我想在教务取数失败时**不阻断登录**，只把画像标记为不完整，这样用户仍能进系统。
25. 作为接入方，我想换票与建会话时只跟随白名单内的跳转，跳出白名单立即拒绝，这样不会退化成任意 URL 代理。
26. 作为安全审阅者，我想身份证号加密存储、且只在必要时返回，这样数据边界是可核的。
27. 作为安全审阅者，我想学校密码、身份证、长期凭据各用**独立的加密密钥**，这样一把钥匙泄露不会全崩。

**平台底座**

28. 作为运维，我想身份数据落在 Postgres，进程重启不丢，这样不必靠内存凑合。
29. 作为运维，我想票据与缓存落在 Redis，多副本不需要粘性会话。
30. 作为运维，我想数据库迁移能被执行且可重复执行（幂等），这样部署不必手工敲 SQL。
31. 作为运维，我想 Redis 故障时缓存快速失败并**降级到直查数据库**，而不是把请求全挂掉。
32. 作为运维，我想缓存有防穿透（空值缓存）、防雪崩（TTL 抖动）、防击穿（singleflight）三道防护。
33. 作为运维，我想审计日志异步落库，且**批量写入不丢记录**。
34. 作为运维，我想审计里出现的是「谁、何时、做了什么、结果」，绝不含密码、票据、身份证原文。
35. 作为运维，我想邮箱验证码存在 Redis、只存哈希、一次性、有冷却与连错上限，这样不会被刷。
36. 作为运维，我想 SMTP 可配可不配：配了发真信，没配只打日志，这样本地开发不需要邮箱。

**可运行性与诚实性**

37. 作为运维，我想服务能在配置齐全时**真的启动**并响应 `/healthz`，且启动日志说清哪些能力是真实的、哪些没启用。
38. 作为运维，我想配置缺失或危险配置（如生产环境 `AUTH_KEY` 为空）时**启动失败**而不是带病运行。
39. 作为运维，我想 HTTP 服务器有读、写、空闲超时，慢连接不会堆积。
40. 作为运维，我想有进程存活与关键依赖状态的观测出口。
41. 作为后续接手的开发者，我想「绿」的定义包含真实出站与真实落库的检查，这样不会再有「测试全绿但跑不起来」。
42. 作为后续接手的开发者，我想 mock 实现与真实实现**命名可区分**，这样看装配代码就知道当前用的是哪个。
43. 作为后续接手的开发者，我想新增一个平台能力只需在 `platform` 加接口 + 在装配层注入，业务域不用改。

## Implementation Decisions

**范围与追认**

- 本 Spec **追认**已经落地的代码为既成事实（含未先立规格的部分），以之为起点而非推倒重写。
- 对与「能跑」要求冲突的现状，逐条标为**待修正项**（见下），不在 Spec 里假装已完成。

**身份域**

- 子域划分：`login/`（四种登录方式）、`session/`（签发/校验/吊销）、`user/`（建号/画像/同步）、`flow/`（登录编排与 HTTP）。
- 四种登录方式共用一套 `Result`；`LoginBySchool` 是**唯一**能建号的路径，其余三种在用户不存在时返回 `CodeNeedSchoolAuth`。
- 密码镜像：学校账密登录成功后，把学校密码加密写入农屿空密码字段；已走过则不再覆盖。
- 权限三档 `RoleUser=0 / RoleAdmin=1 / RoleSuperUser=2`，判定以数据库为准，读不到即拒绝。
- 会话可吊销：令牌只带 `session_id`，验签后查会话；Postgres 为权威、Redis 为副本；吊销写标记而非删 key，避免穿透。

**学校认证**

- 接口形状按真实协议定：`AuthSource.FetchIdentity(ctx, Credential)` 接收完整凭据（Bearer + cookie），**不是**只接一个 cookie 字符串——实测只带 cookie 会 401。
- 换票必须透传**整套**同域 cookie：实测单枚 `go-admin-tgt` 换票返回 `code=500 未登录`。
- 换票响应里直接带回新的长期凭据（`tgt` 字段），因此服务端可保管并滚动续期；但续期同样需要配套 cookie，**只存 tgt 不足以续期**（见待修正项）。
- 教务建立会话是**三跳**重定向（`caslogin.asp → check_cas.asp → note.asp → index1.asp`），会话 cookie 在**中间跳**下发。因此 `HTTPDoer` 的实现**必须不自动跟随重定向**，否则中间跳的 `Set-Cookie` 会被丢弃，表现为「未下发会话 cookie」。
- 学籍页是 GBK 编码；编码判定用 `utf8.Valid` 先行，不能用「解码结果像不像 HTML」来判断。
- 教务取数失败标记 `ProfileIncomplete`，不阻断登录。
- 身份证：加密存完整号，接口按需返回；学校密码、身份证、长期凭据各用独立密钥。

**平台底座**

- `platform` 只定义接口，业务域拿不到实现类型；装配层是唯一注入点。
- 票据与缓存落 Redis；身份与审计落 Postgres；审计走异步批写，取与写必须在同一临界区内完成，否则并发下会丢记录。
- Redis 不可用时缓存层降级为直查，并有限速回灌；熔断器三态。
- 邮箱验证码存 HMAC 哈希，TTL 兼作冷却锁，一次性，连错 5 次作废。
- 测试隔离：每个包用自己的 Postgres schema，`TestMain` 改写 `DATABASE_URL`；跨包并行会互相删数据。

**可运行性**

- 装配层从配置决定用真实实现还是 mock，并在启动日志里**明说**当前用了哪个（`store`、`outboundEnforce`、`authEnabled`、`cacheEnabled`、`accelEnabled`）。
- 生产环境关键配置缺失时启动失败；开发环境可降级但要打 WARN。
- 迁移以幂等方式执行，可在启动时跑，也可单独跑。

## Further Notes

**开放项（未验证，不写进设计前提）**

1. 学校侧限制按账号还是按 IP —— 未知，按「可能按账号」保守设计，不做高频重试。
2. 教务页面表头是否会变 —— 未知，用关键字包含匹配而非列索引，能扛增列/改序。
3. ywtb 的 Bearer 令牌有效期与续期方式 —— 未知，只在登录当下使用，不持久化。
4. Elasticsearch 是否真的需要 —— 待定；当前审计落 Postgres，若日志量不大可以不接。

**口径说明**

- 本 Spec 的验收标准以「可复现的运行结果」为准，不以单测通过为准。凡涉及出站与持久化的用户故事，其验收必须包含真实实现。
- 已实测确认的协议细节（ywtb 取数、解密算法、换票、三跳建会话、GBK 解析）写在 `docs/tech/` 与本 Spec 的 Implementation Decisions 中，测试断言以实测样本为准。

## 验收

每条用户故事至少有一条可执行的检查；下面五条是**本 Spec 特有的门槛**，缺任一条即视为未完成：

1. **真实出站**：配置真实 `HTTPDoer` 后，能对一个可控目标发出真实请求并得到真实响应（不是 mock 的 200 空响应）。
2. **真实落库**：重启进程后，登录产生的用户、会话、票据仍然存在。
3. **迁移可执行**：在空库上执行迁移后建表成功，重复执行不报错。
4. **真实登录**：用真实凭据走完一次「取验证码 → 提交 → 拿到令牌 → 用令牌访问受保护端点」。
5. **降级可用**：Redis 不可用时，缓存相关端点降级到直查数据库仍能返回正确结果。

## Out of scope

- 旧 Node/旧 RN 客户端的迁移与改造（见 ADR-0001）。
- 前端/移动端实现。
- 课表、成绩、考试、通知等教务业务数据的解析与接口（本 Spec 只覆盖「拿到学籍」这一步）。
- 支付、后勤、二课等新业务线。
- ES 的日志写入与检索实现（当前审计落 Postgres；若后续接入，另立规格）。
