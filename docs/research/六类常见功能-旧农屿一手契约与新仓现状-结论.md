## 一、B 端管理

- 旧仓：管理端是独立应用 `nongyu-web-admin`，用「教务网学号 + 农屿管理员密码」登录（与教务网密码不同套）；接口 `POST /api/admin/auth/login`、`GET /me`、`POST /logout`，统一包 `{ code, message, data }`（`code===0` 成功）。[来源: ../../docs/nongyu-web-admin/specs/登录与管理端壳.md:16,25,71,78,190-199]
- 旧仓权限：`role` 三档 `0/1/2`（普通/管理员/超管），管理员与学生**同表** `users`（列 `admin_password_hash`）；会话存 `localStorage` 的 `nongyu-admin:v1:session`，`role===1` 才有效，任一 `/api/admin/*` 返回 401 即清会话。[来源: ../../docs/nongyu-node-server/数据库设计文档.md:109-110,134；../../docs/nongyu-web-admin/specs/登录与管理端壳.md:112-119,130-132]
- **旧仓关键坑**：bootstrap 超管（学号 `202308596`）不反填 `users`；**Admin JWT 不设 `exp`（永不过期）**。[来源: ../../docs/nongyu-node-server/specs/App与Admin鉴权会话策略.md:24-26]
- 新仓现状：无管理端业务域（只有 `identity/`、`school/` 两业务域），但身份域已把 `scope=admin` 会话与 `role 0/1/2` 三档落地（注释「沿用旧农屿语义」）。[来源: internal/platform/store.go:610-617,723-729；docs/adr/0002-身份仓数据边界.md:67-71]
- **方向与旧仓相反**：新仓要求管理台会话「独立、可吊销、有明确过期」且判定 **fail-closed**（role 以 DB 为准，令牌只作提示；「查不到按无权」与「基础设施故障抛错」要区分），点名「旧系统管理票永不过期是要修掉的洞」；外加旧仓没有的 **NY1 请求签名**（证明请求来自持当前密钥的客户端，明确**不加 JWT**）。[来源: docs/tech/领域模型-用户与登录-消息.md:140-150,162；GLOSSARY.md:70；docs/adr/0003-安卓请求签名.md:14-16]
- effort 边界：现行 PRD 明文把「Web 管理端」列为**不包含**。[来源: docs/specs/prd-学生校外访问学校服务.md:49-51]

## 二、日志埋点

- 旧仓：埋点**不在业务 MySQL 建模**，由独立服务 `nongyu-go-track-server`（Go + SQLite）承担；「App 直连上报、管理端经 Node BFF 携内部 Token 查询」；接口文档自称「本文为 Track HTTP 契约真相；实现须 100% 对齐」。[来源: ../../docs/nongyu-node-server/数据库设计文档.md:22,38,55,482；../../docs/nongyu-go-track-server/接口文档.md:7,15]
- 旧仓契约刻意与业务 API **不同包**：Track 用 `{ ok, data }`/`{ ok:false, error }` + snake_case；Node 业务 API 用 `{ code, message, data }` + camelCase；BFF 应自行映射，**禁止**要求 Track 改成 Node 格式。[来源: ../../docs/nongyu-go-track-server/接口文档.md:30,41,44-64]
- 旧仓鉴权/端点：API 前缀 `/v1`、`GET /health` 无鉴权；App 用 `Authorization: Bearer <App JWT>`（与 Node 同一 `JWT_SECRET`，`user_id` 一律取 JWT `uid`、忽略伪造）；Admin 用 `X-Internal-Token`（常量时间比较）；Body ≤1MB、约 120 req/min；核心端点 `POST /v1/track/events`（批量 1~100、`event_id` 幂等、部分成功）、`/v1/track/presence/offline`（**必须**回写 Node 在线态）、`/v1/internal/events`（不更新 presence）。[来源: ../../docs/nongyu-go-track-server/接口文档.md:38-42,96-130,189,219-241,272-329]
- **脱敏**：埋点 `props` 序列化后硬上限 4KB、超长截断，`props` 禁止明文密码。[来源: ../../docs/nongyu-go-track-server/接口文档.md:230,479,616]
- 新仓现状：现行 PRD「**不包含**……埋点服务」；`README.md:84` 明确旧 Go 埋点服务「仅作历史对照，不是现行源码或依赖来源」；`internal/platform` 14 个接口**无任何埋点/事件上报接缝**。新仓现行「可观测性」只有**日志（stdout/slog）+ 审计（PG `audit_log`）**两条，不是埋点。[来源: docs/specs/prd-学生校外访问学校服务.md:49-51；README.md:84；docs/tech/持久层结构.md:13-18,109]

## 三、文件存储（MinIO）

- 决议原文在 PRD：图片存储「走**自建 MinIO（S3 兼容）**，Node 通过 S3 SDK 读写；对象 key 形如 `posts/{yyyy}/{MM}/{uuid}.{ext}`」；grill 结论「不引入阿里云 OSS、不做本地磁盘方案」。[来源: ../../docs/forhuman/rawprds/nongyu-rn-app/Center/广场发帖增强PRD.md:47,81,99]
- 契约细节：反馈墙与大院帖都可带图**最多 9 张**、单张硬限 **5MB**、前端压缩（2560px/q0.8）、格式 `jpg/png/webp/gif`；发布只提交**已上传成功的对象 key**，`images` 须是「本桶前缀下的合法 key（防外部 URL 注入）」。[来源: ../../docs/forhuman/rawprds/nongyu-rn-app/Center/广场发帖增强PRD.md:40,43-49,63]
- **证据等级须降级**：这是 **PRD 提案**，不是已落地契约——全仓 grep 无下游 Spec/实现，旧 `nongyu-node-server` 源码 `images|MinIO|S3|multer|presign` **0 命中**，PRD 自己把「映射方式/草稿存储/大图预览」列为「待定案（交由 Spec 收敛）」。[来源: 底稿:196-199；../../docs/forhuman/rawprds/nongyu-rn-app/Center/广场发帖增强PRD.md:108-114]
- 新仓现状：`internal/platform` **无对象存储接缝**（无 `ObjectStore`/`BlobStore`/`S3` 抽象）；`internal/` grep `MinIO|minio|S3|对象存储` 无命中。架构上对象存储是**被允许的外置位置**（README 第 3 条「进程无状态，状态外置 DB/缓存/对象存储」），但接缝须先在 `platform` 定义（第 2 条禁止业务域直接 import S3 SDK 等实现）。[来源: README.md:45-46；底稿:70-71]
- effort 边界：现行 PRD「不包含……内容、广场」，未列文件存储。[来源: docs/specs/prd-学生校外访问学校服务.md:49-51]

## 四、帖子

- 旧仓：统一 `posts` 表 + `post_type` 三值 `announcement`（公告，管理员只读）/`feedback`（反馈墙，App 匿名）/`courtyard`（大院，App 匿名）；软删 `deleted_at`、`published_at` 默认倒序、阅读量 `view_count`/`unique_reader_count` 由独立 `post_reads` 表（唯一约束 `(post_id,user_id)`）统计。[来源: ../../docs/forhuman/rawprds/nongyu-rn-app/Center/广场发帖增强PRD.md:15；../../docs/nongyu-node-server/数据库设计文档.md:161-187,228-238]
- 旧仓 HTTP：`POST /api/app/posts`（`feedback|courtyard`）、`GET /api/app/posts/:id`（打开即计阅读、不返回阅读量）、`DELETE /api/app/posts/:id`（作者软删、公告不可删）、`GET /api/app/users/me/posts`（不含公告）；`feedback` 帖在配 `GITHUB_TOKEN`+`GITHUB_REPO` 时**异步**建 GitHub Issue（best-effort，失败只记日志不回滚）。[来源: ../../docs/nongyu-node-server/接口文档概览.md:432-440,460-486]
- 旧仓边界：一期「**不做评论、点赞、图片/音频、富文本**」「**不支持编辑已发布帖**」「App 永不展示 viewCount/uniqueReaderCount」；后续增强 PRD 才补「发布后 **24h 内**本人可编辑（服务端 `canEdit`）、`editedAt` 标记、`content` ≤5000、按用户限频」，并明确「**不回退匿名性**」「**不做 push 通知**（沿用前台轮询）」。[来源: ../../docs/nongyu-rn-app/specs/广场功能.md:29-45；../../docs/forhuman/rawprds/nongyu-rn-app/Center/广场发帖增强PRD.md:51-65,102-104]

- effort 边界：现行 PRD「不包含……内容、广场」。[来源: docs/specs/prd-学生校外访问学校服务.md:49-51]

## 五、公告

- 旧仓：公告**不是独立表/模块**，是 `posts.post_type='announcement'` 的取值，作者管理员、客户端只读。[来源: ../../docs/nongyu-node-server/数据库设计文档.md:163-169；../../docs/nongyu-rn-app/specs/广场功能.md:31]
- 旧仓 HTTP：`GET /api/app/posts/announcements/latest` 返回 `{ id,title,subtype,publishedAt }|null` 供 App **首页通知栏**；Admin `POST /api/admin/posts` 发公告（服务端固定 `postType`）、`PATCH /api/admin/posts/:id` **仅允许编辑未软删公告**（其它类型报 `40001`）、`DELETE` 软删；公告墙**不参与** 30s 轮询。[来源: ../../docs/nongyu-node-server/接口文档概览.md:427-430,800-822；../../docs/forhuman/rawprds/nongyu-rn-app/Center/广场回复与留言PRD.md:49-51]

## 六、通知（或内部信）

- 旧仓：**没有独立消息中心/内部信/通知中心模块或表**，只有「帖子派生通知」；新仓领域模型一手对照行「消息中心｜不存在（帖子派生通知）」「旧农屿里也没有独立消息域」。[来源: docs/tech/领域模型-用户与登录-消息.md:8,163]
- 旧仓通知形态是**前台轮询 + toast**，不是推送：用户前台以 **30s** 轮询「自己的帖子是否被回复」，有新回复 toast；列表轮询仅在广场 Tab 前台；**不做 push、不做后台轮询**；「是否已通知」由**服务端**维护标记（通知后置位，避免重复 toast）。[来源: ../../docs/forhuman/rawprds/nongyu-rn-app/Center/广场回复与留言PRD.md:46-52,64,74-75]
- **`notified_author` 语义（重点）**：字段是 `post_replies` 行上的 `TINYINT(1) DEFAULT 0`「是否已通知**帖主**」；轮询 SQL `WHERE p.author_user_id = ? AND r.notified_author = 0 ... LIMIT 50 FOR UPDATE`，返回后**同事务** `UPDATE ... SET notified_author = 1`。**结论：不是 per-user 已读**，是「该回复是否已给帖主推过一次 toast」的行级布尔位；一个帖只有一个作者，无多收件人、无「每用户一行已读」表。[来源: ../../docs/nongyu-node-server/数据库设计文档.md:193-224；../../docs/nongyu-node-server/specs/广场回复与留言.md:77-82,143-149；../../apps/nongyu-node-server/src/modules/posts/postReplies.repo.ts:325-353]
- 两个不同端点：`GET /api/app/users/me/post-replies/new`（**轮询用，有副作用**：返回项置位、后续不再返回、单次≤50）；`GET /api/app/users/me/post-replies/received`（**收到的回复 inbox**，帖主视角、分页、不改通知位）。[来源: ../../docs/nongyu-node-server/接口文档概览.md:488-503]
- 新仓现状：**术语陷阱**——GLOSSARY「用户画像」才是维护者口中的「用户消息」，`_Avoid_` 点名「消息（在本项目指画像，不是通知/私信）」；领域模型是「讨论稿、尚未落代码」，`internal/` 无通知/消息业务域；平台层只有可复用的**邮件投递接缝 `Mailer`（SendMailCode）**，不是通知中心。[来源: GLOSSARY.md:54-55；docs/tech/领域模型-用户与登录-消息.md:3-4,6-8；internal/platform/mail.go:35-38]
- effort 边界：现行 PRD「不包含……内容、广场」；map #43 的 Q5 已把「通知+内部信」锁为**统一 per-user 消息域（含已读）**，这是**本 effort 新语义**，不能从旧契约推导。[来源: docs/specs/prd-学生校外访问学校服务.md:49-51；底稿:200-203]

## 新仓硬约束清单（跨六功能，长期不可破）

1. **README 五条架构约束**（`:42-48`）：①业务域之间不互相 import、协作走 `internal/app` 装配层；②业务域**只依赖 `internal/platform` 接口**，不直接 import 数据库驱动/S3 SDK 等实现；③**进程无状态**，状态外置 DB/缓存/对象存储；④域内自带 handler/service/repo 接口、存储实现放 platform；⑤不提前建 `pkg/utils`、`common` 垃圾场包。[来源: README.md:42-48]
2. **SDD 流程**（`:77-80`）：PRD → Spec → 技术方案（按需）→ 实施计划 → 编码 → 人工 Review；「业务接口开发前须先补 PRD 与 `docs/specs/` 规格，**禁止无规格直接写业务代码**」。六类功能目前**都没有**新仓 PRD/Spec。[来源: README.md:77-80]
3. **ADR-0001/0002 脱敏铁律**：票据、密码（含学校密码镜像）、身份证号、验证码、上游响应体**一律不得进日志／审计／埋点／错误信息／接口响应**；ADR-0001 第 3 条「票据不落日志、不写 MMKV/埋点、退出登录即清除」、ADR-0002 第 22/45 行「密码、身份证号绝不/永不出现」；审计表「只有标识性字段，绝不写票据、密文、验证码、上游响应体」。[来源: docs/adr/0001-服务端代请求边界由新后端重写.md:27；docs/adr/0002-身份仓数据边界.md:21-23,28-45；docs/tech/持久层结构.md:62]
4. **#24 应用不直连 ES**：运行日志只写 stdout/slog，由外部采集器（Filebeat/Vector/Fluent Bit，**尚未部署**）送 ES；「代码里没有任何 ES 依赖是符合本设计的，不是遗漏」；审计走 `PGAuditStore` → Postgres `audit_log`（旁路、满缓冲丢弃并计数）。日志/审计/埋点是三条不同边界，勿混。[来源: docs/tech/持久层结构.md:13-18,36-43,109]
5. **`platform` 现有 14 接口无对象存储／埋点接缝**：清单见底稿「新仓约束清单 B」表（`Store`、`UserRepo`/`ProfileRepo`/`LoginMethodRepo`/`SessionStore`/`StudentBriefReader`、`TicketStore`/`Cipher`/`HTTPDoer`/`Clock`、`Mailer`/`AuditStore`、`LockBackend`/`CacheTx`）；`HTTPDoer` 是「后端有没有权发外部请求的唯一闸口」，强制白名单校验、超时、不跟随真站 302，业务域不得绕过用 `http.DefaultClient`。六类功能一个业务域都没有。[来源: 底稿:150-163；internal/platform/outbound.go:120-150,279-290]
6. **依赖「停用即删」双确认**（根 `AGENTS.md:19-22`）：删功能/换实现/依赖已无代码路径使用时，同一次变更即删；判据缺一不可——① `go mod tidy` 后 `go.mod` 不再出现该 `require`；② `go list -deps ./...` 输出不再含该包路径；不以 `// indirect` 为判据，不手改 `go.sum`。[来源: AGENTS.md:19-28]
7. **不复用旧后端代码/表结构/部署链路**；旧 `nongyu-go-track-server`（Go 已 DEPRECATED、现行 Node Track）与 `nongyu-node-server` 都**不是本仓现行源码或依赖来源**。[来源: README.md:3,84；../../apps/nongyu-go-track-server/DEPRECATED.md:1-7]

3. **旧农屿没有独立「内部信／站内信／通知中心」模块或表**：全仓 `docs/` grep 无独立模块文件，只有「广场回复与留言」里的**轮询通知**。→ 维护者说的「通知（或内部信）」到底指「帖子派生通知（轮询 toast）」还是「新的独立站内信/多收件人通知中心」，二者数据模型完全不同。[底稿:200-201] **对应子票：#55（消息域模型 per-user 已读）** 与 **#48（触发源与派生关系）**；Q5 已锁 per-user 消息域（新语义）。
4. **`notified_author` 不是 per-user 已读**：仓内**未找到**任何「每用户已读/多收件人/未读数」的表、接口或字段；`post_replies` 只有一个行级置位，收件人恒为帖主。→ 若新仓要求 per-user 已读，这是**新语义**，不能从旧仓契约推导。[底稿:202-203] **对应子票：#55**。
5. **六类功能在新仓均无 PRD / Spec / 业务域 / 表 / 代码**：`docs/specs/` 现有规格只覆盖 WebVPN、身份域与平台底座、教务查询与缓存；现行 PRD 把「鉴权、会话、内容、广场、埋点服务、Web 管理端」列为**不包含**；GLOSSARY 与领域模型把范围限定在「WebVPN 能力重写」这一 effort。→ **（最关键）** 这六类功能是「另开 effort / 另立 PRD」还是并入现有 WebVPN effort，须拍板。[底稿:204-205] **对应子票：#47（范围切分与 Out of scope）**，收口方式归 **#51（Spec 章节结构与验收边界）**。
6. **B 端管理「管理票永不过期」是旧仓口径，新仓未继承**：旧仓 Admin JWT 不设 `exp`；新仓要求「独立、可吊销、有明确过期、fail-closed」。→ 若做 B 端按新仓口径设计，**不要照抄**旧仓 Admin JWT。[底稿:206-207] **对应子票：#46（六功能共用横切鉴权口径）**。
7. **日志采集器与 ES 接入都未部署/未接**：「应用只写 stdout，采集器尚未部署，ES 目前没接收本项目日志」；`metrics/tracing` 也没有。→ 「日志埋点」若要落地，需先明确它属于「运行日志→采集器→ES」这条，还是另起埋点服务（现行 PRD 明确不含埋点服务）。[底稿:208-209] **对应：Q4 已锁不重开**（沿用 #24 决议，运行日志/审计不在本图重定；新增只限「用户行为埋点」一层，归 **#45**）。
8. **埋点服务现状的「最终态」仓内有冲突表述**：`DEPRECATED.md` 自称 Go 已下线、现行 Node Track；但同仓迁移 Spec/计划/部署文档分别写「实施中」「代码与 CD 已完成，待 Phase F 机上切换」且验收未勾选；底稿不判定哪份最新。→ 引用旧埋点契约时须知这是「契约真相」文档，不是「现行运行状态」结论。[底稿:210-211] **对应：Out of scope**（与六功能地图无直接关系，不作为本图决策输入）。
