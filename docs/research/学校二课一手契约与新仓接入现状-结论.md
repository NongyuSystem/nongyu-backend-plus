## 一、二课目标、凭据与 ADR-0001 冲突（最关键结论）

- 样本是 **PU / 口袋校园二课平台（川农定制 i川农）**，包名 `tiangong.com.pu`，**不是川农教务客户端**；业务逻辑集中在 `tiangong.com.pu.module.secondclass`（45 类）。BaseURL **`https://jk.sicau.edu.cn:443/`**，H5 **`https://h5.sicau.edu.cn`**（走 query token）。【DEX 静态】[来源: work/iciannong-apk/REPORT.md:14,20,29,55; 底稿:§一.1]
- 鉴权是 **header `x-access-token` = PU 平台 token**（`Session.getLoginInfo(mContext) → LoginInfoVO.getToken()`），**不是 CAS / WebVPN 票据**；全 172 接口统一 `@Header("x-access-token")`，`Api$1` 的 7 个设备头只挂 `getGsonApi`、Rx 侧二课接口不带。`code=0` 成功、`code=5`→`TokenException` 跳登录，但**未在真实响应验证**。【DEX 静态 / 待 HITL】[来源: work/iciannong-apk/REPORT.md:43-53,62,233; 底稿:§一.1]
- **三个冲突维度，均须拍板（扩展 ADR-0001 目标集合，或新增一类非 WebVPN 出站目标 + 新托管 PU 凭据边界）**：
  1. **host 冲突**：`jk.sicau.edu.cn` / `h5.sicau.edu.cn` **都不在** ADR-0001 第 1 条固定白名单（`jiaowu/auth/webvpn`），也不在代码内建 `targetHosts`（3 项）与 `outboundAllowlist`（4 项，含后来补的 `xsgz`）。【仓内一手】[来源: docs/adr/0001-服务端代请求边界由新后端重写.md:25; internal/school/targets.go:29-36; internal/app/app.go:888-896; 底稿:§一.2]
  2. **凭据冲突**：ADR-0001 第 3 条管的是 `wengine_vpn_ticket*`（可下发本人客户端直连、不落日志），**不覆盖** PU `x-access-token`；须新托管一类 PU 凭据（获取/加密外置/续期/失效/脱敏/退出清除），脱敏同样受 ADR-0001 第 3 条、ADR-0002 与 `AuditEntry` 铁律约束。【仓内一手】[来源: docs/adr/0001-服务端代请求边界由新后端重写.md:27-28,40-45; internal/platform/mail.go:398-399; 底稿:§一.2、约束4]
  3. **结构冲突**：ADR 第 1 条「调用方只传逻辑目标名、永不传完整 URL」；二课 `@POST` 注解值**本身就是绝对路径常量**（如 `/act/credit/v1.0.0/getApplyCredit`），从 host 根解析——两套目标表达方式不同。【DEX 静态 + 仓内一手】[来源: work/iciannong-apk/REPORT.md:37; docs/adr/0001-服务端代请求边界由新后端重写.md:25]

## 仓内未找到／待 HITL（照底稿 §六 收成要点）

3. **token 精确字段 / 生命周期 / 是否可复用学校 SSO**：登录响应 `LoginRespVO`/`LoginInfoVO` 字段清单产物里未见；`sid` 是否打通川农 SSO、能否用 CAS 票换 `x-access-token`——**仓内未找到／APK 产物里未见**。→ 真账号/真网络 HITL，不得推测。[底稿:§六.3]
