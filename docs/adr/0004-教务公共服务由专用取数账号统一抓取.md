# ADR-0004 教务公共服务由专用取数账号统一抓取

- 状态：已接受（2026-11-18）
- 相关：ADR-0001（服务端代请求边界）、`docs/specs/spec-教务查询与缓存.md`

## 背景

教务缓存早期对所有 `dataType` 一视同仁：每个请求学生用自己的
`go-admin-tgt` + `wengine_vpn_ticket` 取数，缓存键一律
`<prefix>cache:<userID>:<dataType>`。

但通知、竞赛、教师/教室查询等页面是**全站共有、不需登录、不随学生变化**的。
让每个学生各取一份既浪费凭据与出站，又带来一个隐蔽问题：实测访问教务首页
（`/web/web/web/index.asp`）会重置 WebVPN 网关侧「已登录教务」状态，导致该学生
随后取课表 302。为兜这个顺序坑，曾一度把 CAS 预热加到「每次 cache_miss」，代价是
每次未命中多 3~4 次出站。

## 决策

**按数据是否随学生变化，把 dataType 分成公共与私有两类，走两套凭据、两套缓存键。**

| | 公共 | 私有 |
| --- | --- | --- |
| 凭据 | 管理员维护的「取数账号池」 | 学生自己的 tgt + 网关票 |
| 缓存键 | `<prefix>cache:public:<dataType>`（全局一份） | `<prefix>cache:<userID>:<dataType>` |
| 失效 | 仅管理员（管理端接口） | 学生本人（60 秒节流） |

取数账号**只有两套凭据**（整套 auth 域 cookie + webvpn 票），不对应任何 app 用户、
没有学号/角色/业务数据，存数据库表 `jiaowu_fetch_accounts`（密文列）。

### 具体约束

1. **绝不回退**：池不可用/换票失败时，公共类回专用错误码，绝不用学生自己的
   凭据顶上——那会让公共数据按人分叉，也违背本决策。
2. **凭据不落地**：库里只存 AES-GCM 密文；管理端所有响应不回显明文；明文只在
   新增/更新请求体出现一次；日志/审计不记凭据。
3. **权限**：取数账号 CRUD 与公共缓存失效挂在 `adminGroup`（ScopeAdmin + RoleAdmin），
   普通 app 会话够不着。
4. **续期分工**：tgt 复用 `TGTManager` 的滚动续期思路（存 `TGTBundle` JSON 密文）；
   webvpn 票会话级、无 Max-Age，由管理员手动更新。
5. **预热回退**：公共页分流后，学生侧链路只剩需登录页，它们之间互不重置，
   因此「每次 cache_miss 预热 CAS」回退为交票时一次，`cache_miss` 保持零出站。

## 理由

- 公共数据本就该只有一份，按用户缓存是概念错误。
- 把会重置会话的公开页挪出学生链路，顺序坑从根上消失，不再需要每次出站兜底。
- 取数账号与真实用户解耦，避免用某个真实学生的 ID 当公共缓存键（串数据风险）。
- 凭据集中管理、加密落库、仅管理员可维护，符合 ADR-0001 第 3 条凭据最小化原则。

## 后果

- 新增迁移 `0008`、PG/内存两套仓储、管理端 6 个端点、`IsPublicDataType` 分类表。
- 分类表是**硬约束**：误把随学生变化的类型判为公共会串数据，故有单测锁死 8 公共 / 7 私有。
- 部署需管理员先通过管理端配置至少一个取数账号，否则公共类全部回
  `fetch_account_unavailable`（明确报错，不静默降级）。
- 公共缓存长期命中（管理员才能删失效），实际回源频率很低，池出站代价可控。

## 被取代的旧决策

以下均为本决策落地前的中间方案，不再适用：

- 「客户端什么都没有、全在后端取」（私有类仍是客户端拿地址+cookies 直连）
- 「`cookies` 恒空 + `session=client_side` + `webvpn.status` 状态字段」
- 「每次 cache_miss 都重新预热 CAS 三跳」
