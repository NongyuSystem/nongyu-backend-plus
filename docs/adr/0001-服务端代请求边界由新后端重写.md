# 服务端代请求边界由新后端重写

旧 RN 客户端规格 `docs/nongyu-rn-app/specs/WebVPN传输适配.md:20` 写的是「不做服务端代请求，不把 WebVPN 编成任意 URL 代理」，那条边界是**旧 App 的规格**。本仓 `README.md:3` 声明自己是独立于旧 monorepo 的全新仓库、不复用旧后端代码与部署链路，旧 spec 对新 Go 后端因此不具约束力。故本仓不沿用「有条件放宽」的说法，改为**为全新后端重写这条边界**：允许后端在明确的目标集合与约束条件下代请求，同时把「开放成任意 URL 代理」继续排除在外。拍板于 [放宽边界与 ADR：Q4「有条件放宽」的具体条件是什么](https://github.com/NongyuSystem/nongyu-backend-plus/issues/4)（Q1=a）。

## Status

accepted

## Considered Options

- **沿用「有条件放宽」**（map 初版口径）：把旧 spec 当成仍生效的规则，再列例外。否决理由：旧 spec 的标题与适用范围都是旧 RN 客户端（[WebVPN传输适配.md](<D:/IT/program/web-program/nongyu-system/docs/nongyu-rn-app/specs/WebVPN传输适配.md>) 第 1-5 行），而本仓明说不复用旧实现；给一个不适用于本仓的规则列例外，会让后来读代码的人以为存在一个正在生效的禁令。
- **整体废弃、不做替代**：既然旧 spec 不适用，就干脆不写边界。否决理由：`WebVPN探索.md:329` 记录的 SSRF 原理（持已认证网关会话即等价于访问任意校内 host）是**技术事实**而非旧仓规则，废弃文档不等于消除该风险。
- **为新后端重写边界（采纳）**：承认旧 spec 只管旧客户端，本仓重新规定允许的目标集合与硬约束。

## Consequences

- map 的 Q4 口径由「有条件放宽」改为「为新后端重写边界」；旧 spec 仅作历史对照引用。
- **本次重写只改文档规则，不改硬事实**：SSRF 原理、学校 ToS/风控、票据与网关会话的技术行为、真账号未验收项，全部继续生效，并作为具体条件的判据（[Go后端承载WebVPN的硬约束.md](<docs/tech/Go后端承载WebVPN的硬约束.md>)）。
- [GLOSSARY.md](<GLOSSARY.md>) 的「服务端代请求」词条随之确认：它是中性事实（后端代替客户端发起请求），不再与被废弃的禁令绑定。

## 重写后的边界

第二轮（2026-11-07）定下五条，构成本仓对服务端代请求的全部约束：

1. **目标集合固定白名单**：仅 `jiaowu.sicau.edu.cn` / `auth.sicau.edu.cn` / `webvpn.sicau.edu.cn`。调用方**永不传入 host 或完整 URL**，只传逻辑目标名（如 `jiaowu`），由后端映射为具体 URL。这是排除 SSRF 的结构性做法：调用方无法决定目标，就不存在「任意 URL 代理」这一形态。
2. **仅内网/可信网络，且每请求归属已认证用户**：代请求必须携带既有用户体系的身份，归属到具体学生。依据 ToS「账号仅限本人」—— 无身份归属时该条在架构上不成立，审计也无法追溯。
3. **票据可下发到客户端，但只在必要时、且不落日志**（2026-11-07 修订，原「票据不出后端」作废）：`wengine_vpn_ticket*` 可由后端下发给**已认证的本人**，用于客户端直连学校；后端自身持有时按用户键控加密外置到 Store（密钥走环境变量）。日志与埋点对票据字段一律脱敏。**不下发给第三方、不写入 MMKV/埋点、退出登录即清除。** 具体 Store 形态与加密算法留给「进程无状态 vs 票据外置」后续票。
4. **限流与审计按其可见范围分段落地**（2026-11-07 修订，原「所有代请求都经后端限流」在新流量形态下不成立）：凡经后端的交互（换票、票据续期/失效判定、代请求）**必须**记审计（谁、何时、目标逻辑名、结果码）并按**用户分级**限流，本期只实现默认 1 级；**客户端直连学校的只读请求不经后端，后端无法限流也无法审计**——这部分改由客户端侧节流（同一用户只读请求串行化 + 最小间隔）承担，且必须在后续 Spec 中明确写出「后端观测不到」。依据学校 `1 分钟内间隔 <15s` 基础限制、`连续 5 次 → 1 小时`；**这两个限制按账号还是按 IP 施加，仓内尚无一手证据**，故本条不承诺「推给客户端即可规避」。
5. **不跟随真站、不回显非必要 Set-Cookie**：302 只允许在 `webvpn.sicau.edu.cn` 域内跟随；目标为真站时立即停止并返回明确错误。上游 `Set-Cookie` 中**除下发给本人的票之外**的内容不回显给调用方。票据失效（302 → `/login`）与教务会话失效（正文「登录超时」）在**能观测到的一方**映射为两个可区分错误：经后端的交互由后端产出；客户端直连时由客户端依据最终 URL 前缀与响应正文自行判定。 [2026-11-07 修订]

「开放成任意 URL 代理」由此被排除，但依据是第 1 条的**结构性设计** + SSRF 原理 + ToS，而非旧 spec 的禁令。

## 2026-11-07 修订：直连模式与票据下发

[功能范围切分：新后端承载 WebVPN 五段能力中的哪几段](https://github.com/NongyuSystem/nongyu-backend-plus/issues/3) 定下「路径一」：**承认票据必须到客户端，删掉「一次性访问许可」这一层**。变更理由：

- [红队审查-Q3C分流方案.md](<docs/tech/红队审查-Q3C分流方案.md>) 证伪了早先的「分流 + 许可」方案：学校网关只认 `wengine_vpn_ticket*` 与 CAS ticket XML，**不认任何第三方签发的许可**；而编码后的地址由常量 + 纯函数算出、本就公开，许可保护不了任何东西。
- 客户端要直连学校，就必须持有票据（旧仓直连能力完全建立在「票在客户端 + `withCredentials`」上）。故「票不出后端」与「客户端直连」不可同时成立，本 ADR 选择承认前者、放弃后者。

**代价与由此产生的约束（必须由后续 Spec 承接）**：

- 客户端成为票的独立持有者，凭据边界画在客户端；后端对它如何使用票**无强制力**。
- **后端失去对「高频只读」请求的观测**：既无限流、也无审计。这是本修订明确接受的盲区，不得在后续文档中声称「所有请求均已限流」。
- 「15 秒 / 1 小时」限制按账号还是按 IP 施加**尚无一手证据**；若按 IP 施加，客户端直连未必降低被拉黑风险。
- 审计退化为「事后流水」：若需追溯客户端直连行为，只能用后端签发的**流水号 + 客户端回执上报**，且须明说它是事后审计、不是事前授权。
- 旧实现「网络错误最多重试 3 次、每次间隔 1 秒」与 15 秒限制直接冲突，**后续 Spec 必须撤掉或加门**。
