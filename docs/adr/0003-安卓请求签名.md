# ADR-0003：安卓请求签名，不另加 JWT

- 状态：accepted（2026-11-11）
- 相关：[GLOSSARY.md](../../GLOSSARY.md)、[ADR-0002](<0002-身份仓数据边界.md>)

## 背景

要保证「用其它方式向服务器发请求会被拒绝」，也就是请求不能被 curl / 脚本仿造。同时后端已经有 HMAC 自包含令牌和可吊销会话令牌，作用是证明「用户是谁」。

主力用户在无 GMS 的国产安卓机上，且不上架 Google Play。Play Integrity 在这种设备上起不来；SafetyNet 已关停；Key Attestation 对非 Google 认证机型没有信任锚。平台证明这条路不成立。

## 决定

1. **不加 JWT。** 用户身份继续用现有 HMAC 会话令牌（`Authorization: Bearer`）。业务域不改。
2. **另加一层请求签名**，只证明「请求来自持有当前密钥的客户端」。登录、发验证码、业务接口都要签。`/healthz` 与 `/status` 豁免，给探针留门。
3. **协议 NY1**：对 `方法 + 路径 + raw query + body SHA-256 + 时间戳 + nonce + key id` 做 HMAC-SHA256。时间窗 ±5 分钟，nonce 只可用一次。规范化串与 `nongyu-app-plus` 的 `AppRequestSigner` 逐字节对齐，共享测试向量。
4. **密钥可轮换、可吊销。** `APP_SIGNING_KEYS=kid:base64url[,kid2:...]`。删掉 kid 即吊销。prod 缺密钥拒绝启动。有 Redis 时 nonce 走 `SET NX`（失败即拒绝，不把存储故障当成放行）；没有 Redis 时只用进程内存，并打警告。
5. **接受密钥可被从 APK 提取。** 这不是「未被改包」的证明，只是把仿造成本从「直接打接口」抬到「先从包里抽出密钥」。字符串混淆不算保管手段。

## 后果

- 本地不配 `APP_SIGNING_KEYS` 时，现有 curl / 单测仍能打接口。要和 App 联调验签，把 `.env.example` 里那把开发密钥配上。
- 生产密钥不要提交进仓库。App 侧用 gradle 属性 `appSigningKey` / `appSigningKeyId` 注入；不注入时 debug/测试包用同一把开发密钥。
- 换协议必须改版本串（NY1 → NY2），并同时改两端向量测试。
