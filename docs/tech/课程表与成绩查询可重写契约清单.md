## ① 业务查询清单

### 1.1 契约形状：所有模块都长一个样

15 个模块是同一个模板的三段式（以 `getCourseInfo` 为例）：`fetchJiaowuHtml(常量 URL)` → `extract*(html)` → `catch` 里返回 `jiaowuFailResult(<空值>, error)`。[来源: @OLD/packages/nongyu-tool-jiaowu/core/jiaowu/courseInfo.ts:96-104]

失败形状由 `jiaowuFailResult<T>(result, error)` 统一产出 `{ success: false, result: <T>, message: string }`，`message` 经 `resolveJiaowuErrorMessage` 归一：**超时类错误一律替换成固定文案** `"教务网迁入内网，可尝试连接校园网使用农屿"`，其余透传 `error.message`。[来源: @OLD/packages/nongyu-tool-jiaowu/core/utils/errors.ts:55-67,72-85]

即：**`success:false` 有两种完全不同的成因**——「网络/会话失败」（带 `message`）与「抓到了但页面里没数据」（extractor 自己返回 `success:false`，**不带 `message`**）。两者只能靠 `message` 是否存在区分。[来源: @OLD/packages/nongyu-tool-jiaowu/core/jiaowu/courseInfo.ts:96-104；@OLD/packages/nongyu-tool-jiaowu/core/extractor/courseInfoExtractor.ts:107]

1. **课表与成绩都没有「学期」入参**。`getCourseInfo` 只带 `title_id1=4`，`getScoreInfo` 连 query 都没有——它们抓的永远是「教务当前认定的学期/全部成绩」。旧仓里受学期影响的地方全部在**客户端或解析后**：成绩页自己按 `term` 分组排序（`b.term.localeCompare(a.term)` 降序），课表页按 `weeks` 决定渲染哪些周。[来源: @OLD/packages/nongyu-tool-jiaowu/core/jiaowu/courseInfo.ts:11-12；scoreInfo.ts:11；@OLD/apps/nongyu-rn-app/src/modules/jiaowu/screens/ScoreScreen.tsx:19-32]

## ② 解析器契约

### 2.1 先讲共享的 HTML 工具：它决定了所有解析器的能力上限

四个原语，全部是正则/手写扫描，**不引 DOM 库**：[来源: @OLD/packages/nongyu-tool-jiaowu/core/utils/html.ts:1-111]

| 原语 | 行为 | 关键边界 |
| --- | --- | --- |
| `decodeEntities` | 只解 `&nbsp; &lt; &gt; &amp; &quot; &#39;` + 十进制 `&#NNN;` | **不解十六进制 `&#xNN;`**，不引实体表 [html.ts:15-32] |
| `stripTags` | `<br>` → `\n`，删 `script`/`style`/全部标签，再解实体，压行尾空格与 3+ 连续换行 | **`<br>`→换行是课表多行字段能成立的前提** [html.ts:43-58] |
| `extractSegments(html, ...tags)` | 手工数标签深度配对，支持同名嵌套 | 只认 `<tag ...>` / `</tag>` 字面形态 [html.ts:71-94] |
| `parseTable(tableHtml)` | `extractSegments(tr)` → 每行 `extractSegments(td,th)` → `stripTags` | **完全不处理 `rowspan`/`colspan`**，返回的是「行内实际出现的 td 序列」 [html.ts:105-111] |

`parseTable` 不展开 `rowspan/colspan` 是整个领域最重要的一条结构性约束，它直接解释了下面几件事：

- 成绩/考试/排名/进度这些「规整表」用 `parseTable` + 表头关键字定位列，**够用**；
- 教室课表/教师课表是「周×节」矩阵，用 `rowspan` 表达「上午/下午/晚上」，`parseTable` 会错位，所以这两个解析器**绕开 `parseTable`，自己手写 `<tr>` 扫描 + `rowspan` 探测**；[来源: @OLD/packages/nongyu-tool-jiaowu/core/extractor/classroomCourseInfoExtractor.ts:115-167；teacherCourseInfoExtractor.ts:112-167]
- 进度表有「rowspan 分类标签行 7 列 / 普通行 6 列」的混合，解析器用**列数启发式 + 偏移 1** 兜。[来源: @OLD/packages/nongyu-tool-jiaowu/core/extractor/progressInfoExtractor.ts:59-72]

### 2.2 `courseInfo`（课表）——本次任务的核心之一

**入口**：`extractCourseInfo(html) => { result: CourseItem[], success: boolean }`。[来源: @OLD/packages/nongyu-tool-jiaowu/core/extractor/courseInfoExtractor.ts:53-108]

**定位策略**（与其他解析器都不同）：
1. 用**非贪婪正则** `/ <table[\s\S]*?<\/table> /gi` 切所有表格（注释明说这样做是为了「避免 `extractSegments` 的深度嵌套问题」）；[courseInfoExtractor.ts:59-61]
2. 按 **HTML 长度降序**排序，逐个 `parseTable`，丢掉行数 < 2 的；[courseInfoExtractor.ts:62-65]
3. 对每个 grid 取「第一个有内容的行」当表头，`detectColumns` 认列；**认不出 `courseName` 列就跳过**；[courseInfoExtractor.ts:68-73]
4. 第一个能产出非空 items 的表格直接返回 `success:true`；都不行则 `{result:[], success:false}`。[courseInfoExtractor.ts:102-107]

**列识别**（表头文本 normalize：去空白、去中英文冒号、转小写，然后**子串包含**匹配，取第一个命中）：[courseInfoExtractor.ts:114-136]

| 字段 | 关键字（按优先级） |
| --- | --- |
| `campus` | `校区` |
| `courseName` | `课程名称` → `课程名` → `课程` |
| `courseId` | `编号` → `课程编号` |
| `weeks` | `周次` → `上课周次` |
| `classroom` | `教室` → `上课教室` |
| `scheduleTime` | `上课时间` → `时间` |
| `credit` / `hours` | `学分` / `学时` |
| `weeklyHours` / `labHours` | `周学时` / `实验周学时` |
| `assessmentMethod` | `考核方法` → `考核方式` |
| `teacher` | `教师` → `任课教师` |
| `enrollmentType` / `blendedTeaching` | `选课方式` / `混合式教学` |

**字段语义（14 个字段，全部 `string`，缺列即 `""`）**：[courseInfoExtractor.ts:11-26,145-148]

| 字段 | 语义与形态 |
| --- | --- |
| `campus` | 校区简称（`雅安`/`成都`/`都江堰`） |
| `courseName` | 课程中文名；**唯一必需字段，为空则不产出该行** [courseInfoExtractor.ts:97-99] |
| `courseId` | 课程编号（纯数字串） |
| `weeks` | 教学周范围，形态 `1-16`（也见过单周 `8`） |
| `classroom` | **多行**：一格多时段时每行一个教室，用 `\n` 分隔；空心课可能整格是 `""` |
| `scheduleTime` | **多行**：每行形如 `3-3,3-4` 或 `2-9,2-10(单)`；也可能是不可落格的散文（如 `自行在线学习`） |
| `credit` / `hours` / `weeklyHours` / `labHours` | 学分 / 学时 / 周学时 / 实验周学时，数字串，可能 `0` |
| `assessmentMethod` | `卷面考核` / `其它` 等 |
| `teacher` | 教师名，**可能为空**（纯线上课） |
| `enrollmentType` | `初修` / 重修等 |
| `blendedTeaching` | 混合式教学说明，**长文本、可能含 URL 与换行** |

`classroom` 与 `scheduleTime` 的「多行 + 行序对齐」语义由**下游客户端**承担：`mapJiaowuCourseItems` 把 `classroom` 按 `\n` 切、把 `scheduleTime` 按 `\n` 切成时段，再**按数组下标把第 i 个教室配给第 i 个时段**（`rooms[idx] || rooms[0] || ""`，即行数不等时回落到第一个）。[来源: @OLD/apps/nongyu-rn-app/src/modules/course/model/mapJiaowuCourseItems.ts:191-213]

`scheduleTime` 的单行解析规则（`parseScheduleTimeLines`）：`D-P` 形式的逗号对（`3-4,3-5` → 第 3 天第 4~5 节），`(单)`/`(双)` → `odd`/`even`，**首尾不同天则整行丢弃**（`if (d1 !== d2) continue`），命中 `任课教师自行安排|自行在线学习|自行安排` 的整行跳过。[来源: @OLD/apps/nongyu-rn-app/src/modules/course/model/mapJiaowuCourseItems.ts:63-105]

**异常容忍**：全程不抛错。空/非字符串入参 → `{result:[],success:false}`；找不到课表 → 同上；**单行缺 `courseName` 静默丢弃**；列缺失 `pickCell` 返回 `""`，不会越界。[courseInfoExtractor.ts:54-57,145-148]

**两条容易踩的语义**：

1. **行有效性的门是 `courseName && score` 同时非空**（`if (item.courseName && item.score)`）。只有课程名没有成绩的行（例如成绩未录入）会被**静默丢弃**。[scoreInfoExtractor.ts:84-86]

## ③ 编码与解码

### 3.1 结论：教务页面是 **GBK**（`gb2312` 声明），解码发生在**请求响应拦截器**，不在 `fetchJiaowuHtml`

- `fetchJiaowuHtml(url, headers?)` **只做一件事**：`get<string>(url, undefined, {headers})`。它拿到的是**已经被解码成字符串**的值；GBK 解码发生在更下层。[来源: @OLD/packages/nongyu-tool-jiaowu/core/utils/fetchJiaowuHtml.ts:23-28]
- 真正的解码点：axios 实例 `responseType: "arraybuffer"`，响应拦截器**无条件先 `decodeGbk(response.data)` 再写回 `response.data`**。[来源: @OLD/packages/nongyu-tool-jiaowu/core/utils/request.ts:39-46,189-195]
- `decodeGbk` = `iconv.decode(buf, "gbk")`；`decodeToText` 默认 `encoding = "gbk"`。[来源: @OLD/packages/nongyu-tool-jiaowu/core/utils/decode.ts:19-27,36-38]
- 注释给出的理由：`check.asp`（登录）必须也解成字符串，否则无法识别失败脚本 —— 所以解码放在**全局拦截器**而不是按需。[来源: @OLD/packages/nongyu-tool-jiaowu/core/utils/request.ts:193-194]

### 3.2 会话失效也是靠「解码后的正文」判定的

拦截器在解码之后才做失效判定：最终 URL 以 `https://webvpn.sicau.edu.cn/login` 开头，或正文含 `登录超时` / `账号验证失败` → 清 Cookie 并 reject `JiaowuSessionExpiredError`。[来源: @OLD/packages/nongyu-tool-jiaowu/core/utils/request.ts:203-212]

这条对重写很关键：**HTTP 状态码不携带失效信息**，必须解码后才能判。实测两份失效页都是 `200` + 一段 GBK 编码的 JS `alert`：`_temp_gate_916.txt` 是 `<script>alert('系统提示：登录超时，请重新登录！')…`，`_temp_gate_619.txt` 是 `alert('验证失败，请通过正常链接重新登录！')`——**后一种不含「登录超时」，旧仓的失效判定抓不到它**。[来源: 本会话实测 `_temp_gate_916.txt`、`_temp_gate_619.txt`]

### 3.3 中文**出站**参数必须 GBK 编码

`encodeGbkUrl(str)` 用 `iconv.encode(str,"gbk")` 逐字节转 `%XX`（大写、两位补零），示例 `encodeGbkUrl('蒲海波') === '%C6%D1%BA%A3%B2%A8'`。[来源: @OLD/packages/nongyu-tool-jiaowu/core/utils/decode.ts:40-55]

### 3.4 新仓的编码先例：`schoolauth/academic.go` 做对了什么、踩了什么坑

**做对的**：

1. **先判 UTF-8 合法，再回落 GBK**，而不是「先试 GBK 再看像不像 HTML」。文件头把坑写死了：GBK 解码器对非法字节很宽容，UTF-8 字节被解成乱码后 ASCII 部分（如 `<table`）原样保留，于是「像 HTML」会误判为真，把乱码当正常内容，最后表现为**表头全空、字段全空**——而且**不报错**。[来源: @NEW/internal/school/schoolauth/academic.go:273-292]
2. 依赖 `golang.org/x/text/encoding/simplifiedchinese` 的 `GBK.NewDecoder()`，不自己写码表。[academic.go:294-312]
3. 会话失效靠**正文**判（`登录超时` / `请重新登录`），不靠状态码。[academic.go:108-111]
4. 表头关键字用「包含匹配 + **更长表头优先**（`sort` 按长度降序，附注释「map 遍历顺序随机，必须显式排序」）」+ `lookupExcluding` 排除「新专业」抢「专业」。`CleanValue` 去脚本/去标签/去全角与半角括注/压空白。[academic.go:143-211,254-265]
5. 全链路零依赖 DOM 库，只用 `regexp`（包内 6 条预编译正则）。[academic.go:55-68]
6. 结构化断言式测试：`ParseAcademic` 失败必须是 `error`，不允许「返回空值当成没数据」；测试里显式写「登录超时页面 HTTP 200 但没有数据表 → 必须判失败」。[来源: @NEW/internal/school/schoolauth/academic_test.go:118-133]

**踩过/仍存在的坑**：

1. **`decodeGBK` 是包内私有函数**，没有提到 `platform`。新仓 `grep simplifiedchinese` 全仓只有 `schoolauth/academic.go` 与其测试两处命中 —— 也就是说这套解码目前**不可被其他子域复用**，教务子域若要解析页面就得复制一份。[来源: 本会话 grep `@NEW` 全仓 `simplifiedchinese`]
2. `ParseAcademic` 对「表头/值行数不等」用「以较短为准、多余列忽略」吞掉，**没有告警**；如果教务加列，解析会静默降级而不是报错。[academic.go:134-141]
3. `reNBSP` 与 `CleanValue` 里对 `&nbsp;` 的处理是用普通空格替换后再 `strings.Fields`，**不解 `&#160;` 之类的数字实体**（旧仓 `decodeEntities` 解，New 仓这一层不解）。[academic.go:254-271]
4. 仅覆盖 1 个页面（`bjiben.asp`），且该页面结构（`g_column`/`g_body_2`）**与课表页、成绩页并不相同**（后两者是表头行 + 数据行，无 class 标记，见 ②）——所以这套解析**不能直接套到课表/成绩上**，能复用的只有「解码 + 失效判定 + 清洗 + 关键字映射」四件事。

### 5.1 课表：唯一「真·本地缓存」的资源，语义是「本地优先，无 TTL，手动刷新」

**缓存键**：`course:entries:<studentId>`（前缀常量 `COURSES_KEY_PREFIX = "course:entries:"`），存 `JSON.stringify(CourseEntry[])` 到 MMKV（`appStorage`）。[来源: @OLD/apps/nongyu-rn-app/src/modules/course/data/courseLocalStore.ts:4-8,13-23,28-30]

| 函数 | 行为 | 来源 |

### 5.2 成绩/排名/进度/考试/培养方案：**没有本地持久化**，只有 React Query 内存缓存 + 分资源 staleTime

### 6.2 `Fetch` 的三条硬事实

1. **返回原始 body 字节，不解码、不判 charset、不解析**：`io.ReadAll(resp.Body)` 直接塞进 `FetchResult.Body`。[来源: `@NEW/internal/school/jiaowu/service.go:223-229`]
2. **不透出业务语义给上层**：handler 把 body 原样以 `application/octet-stream` 写出，并**二次剥离 `Set-Cookie`**；失败才返回 `{code,message}` JSON。[来源: `@NEW/internal/school/jiaowu/handler.go:77-98`（`fetchHandler` 全 22 行）、:100-121（`writeError` 错误码→状态映射）]
3. **`Fetch` 不注入任何会话凭据** —— 它只拼 URL 就 `doer.Do`，`Service` 里虽有 `tickets platform.TicketStore` 字段，但 `Fetch` 全程未读取它。[来源: `@NEW/internal/school/jiaowu/service.go:178-196`（对比同文件 `Login`/`Logout` 才用 tickets）]

第 3 条是本次差距里最需要被看见的一条：**新仓目前没有任何「带教务会话去取需登录页面」的路径**。真正带 Cookie 取页面的实现在另一个包——`schoolauth.JiaowuSource.FetchPage`：它先 `EnsureFresh(tgt)` → `exchangeTicket` → `establishSession` 拿会话 Cookie → `req.Header.Set("Cookie", sessionCookies)` → `io.LimitReader(resp.Body, 2MiB)`。[来源: `@NEW/internal/school/schoolauth/jiaowu.go:326-376`，`maxJiaowuBody = 2 << 20` 见 :50]

也就是说：**解析器的上游数据源，如果走 `jiaowu.Service.Fetch` 就只有 WebVPN 网关注入 Cookie 这一条路**；想直连取需登录页，必须复用 `schoolauth` 那条换票链，或在 `jiaowu` 里新增等价能力。仓内未找到把两者接起来的代码。

### 6.3 `platform/cache.go` 的 `GetOrLoad` 签名与键前缀约定

```go
// Loader 是回源函数：found=false 表示下游明确「查无此物」（会触发空值缓存）。
type Loader func(ctx context.Context) (value []byte, found bool, err error)

func (c *RedisCache) GetOrLoad(ctx context.Context, key string, loader Loader) ([]byte, error)
```

[来源: `@NEW/internal/platform/cache.go:316-323`]

语义要点（`GetOrLoad` 全 37 行，:323-359）：

- 命中正常值直接返回；命中空值哨兵返回 `(nil, nil)` **且不回源**（防穿透）；未命中走进程内 singleflight 重建，`RebuildTimeout` 超时返回错误。[cache.go:323-340]
- `found=false` → 写入 `emptyMarker`，TTL 取 `NotFoundTTL`；`found=true` → `Set`（TTL 传 0 表示用 `DefaultTTL`，**仍会加抖动**）。[cache.go:349-358；`Set` 见 :240-247]
- **值只能是 `[]byte`**：业务必须自己 `json.Marshal`/`Unmarshal`，缓存层不做类型。[cache.go:316-317]
- 降级：Redis 出错/熔断时落进程内存，`FallbackEnabled` 由装配层置 `true`。[cache.go:211-238,240-265；`@NEW/internal/app/app.go:156-176`]

**键前缀约定（两段拼）**：

```go
cacheKeyPrefix = "cache:"
func (c *RedisCache) fullKey(key string) string { return c.prefix + cacheKeyPrefix + key }
```

[来源: `@NEW/internal/platform/cache.go:98-104,192`]

- `prefix` 来自 `RedisOptions.Prefix`，`NewRedisCache` 里缺省填 `"nongyu:"`；装配层从 `cfg.RedisPrefix` 传入，配置默认值也是 `nongyu:`。[cache.go:143-150；`@NEW/internal/config/config.go:119`；`@NEW/internal/app/app.go:157-162`]
- 所以业务键 `jiaowu:course:<studentId>` 实际落 Redis 为 **`nongyu:cache:jiaowu:course:<studentId>`**。
- **同包内另两套前缀是不同的**：`RedisTicketStore` 用 `<prefix>ticket:<userID>`（`:576`）与 `<prefix>expiries`（`:580`）；`RedisSessionCache` 用 `<prefix>session:<id>`（`:721`）。三者不共用 `cache:` 中间段。[来源: `@NEW/internal/platform/cache.go:521-529,576-580,696-731`]

**缓存层是可选依赖**：`Cache` 只在 `cfg.RedisAddr != ""` 时构造，否则字段为 `nil`，注释要求「业务侧按『无缓存直接命中』处理」。[来源: `@NEW/internal/app/app.go:154-156`；同文件 :45 的字段声明]
