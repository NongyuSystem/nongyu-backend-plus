## 决议（Q1~Q5 全 A）

**Q1 effort 边界 = 另立一份新 PRD**（`docs/specs/prd-六类常见功能.md`），**不改现行 PRD 的范围段**。
- 理由：① 不动已交付 effort 的合同（现行 PRD 是 WebVPN effort 的契约，#1/#19/#30 的验收挂在它上面）；② 满足 SDD 的 PRD 前置；③ 把原本不存在的「多 PRD 并存」显式立规。
- **配套**：`README.md` 的「开发流程（SDD）」段补一句「本仓当前并行承载多个 effort，各自有 PRD；`docs/specs/` 下按 effort 分文件」。
- 否决：修订现行 PRD（会事后修改已交付 effort 的合同）；跳过 PRD 直接补 Spec（正面违反 `README.md:80`）。
- **新 PRD 的撰写不在本票做** → 另立 [#56 撰写新 PRD](https://github.com/NongyuSystem/nongyu-backend-plus/issues/56)（`wayfinder:task`），作为 [#51](https://github.com/NongyuSystem/nongyu-backend-plus/issues/51) 的前置。

**Q2 仓库定位句跟着改**：`README.md:3` 与「状态」段从「本仓是 WebVPN 能力重写的仓」改为「本仓承载多个业务 effort（WebVPN 迁移、身份域/平台底座、六类常见功能），各自有 PRD/Spec」。`GLOSSARY.md:3` 已按 effort 分段（#52 已改），**不再动**。否决：不改定位句（文档与事实长期矛盾）；把六功能挪到新仓（与 Destination 冲突，且与身份域/`StudentBrief` 强耦合）。

**Q3 粒度**：本图六域各已定到「**域模型 + 端点契约 + 鉴权口径 + 存储载体 + 派生规则**」（五份决策笔记）。**明确交后续 Spec 的只有四类**：① 具体表 DDL 与迁移脚本；② 各域验收用例逐条清单；③ TTL / 保留期 N / 缓冲参数等数值；④ `audit_log.action` 完整取值表与权限矩阵（#46 D4/D5 已指给 #51）。**本图不再补任何域模型**。

**Q4 Out of scope 共 13 条**（每条有出处）：
- 原有 7 条：管理端 UI、完整 RBAC、运行日志/审计/ES 重定、MinIO 选型重开、埋点查询分析平台、旧代码/表结构/部署复用、可运行代码与 PR。
- 新增 2 条：旧仓 Admin JWT「永不过期」口径、把 `notified_author` 行级投递位照搬成 per-user 已读。
- 由已关票导出 4 条：① 埋点做成独立服务（#45 Q1）；② 照抄旧 Track 的 `{ok,data}`+503（#45 Q2/Q5）；③ 埋点域做 `presence/offline`（#45 D2）；④ 要求 `/admin/*` 签 NY1、把业务公开读塞进 `publicPaths`（#46 Q1/Q4）。

**Q5 与前序 map 的边界 + 横切指认**：**不重开三张已关 map 的任何结论**（WebVPN 能力重写、身份域/平台底座、教务查询与缓存），仅**复用**它们已落地的能力（`StudentBriefReader`、会话/role、`RedisCache`、`RateLimitMiddleware`、`audit_log`）。六功能之间的横切依赖逐条指认，**每条只在一张票里定、另一张引用**：
