# 决议：六功能共用的横切鉴权口径

> 来源：[决议：六功能共用的横切鉴权口径（role 三档 / admin 会话 / 公开与登录作用域）](https://github.com/NongyuSystem/nongyu-backend-plus/issues/46)（wayfinder map #43 子票），2026-11-12 收口（HITL grilling，Q1~Q6 全 A + 5 项派生项按推荐收敛）。
> 性质：**决策记录**，不是 Spec、不是实现。本票的 resolution comment 是决议正文；本文是给 [#54](https://github.com/NongyuSystem/nongyu-backend-plus/issues/54) / [#51](https://github.com/NongyuSystem/nongyu-backend-plus/issues/51) 引用的稳定落点。

## 前置（已锁，不在本票重开）

- **Q3（六题全 A）**：B 端管理 = 管理台后端 API + 复用既有 `role` 三档（0/1/2）与 `scope=admin` 会话（可吊销、有过期、兜底 fail-closed）；管理端 UI 在 `nongyu-web-admin`，**不建完整 RBAC**。
- **既有底座（一手核对，不重开）**：
  - `publicPaths` 是**全仓唯一**公开路径来源（`internal/server/revocable_auth.go:134-150`），现有 5 条：`/healthz` / `/status` / `/identity/login` / `/identity/mailcode` / `/identity/register`；匹配规则「精确相等 or 以 `p+"/"` 为前缀」（`:152-163`）。
  - `RateLimitMiddleware` **只豁免 `/healthz`**，注释明写「刻意不用 `IsPublicPath`：限流豁免与『是否需要认证』是两件事」；未认证按 IP 计数（`internal/server/auth.go:153-178`）。
  - `platform.Role` 0/1/2 + DB `CHECK (role IN (0,1,2))`（`store.go:610-620,962`）；`session.RequireRole` 对非法角色/非法最低要求/UserID=0 **一律拒绝**（`session/service.go:208-220`，`TestRequireRole_FailClosed`）。
  - `DefaultAdminTTL = 12h`，`ScopeAdmin` 与 `ScopeApp` 分离（`session/service.go:22-26`、`store.go:728`）。
  - **NY1 只豁免 `/healthz` 与 `/status`**，且「登录、发验证码、业务接口都要签」（[ADR-0003](<../adr/0003-安卓请求签名.md>):15-18）；**密钥在 Android APK 内**（`:16,23`）。
- **旧仓口径已被推翻**：旧仓 Admin JWT **不设 exp**（`../../docs/nongyu-node-server/specs/App与Admin鉴权会话策略.md:24`）；新仓要求可吊销 + 明确过期 + fail-closed（`GLOSSARY.md:70`、[领域模型:148-150,162](领域模型-用户与登录-消息.md)）。
- **上游四张票挂来的遗留项**：#44（管理端鉴权粒度）、#49（管理端查实名 + 「默认关闭」GitHub 开关权限）、#55（消息端点鉴权）、#45（埋点端点 NY1/publicPaths）。

## 决议（Q1~Q6 全 A）

**Q1 公开（免登录）端点判定**：判据 = 「内容是公开产品数据」vs「需要知道你是谁」。
- **免登录仅 5 个只读端点**：`GET /announcements`、`GET /announcements/:id`、`GET /announcements/latest`、`GET /posts`、`GET /posts/:id`。
- **其余一律需要农屿会话**：含回复/点赞/收藏、内部信/消息、埋点上报、以及**所有 `/admin/*`**。
- **落法**：**不往 `publicPaths` 里加业务端点**（保持它只服务「取得身份」类路径的原语义），**新增独立的 `publicReadablePaths` 清单**，由**同一个 `IsPublicPath` 判定函数**统一消费 → 仍只有**一处**判定入口，不违反「避免各自为政（M5/N6）」。
- 否决：全塞 `publicPaths`（两种语义混一文件，稀释原前提）；一律要登录（公告/帖子对未登录不可见，使 #44 的 `latest` 首页通知栏语义落空）。

**Q2 管理台端点鉴权**：`/admin/*` 统一要求 **`scope=admin` 会话 + `role >= 1`**；**改 role、GitHub 集成开关等敏感操作要求 `role >= 2`**（超管）。判定**直接复用既有 `session.RequireRole`**（已 fail-closed）；**role 以 DB 为准、令牌内 role 只作提示**（沿 ADR-0002:71）。**新增薄封装 `AdminOnly` 中间件**（`RequireRole(..., RoleAdmin)` 的组合），**不改既有 `RevocableAuthMiddleware`**。

**Q3 审计粒度与 `audit_log.action` 规范**：**命名 `<域>.<动作>`** —— `post.delete` / `post.restore` / `announcement.publish` / `announcement.revoke` / `user.role_change` / `integration.github_toggle` / `message.read_all` 等；**一次管理动作一条**（不做一请求多动作合并）；**审计对象记在既有 `target` 列**（`<域>:<id>`，如 `post:12345`）；**只记标识性字段**（沿 `持久层结构.md:62` 铁律：绝不写票据/密文/验证码/上游响应体）；**管理员读普通用户敏感数据也算一次审计**。不建独立审计表。

**Q4 NY1 请求签名适用面 = 分层**：
- **App 侧业务端点与埋点上报继续要签 NY1**（密钥在 APK 内，符合 ADR-0003 威胁模型）。
- **`/admin/*` 不签 NY1** —— Web 端拿不到 APK 密钥；管理端安全边界由 **admin 会话 + role 三档 + fail-closed + 审计**承担。
- **埋点上报按 `platform`（app / web）区分**，不一刀切。
- 否决：全部要签（需向浏览器分发 APK 密钥，**正面击穿 ADR-0003 威胁模型**）；全部不签（App 侧失去防伪造，与 accepted ADR 冲突）。

**Q5 中间件顺序**：**`RequestID → NY1（适用时）→ 鉴权（会话）→ AdminOnly（仅 /admin）→ 限流`**；**不新增 `RequestIDMiddleware`/限流实现**（复用既有）；**`/status` 保持公开且限流豁免**（限流仍只豁免 `/healthz`）；**埋点端点必须挂限流，但不列入限流豁免**。

**Q6 管理员读普通用户隐私数据边界**：**最小必要 + 全部留痕** —— 管理端只能读**业务所必需**字段（帖子作者学号姓名、消息收件人身份等）；**身份证号等 ADR-0002 敏感字段默认不返回**，确需时走**超管（`role>=2`）+ 显式原因参数 + 必记审计**；**所有此类读取每次一条审计**（如 `user.read_sensitive`）。否决：可读任意画像字段（与 ADR-0002 冲突）；完全不读画像（#44 定向公告需 `StudentBrief`、#49 管理端实名展示落不了）。

## 派生项（票评「下一轮才问」的 5 项，按「按推荐」保守收敛，可回滚）

- **D1 管理台会话续期/吊销入口**：**复用既有 `logoutall` + 会话吊销**，**不新增 admin 专用端点**；管理台会话 `DefaultAdminTTL = 12h` 不变，过期即重新登录。若将来要做「管理台强制下线某会话」，另立。
- **D2 `publicReadablePaths` 的限流档位**：**本期不做单独档位**，与普通未认证请求同为「按 IP 计数」（`RateLimitMiddleware` 既有行为）；若公开读成为刷量入口，再评估。
- **D3 埋点 Web 来路的判定依据**：**本期接受 `platform` 字段由客户端自报**（可伪造），Spec 记为**已知边界**；不为此引入更强的客户端证明（会与 ADR-0003 的取舍冲突）。→ fog。
- **D4 `audit_log.action` 完整取值表**：本票只定**命名规范**（`<域>.<动作>`）与**示例集**；**完整取值表与索引调整归 [#51](https://github.com/NongyuSystem/nongyu-backend-plus/issues/51)**。
- **D5 超管 vs 管理员的差异清单**：本票只锁**两类敏感操作要 `role>=2`**（改 role、GitHub 开关）+ **读敏感字段要 `role>=2`**；**完整权限矩阵归 #51 在 Spec 里列表**。

## 本票未裁定 / 留 fog

- **埋点 Web 端 `platform` 自报可伪造**（D3）：本期接受，Spec 记已知边界。
- **管理台「强制下线他人会话」**：本期不做，复用 `logoutall` 语义。
- **公开只读端点的独立限流档位**（D2）：本期与普通未认证请求同档。
- **完整审计 action 取值表与索引**（D4）→ #51。
- **超管/管理员完整权限矩阵**（D5）→ #51。
- **管理端的 CSRF / 会话固定防护**：Web 管理端特有，本票未涉及 → 若 #51 认为必要另立。

## 对下游票的约束
