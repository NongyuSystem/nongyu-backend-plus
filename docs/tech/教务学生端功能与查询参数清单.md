### 1.2 实地核对：未登录时的响应形态

关键前置：**`jiaowu.sicau.edu.cn` 从本机公网直连可达**，不是内网。`curl -sv https://jiaowu.sicau.edu.cn/` 解析到 `202.115.177.11` 且 TCP+TLS 均建连成功（TLS 断在客户端 Schannel 凭证问题，见上）。与知识库既有结论一致（「302 即可达，无需 WebVPN」）。

**闸门两跳已解开**：302 的目标 `.../jiaoshi/bangong/index.asp` 本身返回 **200**，但正文是一句 JS：

```
<script language=javascript>alert('系统提示：登录超时，请重新登录！');window.location.href='../../index_out_mi.html'</script>
```

[来源: 实测 `https://jiaowu.sicau.edu.cn/jiaoshi/bangong/index.asp` 返回 200，正文 195 字节]

同样，旧口令端点 `check.asp` 返回 200 + `alert('验证失败，请通过正常链接重新登录！')` [来源: 实测 `.../jiaoshi/bangong/check.asp` 返回 200，122 字节]。

**判定要点：教务的「未登录」不是靠 HTTP 状态码表达的**——它先 302 到闸门页、闸门页再 200 + JS alert 跳回登录页。因此 Go 侧判失效必须看**正文**（旧仓正是这么做的：检查 `登录超时` / `账号验证失败` 字样）[来源: @OLD/packages/nongyu-tool-jiaowu/core/utils/request.ts:202-217]。

**「302 是因为页面存在、而不是 IIS 对任何路径都这样」——已用对照组排除**：`.../xuesheng/gongxuan/gongxuan/zzz_not_exist_12345.asp` 返回 **404**（1163 字节），而同目录的 `kbbanji.asp` 返回 302。故 302 是 ASP 脚本在执行的登录检查，页面**真实存在** [来源: 实测两个 URL 对照，404 vs 302]。

**结论**：学生端全部功能页（`/xuesheng/**`）未登录一律 302 到登录闸门，**没有任何一个能在未登录状态下读到内容或导航菜单**。`/xuesheng/` 目录页甚至连 403 都不给目录列表。因此：
> **学生端功能页清单的权威来源只能是旧仓 URL 清单 + 功能名**；未登录态下无法从教务网侧独立枚举或交叉验证功能名，本清单不编造任何旧仓以外的功能。

### 1.3 例外：教室/教师课表页在未登录时是**部分公开**的

这是本次核对最有价值的发现，与「全部需要登录」的预期不同：

- `jshi_new.asp?bj=10-A104`（教室搜索）**不需要登录即返回完整列表**，表结构为 `table#grid`：`序号 / 校区 / 教室地点 / 可容纳人数 / 教室类别 / 查看`，其中「查看」列是 `kbjshi_new.asp?bianhao=86556277812094529780603989715685`（32 位数字串）[来源: 实测 `.../jshi_new.asp?bj=10-A104` 返回 200]
- `jiaoshi_new.asp?xm=<GBK 姓名>&shou1=`（教师搜索）同样**免登录**，`table#grid` 列为 `序号 / 校区 / 部门 / 姓名 / 查看`，返回 3 条「张洁」记录，每条带 40 位 `bianhao` [来源: 实测 `.../jiaoshi_new.asp?xm=%D5%C5%BD%E0&shou1=` 返回 200]
- **链式验证通过**：用上面拿到的真实 `bianhao=97803259897110359780603981208732` 请求 `kbjshi_new.asp`，返回 **200 / 23,305 字节**，正文含完整课表：「四川农业大学课程表(10-A104)」，周一 12 节有「高级语言程序设计I101 胡兵(2) 5-14周 178人 专业基础课」等 [来源: 实测 `.../kbjshi_new.asp?bianhao=97803259897110359780603981208732` 返回 200，带 `Referer`]
- 教师侧同构：真实 `bianhao=8971103597745998865562779049286190481381` 返回 200，标题「（张洁）2026-2027-1学期课程安排表」[来源: 实测 `.../jiaoshikb_new.asp?bianhao=8971103597745998865562779049286190481381` 返回 200]
- 但**伪造 `bianhao=1` 时标题带「（加密验证未通过）」**，教室页 `bianhao=1` 直接 500。即：`bianhao` 是带校验的密文式 id，不是序号；合法 id 只能从搜索列表页拿 [来源: 实测 `bianhao=1` 的两种响应]

**语义推论（标注为推论，非事实）**：教室课表与教师课表属于「公开查询资源」，登录闸门只保护 `/xuesheng/**` 下的个人数据；`bianhao` 的「加密验证未通过」是防遍历的签名校验。这对移植有直接价值——这两类查询**不依赖用户会话**，可以作为纯公开能力实现，不需要 CAS。

**另有一组公开的「今日/明日/后日」课表入口**：教室搜索页顶部有一排 `jshi_yk_1.asp` … `jshi_yk_35.asp`（今日 1–5 讲、明日 1–5 讲、后日 1–5 讲）以及 `jshi_new.asp`（全部教室）[来源: 实测 `jshi_new.asp` 页面内的 `class=menu` 链接表]。旧仓**完全没有用到**这组页面。

- `term` / `semester` 的命中**全部是前端展示用的字段名与排序**，不是发给教务的查询参数：例如成绩页按 `item.term` 分组折叠、课表周次按本地 `semesterStartMs` 计算 [来源: @OLD/apps/nongyu-rn-app/src/modules/jiaowu/screens/ScoreScreen.tsx:13-35；@OLD/apps/nongyu-rn-app/src/components/agent/ScoreCard.tsx:11-21；@OLD/apps/nongyu-rn-app/src/modules/course/store/courseUiStore.ts:40]

**课表 URL 只有一个参数 `title_id1=4`，没有学期** [来源: @OLD/packages/nongyu-tool-jiaowu/core/jiaowu/courseInfo.ts:11-12]，`courseInfo.ts` 的函数签名 `getCourseInfo()` **无入参**，注释明确写「获取学生**本学期**的课程安排」[来源: @OLD/packages/nongyu-tool-jiaowu/core/jiaowu/courseInfo.ts:24]。

同理，成绩页 `getScoreInfo()` 也无入参、无查询参数 [来源: @OLD/packages/nongyu-tool-jiaowu/core/jiaowu/scoreInfo.ts:11,20]。

### 2.2 成绩页的「学期」是从哪来的：**表格列，不是下拉筛选**

`extractScoreInfo` 的流程是「扫描所有 `<table>` → 用表头关键字打分选出最像成绩表的那张 → 按表头关键字定位列 → 逐行取值」[来源: @OLD/packages/nongyu-tool-jiaowu/core/extractor/scoreInfoExtractor.ts:55-96]。其中：

- 「学期」是**表头关键字之一**：`headerKeywords` 数组里就有 `"学期"`，用于给表格打分 [来源: @OLD/packages/nongyu-tool-jiaowu/core/extractor/scoreInfoExtractor.ts:101-110]
- 列定位：`term: findIdx(["学年学期", "学期", "学年"])` [来源: @OLD/packages/nongyu-tool-jiaowu/core/extractor/scoreInfoExtractor.ts:145]
- 取值：`term: pickCell(row, cols.term)` —— 直接从**每一行的那个单元格**读 [来源: @OLD/packages/nongyu-tool-jiaowu/core/extractor/scoreInfoExtractor.ts:71-78]
- 有效行判定只要「课程名 + 成绩」两项 [来源: @OLD/packages/nongyu-tool-jiaowu/core/extractor/scoreInfoExtractor.ts:84]

即：**成绩页一次性返回该生全部成绩，每行自带「学年学期」文本；学期是数据列，不是请求参数，也不是下拉框筛选**。整个 `core/jiaowu/` 里唯一的 POST 只出现在登录模块（`post(LOGIN_ENDPOINT, ...)` 与 `cas.ts` 的换票 POST）[来源: @OLD/packages/nongyu-tool-jiaowu/core/login/index.ts:324；@OLD/packages/nongyu-tool-jiaowu/core/login/cas.ts:534,614,657,758]，**没有任何业务查询走 POST 筛选**。

> 注意：这个结论的力度是「旧仓实现里没有，且其解析逻辑证明学期来自表格列」。至于成绩页**页面上是否另有未登录不可见的学期下拉框**，见「尚未查清」。

### 2.3 教师/教室课表的「学期」也是从标题文本正则抠出来的

学期不是请求参数，而是从页面标题字符串里用正则抓的：

- 教室：`/四川农业大学\s*(\d{4}-\d{4}-\d)\s*课程表/` [来源: @OLD/packages/nongyu-tool-jiaowu/core/extractor/classroomCourseInfoExtractor.ts:95-97]
- 教师：`/[（(]([^）)]+)[）)]\s*(\d{4}-\d{4}-\d)\s*(?:学期)?\s*课程/`，备选 `四川农业大学\s*(\d{4}-\d{4}-\d)` [来源: @OLD/packages/nongyu-tool-jiaowu/core/extractor/teacherCourseInfoExtractor.ts:96-104]

实测验证了这条正则的真实输入：教室页标题是「四川农业大学课程表(10-A104)」——**注意此标题里没有学期**，故教室课表的 `semester` 字段实测情况下会是空串；教师页标题是「（张洁）2026-2027-1学期课程安排表」，正则能命中 [来源: 实测两个页面正文]。

**两者返回的都是「当前学期」**：实测日期 2026-11-10，两页都显示 `2026-2027-1`，与「当前学期」一致。

### 2.4 实测：加学期参数不改变任何行为（但这一条证据力很弱）

对下列 URL 加了 `xnxqh=` / `xq=` 参数：

```
.../xuesheng/gongxuan/gongxuan/kbbanji.asp?title_id1=4&xnxqh=2024-2025-1   → 302
.../xuesheng/chengji/chengji/sear_ch_all.asp?xnxqh=2024-2025-1              → 302
.../xuesheng/chengji/chengji/sear_ch_all.asp?xq=2                           → 302
```

[来源: 实测三个 URL 均返回 302 `Location: ../../../jiaoshi/bangong/index.asp`]

**但这三条不能证明任何事**：未登录时闸门在参数被读取之前就触发了，响应与不带参数时逐字节相同（都是 132 字节跳转页）。因此「加参数无效」这个结论**不成立也不被反驳**——正确说法是「未登录态无法观测学期参数是否生效」。

### 2.5 一个被忽略的事实：`title_id1` 是**菜单 id**，不是学期

`title_id1` 在旧仓出现 5 处，取值分别是 `01`（考试）、`1`（进度、培养方案）、`2`（教师信息、开课目录）、`4`（课表），且**同一个文件名在不同 `title_id1` 下被复用**（`kai.asp?title_id1=2` vs `kai.asp` 无参）[来源: @OLD/packages/nongyu-tool-jiaowu/core/extractor/kaikeInfoExtractor.ts:114 与 core/jiaowu/kaikeInfo.ts:15]。这符合川农教务 ASP 老系统的「`title_id1` = 左侧菜单项编号」惯例（**此惯例为推测，未取得一手菜单页佐证**，因为菜单页需登录）。

补充证据：`planInfo.ts` 里那个超长固定参数串（`selw` / `sel1w` / `o` / `dizhi` / `w1` / `rul` / `wid` / `rig` / `bh` 等）明显是**页面内嵌表单的隐藏域快照**——它们不像人工设计参数，更像「把页面上的隐藏 input 原样带上」[来源: @OLD/packages/nongyu-tool-jiaowu/core/jiaowu/planInfo.ts:19]。这类隐藏域里**通常**才藏着真正的查询条件，但**该串里没有学期的字样**，均为无意义数字/时间戳形态，故无法从此推断学期字段名。

### 2.6 结论：支持 `?term=` 指定学期可不可行

**在无真实账号的前提下，不能声称可行。** 具体分三层：

1. **旧仓证据明确指向「不支持」**：课表 URL 无学期参数、函数无入参、注释写死「本学期」；学期在成绩页是数据列而非查询条件 [来源: 见 2.1、2.2]。
2. **实测无法证否也无法证真**：未登录闸门吞掉一切参数差异 [来源: 见 2.4]。
3. **唯一还没排除的可能**：教务课表页 `kbbanji.asp` 在**登录后的页面上**可能存在一个学期下拉框（`<select name=...>` + 提交按钮），旧仓因为只抓本学期而从没去解析它。这一点**必须用真实账号登录后看页面 HTML 才能定论**。

因此对 Go 后端的移植建议是：**接口先按「只查本学期」实现，但把学期参数留在 handler 签名里当占位**；等有人能用真账号看到 `kbbanji.asp` 的完整 HTML 时，再决定是拼 query 还是 POST 表单。

## 三、数据字段与 HTML 结构特征

### 3.1 课表 `courseInfoExtractor`（`kbbanji.asp?title_id1=4`）

**结构识别方式（不依赖 table class / tr class）**：

1. 用非贪婪正则 `/<table[\s\S]*?<\/table>/gi` 抓出所有表格片段，**不**用 `extractSegments`（代码注释说明这是为了绕开深度嵌套问题）[来源: @OLD/packages/nongyu-tool-jiaowu/core/extractor/courseInfoExtractor.ts:59-62]
2. 按**表格 HTML 长度降序**排序，`parseTable` 后过滤掉行数 < 2 的 [来源: @OLD/packages/nongyu-tool-jiaowu/core/extractor/courseInfoExtractor.ts:63-66]
3. 表头行 = 第一个「有任意非空单元格」的行；**若该表没有「课程名称」列则跳过整张表** [来源: @OLD/packages/nongyu-tool-jiaowu/core/extractor/courseInfoExtractor.ts:69-73]
4. 从表头行的**下一行**开始逐行取数，**只保留 `courseName` 非空的行** [来源: @OLD/packages/nongyu-tool-jiaowu/core/extractor/courseInfoExtractor.ts:78-100]
5. 取第一张有结果的表就返回 [来源: @OLD/packages/nongyu-tool-jiaowu/core/extractor/courseInfoExtractor.ts:102-104]

> **无任何 class 依赖**：既没有 `table.datagrid` 也没有 `tr.xxx`，全靠表头文字。这点与 `bjiben.asp` 不同（后者的 Go 解析器依赖 `table.tablebody` + `tr.g_column` + `tr.g_body_2`）[来源: @NEW/internal/school/schoolauth/academic.go:5-12,55-60]。

**表头规范化**：去空白符 → 去中英文冒号 → 转小写，然后用「关键字**包含**」做 `findIndex` 定位列 [来源: @OLD/packages/nongyu-tool-jiaowu/core/extractor/courseInfoExtractor.ts:114-117]。

### 3.2 成绩 `scoreInfoExtractor`（`sear_ch_all.asp`）

**结构识别方式**：

1. 用 `extractSegments(html, "table")` 抓表格（注意：与课表不同，**这里用的是深度配对的 `extractSegments`**，处理嵌套）[来源: @OLD/packages/nongyu-tool-jiaowu/core/extractor/scoreInfoExtractor.ts:100；实现见 @OLD/packages/nongyu-tool-jiaowu/core/utils/html.ts:71-95]
2. 对每张表，用表头**关键字打分**：`["课程","成绩","学分","绩点","学期","课程性质","成绩来源","成绩说明"]`，命中一个 +1，取**得分最高且 > 0** 的那张 [来源: @OLD/packages/nongyu-tool-jiaowu/core/extractor/scoreInfoExtractor.ts:101-130]
3. 表头行 = 第一个有非空单元格的行；数据从下一行开始 [来源: @OLD/packages/nongyu-tool-jiaowu/core/extractor/scoreInfoExtractor.ts:60-70]
4. **有效行 = `courseName` 与 `score` 同时非空** [来源: @OLD/packages/nongyu-tool-jiaowu/core/extractor/scoreInfoExtractor.ts:84]

**字段表（8 个字段）**：

| 字段 | 中文表头关键字 | 原样文本 / 归一化 |
| --- | --- | --- |
| `courseName` | `课程名称` / `课程名` / `课程` | 原样文本 |
| `score` | `成绩` / `总评成绩` / `最终成绩` | **原样文本**——可能是数字串，也可能是「优秀」「合格」等等第文本，代码注释明说 [来源: scoreInfoExtractor.ts:16] |
| `credit` | `学分` | 原样文本 |
| `gradePoint` | `绩点` | 原样文本 |
| `term` | `学年学期` / `学期` / `学年` | 原样文本（`2023-2024-1`），**未转成结构化学年/学期号** |
| `courseType` | `课程性质` / `性质` | 原样文本（`必修`） |
| `source` | `成绩来源` / `来源` | 原样文本（`初修`、`补考`） |
| `note` | `成绩说明` / `说明` | 原样文本 |

[来源: @OLD/packages/nongyu-tool-jiaowu/core/extractor/scoreInfoExtractor.ts:11-19,137-152]

同样**全部原样文本**，`pickCell` 只 trim [来源: @OLD/packages/nongyu-tool-jiaowu/core/extractor/scoreInfoExtractor.ts:162-165]。

**两个已知脆弱点（移植时别照抄）**：

1. **关键字 `课程` 会同时命中「课程名称」和「课程性质」**：`findIdx` 用 `keywords.some(k => h.includes(k))` + `findIndex`，取的是**第一个**命中的列。若表头顺序变成「课程性质」在前，`courseName` 就会指错列。知识库已记录同类坑（「新专业」也包含「专业」，必须让更长的表头优先）。
2. **`findScoreTable` 在 `score > maxScore && score > 0` 时才替换**，若首张表得分最高但为 0 则返回 null；但当两张表得分相同时**保留先出现的**，不区分是「成绩表」还是「统计表」[来源: @OLD/packages/nongyu-tool-jiaowu/core/extractor/scoreInfoExtractor.ts:124-127]。

### 3.3 关键传输层事实（影响移植）

- 页面是 **GBK**，请求层统一 `decodeGbk`（axios `responseType: arraybuffer`）[来源: @OLD/packages/nongyu-tool-jiaowu/core/utils/request.ts:186-194；@OLD/packages/nongyu-tool-jiaowu/core/utils/decode.ts:36-38]
- **Referer 被自动设成请求自身的 URL**（注释：ASP 系统以此做安全校验）[来源: @OLD/packages/nongyu-tool-jiaowu/core/utils/request.ts:66-69]
- 中文查询参数（教师名）必须用 **GBK URL 编码**，不是 UTF-8：`encodeGbkUrl('蒲海波') === '%C6%D1%BA%A3%B2%A8'` [来源: @OLD/packages/nongyu-tool-jiaowu/core/utils/decode.ts:44-57]
- 会话 Cookie 只认 `ASPSESSIONID*` [来源: @OLD/packages/nongyu-tool-jiaowu/core/utils/cookie.ts:9]
- 新仓出站闸口**不跟随重定向**（`ErrUseLastResponse`），因为教务是「三跳建会话」[来源: @NEW/internal/platform/outbound.go:90-96]，本次实测的 302 形态与之吻合，Go 侧必须自己处理跳转

## 四、尚未查清

按重要性排序，全部是「需要真实学校账号」或「需要更多一手页面」才能闭合的：

1. **学期参数的真实形态（最重要）**：`kbbanji.asp` 登录后的完整 HTML 里，是否存在学期下拉框（`<select>`）或学期隐藏域？若存在，它的参数名是什么、是 GET 还是 POST？旧仓零痕迹、未登录零可观测，**当前无法回答**。成绩页 `sear_ch_all.asp` 是否存在未登录不可见的学期筛选表单，同样未知。→ 需要：一次真实登录后的页面 HTML 抓取（`curl -b <cookie>` 或浏览器保存页面）。
2. **`/xuesheng/` 学生端左侧功能菜单的完整条目**：需要登录才能读到，因此「教务侧真实存在但旧仓没涉及的功能页」可能还有若干（例如选课、学籍异动、教学评价等）。当前清单**只覆盖旧仓涉及的 14 个模块**，不代表教务全部学生端功能。
3. **`title_id1` 的确切语义**：推测是左侧菜单项编号（`01`=考试、`1`=进度/培养方案、`2`=教师信息/开课、`4`=课表），但**没有一手菜单页佐证**。同一文件名 `kai.asp` 在不同上下文用不同 `title_id1` 这一点也未能解释。
4. **`kbbanji.asp` 表格的真实表头文字顺序**：3.1 的 14 个关键字是从代码推断的，**未见过真实表格 HTML**（未登录 302）。若真实表头与关键字对不上（比如写「任课老师」而非「任课教师」），`teacher` 会取到空串而不会报错——这类静默失败只有真数据能暴露。
5. **`kai.asp` 的 `KAIKE_PARAMS` 是死代码**：定义了 `{y:1, ww_f:""}` 但从未参与 URL 拼接 [来源: @OLD/packages/nongyu-tool-jiaowu/core/jiaowu/kaikeInfo.ts:20-23]，且 `kaikeInfoExtractor.ts:114` 里另有一个带 `title_id1=2` 的常量。两个常量谁是对的、开课目录到底要不要分页，**未查清**。
6. **`jshi_yk_*.asp` 那 15 个「今日/明日/后日 N 讲」页面的参数与返回结构**：只确认链接存在，未抓取内容。
7. **教室课表标题是否真的没有学期**：实测标题是「四川农业大学课程表(10-A104)」，按旧仓正则 `semester` 会是空串；但这是**一个教室**的样本，不能排除别的页面形态。旧仓 JSDoc 示例里 `semester` 是 `'2025-2026-2'`，与实测矛盾 [来源: @OLD/packages/nongyu-tool-jiaowu/core/jiaowu/classroomCourseInfo.ts:88 vs 实测]。**该字段的真实可靠性存疑**。
8. **`/xuesheng/` 目录为什么是 403 而不是 302**：IIS 层面禁止目录浏览，但同目录的具体 `.asp` 是 302。不影响结论，但说明闸门有两层（IIS + ASP）。

## 附：给移植的一句话小结

学生端 9 个需登录页面（课表/成绩/考试/进度/培养方案/排名/学籍/教师信息/开课目录）URL 与参数已在 1.1 表格固化，**未登录一律 302 → `jiaoshi/bangong/index.asp` → 200 + JS alert，判失效必须看正文**；教室与教师课表是**免登录的公开查询**，可直接移植；**学期在旧仓全是「当前学期」，无法按 `?term=` 指定**，此事须真账号验证后才能定。
