## 0. 一句话方案

**客户端完成一次统一登录，拿到 `go-admin-tgt` 交给后端；后端用这一张 tgt 换出 xsgz access token，再经 `checkUserAndGetUserLevel` → `enterHall` → `student/detail` 取到 13 组学生档案。这就是唯一数据源，别再从教务掰扯。**

```
客户端（一次登录，拿到 tgt）
   └─→ 后端：go-admin-tgt
          ├─① auth /api/v1/cas/login?appid=ywtb   → st + userId
          ├─② xsgz /gateway/xg-agg-pc/cas/login   → access token (608 字符)
          ├─③ user/checkUserAndGetUserLevel       → levelNo / unitNo / unitType
          ├─④ user/enterHall                      ★ 缺这步 detail 必 500
          └─⑤ student/detail/<学号>                 → 13 组档案（含 18 位身份证）
                 └─→ 落库 4 张表
```

## 1. 凭据：go-admin-tgt

**【实测】唯一需要客户端交的东西就这一张。**

| 项 | 事实 |
| --- | --- |
| cookie 名 | `go-admin-tgt`（**不是**标准 CAS 的 `TGC`，按 TGC 猜会一路走错） |
| 值形态 | `201690:TGT:<base64url>`，约 55–60 字符 |
| 有效期 | 10 天（`Max-Age=864000`） |
| 属性 | HttpOnly —— 页面 JS 的 `document.cookie` 读不到，必须从 `Set-Cookie` 头取 |
| 存储 | 加密后按 userID 存 Redis，TTL 取 9 天（比服务端 10 天留 1 天余量） |

### 1.1 单枚 tgt 够不够？

**够。【代码 + 实测】** 生产路径 `internal/school/xsgz/fetch.go:48` 就是只设一枚：

```go
req.Header.Set("Cookie", goAdminTgtCookie+"="+strings.TrimSpace(tgt))
```

这条链路端到端跑通，取到 token(608) 与 13 组档案。

> **重要更正**：2026-11-09 曾有「单枚 tgt 不行、必须整套同域 cookie」的结论，**已推翻**。那次失败的真正原因不是 cookie 集合不足，而是**拿到的是 302 重定向的 HTML 而不是 tgt 值**（`<a href="https://webvpn.sicau.edu.cn/login">Found</a>.`）。整套 cookie 属于「更保险但非必要」，代码里 `TGTBundle` 仍保留 `CookieHeader` 字段用于续期，但 `FetchToken` 不依赖它。

### 1.2 必须校验 tgt 形态（血泪教训）

**【实测】** 客户端若把一次 HTTP 响应的 body 当 cookie 值交上来，后端不校验就会把它加密存进 Redis，之后**每次换票都 500「未登录」**，表现为「能登录、有姓名、画像其他字段全空」，而日志里零线索。

```go
// 合法 tgt：可见 ASCII、含 ':'、无尖括号/引号/空白、长度 8..512
func looksLikeTGT(s string) bool {
    if len(s) < 8 || len(s) > 512 { return false }
    if !strings.Contains(s, ":") { return false }
    for _, r := range s {
        if r < 0x21 || r > 0x7e { return false }
        switch r {
        case '<', '>', '"', '\'', '\\', ' ': return false
        }
    }
    return true
}
```

落点：`internal/school/schoolauth/tgt.go` 的 `TGTManager.Save` 入口。

## 2. 换票链路（后端全权，客户端零参与）

### ① tgt → st + userId

```
GET https://auth.sicau.edu.cn/api/v1/cas/login?appid=ywtb
Cookie: go-admin-tgt=<tgt>
```

响应信封 `{code:200, data:<base64密文>, requestId}`，解密 `data` 得：

```json
{"st":"ST:...", "users":[{"id":201690}], "callbackUrl":"..."}
```

**解密算法**（`schoolauth.DecryptYWTB`）：

```
key      = MD5(requestId + ":sicau-cas") 的 hex 再转 16 字节二进制
raw      = base64decode(data)
iv       = raw[:16]        ← 前 16 字节是 IV，不是密文
ct       = raw[16:]
plain    = AES-128-CBC(NoPadding) 解密后按末字节 N 去掉尾部 N 字节
```

> ⚠️ 用错 IV 会解出满屏乱码，容易误判「平台改了加密」。结果是裸 JSON 或带引号的 JSON 字符串字面量，两种都要能处理。

### ② st:userId → xsgz access token

```
POST https://xsgz.sicau.edu.cn/gateway/xg-agg-pc/cas/login
Content-Type: application/x-www-form-urlencoded
H-Zove-Source: 20100
H-Zove-ClientType: PC          ★ 漏了报「客户端类型不能够为空」
H-Zove-TenantId: XG
H-Zove-AppKey: zovecenter-saip-xg-agg-pc

ticket=<st>:<users[0].id>      ★ 不是学号，是 CAS 用户 ID
```

→ `{code:"0", data:{token:"<608 字符>"}}`

### ③ 拿 level / unit

```
POST .../user/checkUserAndGetUserLevel
H-Zove-Token: <token> + 主应用那套头（Source:20100 / agg-pc appkey）
```
→ `{data:{loginLevels:[{levelNo:"XS", units:[{unitType:2, unitNo:"419"}]}]}}`

### ④ enterHall ★★★ 决定性一步

```
POST .../user/enterHall
body: {"departNo":"419","userStateLevel":"XS","userType":2,"accessSource":"30100"}
```

body 的 `departNo`/`userStateLevel`/`userType` **必须用 ③ 返回的真实值**，`accessSource` 固定 `"30100"`。

> **这是整条链路最容易漏的一步。** 拿到 token 直接打 detail 必 500「验证权限异常」；同一个 token 走完 enterHall 立刻 200。曾误判为「服务端反爬 / TLS 指纹识别」，用 uTLS 伪装 Chrome 白费一轮功夫——**与客户端环境完全无关**，纯 curl 也能通。

### ⑤ 取 13 组档案

```
GET https://xsgz.sicau.edu.cn/gateway/zovecenter-saip-xg-app-student/student/detail/<学号>
H-Zove-Token: <同一个 token>
H-Zove-Source: 20000                              ★ 子应用是 20000，不是 20100
H-Zove-TenantId: XG
H-Zove-AppKey: zovecenter-saip-xg-app-student    ★ 不是 agg-pc
H-Zove-UserLevel: XS                              ★ 缺了 403
```

→ 200，约 7.9 KB，13 组。

> **网关/appkey 两套不能混**：登录类走 `/gateway/xg-agg-pc` + `...-agg-pc` + Source 20100；detail 走 `/gateway/zovecenter-saip-xg-app-student` + `...-app-student` + Source 20000。

## 3. 13 组档案与字段

`baseDto`（**含 18 位完整身份证**）、`studentStatusDto`、`personalInfoDto`、`contactInfoDto`、`emergencyContactInfoDto`、`examDto`、`familyDto`、`economyDto`、`workUnitDto`、`familyMemberList`、`sociologyMemberList`、`resumeList`、`age`。

可得字段：学号、姓名、性别、学院、专业、班级、年级、**身份证 18 位**、生日、年龄、宿舍、校区、手机、邮箱、家庭地址、紧急联系人、考生号、教育经历、家庭成员、经济情况。

### 3.1 身份证的真相

| 入口 | 身份证 |
| --- | --- |
| ywtb 个人信息页 | 掩码 `650****2614`（前 3 + **** + 后 4） |
| **xsgz student/detail** | **完整 18 位** |

> **更正**：曾有「完整号拿不到、只存后四位」的结论，**已推翻**——那是只看 ywtb 一页就外推了。
>
> **现实现**：完整号 AES 加密存 `student_profiles.id_card_sealed`（bytea），另存后四位 `id_card_suffix4` 供展示。明文绝不落库、不进日志。

### 3.2 token 结构（避免误判）

608 位 hex = 304 字节，四段：`[身份段 0-255][会话段 256-351][固定段 352-479][签名段 480-607]`。

两次换出的后 352 位不同是**正常的**（会话段随登录变），不要误判成「签名错误」。

## 5. 8 个校内站点的真实性质

**【实测】「认证层全通」≠「业务数据可取」。** 同一张 tgt 对 8 个站名都返回 `cascallback=choose`，但：

| 站点 | 性质 | 个人数据 |
| --- | --- | --- |
| **jiaowu 教务** | CAS 换票（appid `b54a2f27-…`） | 有 |
| **ywtb 一网通办** | **自有 Bearer**（`用户ID\|随机串` + laravel_session），不认 tgt | 有 |
| **xsgz 学工** | SSO 网关 | 有（13 组最全） |
| xsc 学工部 | 资讯门户 | 无 |
| zjc 招就处 | 资讯门户 | 无 |
| cwc 财务 | 需额外授权，首页即「没有访问当前栏目的权限」 | 无 |
| lib 图书馆 | 资讯门户；opac 子系统是独立账密体系 | opac 有但不认统一认证 |
| webvpn | 网关（`aea49a21-…`） | 不提供数据 |
| ecology | 可达 200 | 未发现统一认证取数入口 |

**换票能力不能跨 appid 外推。** 教务 appid 通过 ≠ 门户 appid 可用。`GET /api/v1/captcha?appid=X` 返回 200 只证明「该 appid 已注册」，不证明免密换票可行。

## 6. tgt 定时续期

- 每 5 分钟扫一轮，挑「即将过期」的候选换票；周期观测驱动（从成功/失败时刻反推，初始 9 天，失败减半收敛到 1 小时下界）。
- **16 槽位错峰 + 随机抖动**：`slotGap 2s` + `jitter 0–3s`，避免 TPS 尖峰与机器换票检测。
- 失败减半周期、不刷屏重试。
- 遗留：`SetTrustedProxies` 未配置，上反向代理后登录 IP 记成代理地址。

## 7. 明确不要做的事

| 别做 | 为什么 |
| --- | --- |
| 用 `serviceValidate` / `proxyValidate` + TGT 验证 | 这是自研 JSON 平台，不是标准 CAS；标准端点走不通，但不能据此说「不支持」 |
| 拿教务 appid 的成功外推到其他站点 | 换票以 appid 为发放维度 |
| 给 curl 补 TLS 指纹（uTLS）、强制 HTTP/2 | detail 500 的根因是漏了 enterHall，与客户端环境无关 |
| 把 detail 的网关/appkey（Source 20000）用在登录端点上 | 两套网关混用必失败 |
| 只取 `go-admin-tgt` 的**值**却不校验形态 | 会把 302 HTML 存成 tgt，导致「能登录但画像全空」且日志无痕 |
| 把「降级可继续」当理由静默吞错 | 取数失败必须有 onError 出口，否则排障全靠猜 |
| 期望 xsgz access token 长期复用 | 每次现换；只有 tgt 是长期凭据 |

## 10. 验证基线

真实 tgt 端到端（拆包后复跑）：
`tgt → token(len=608) → 档案(学号 202502204 / 姓名 / 分组 13) → 落库(分组 13 / 家庭成员 2 / 教育经历 3)`

对照实验：同一 token 直接 detail → 500；enterHall 200；再 detail → 200 / 7875 字节。
纯 curl（非浏览器、无 uTLS、无 cookie）用真实 token 也返回 200 —— 证明与客户端环境无关。
