## 实证结论（逐条对应此前的 fog / 推测）

### 1. 课表表头用「任课教师」，不是「任课老师」

**确认 #31 的推测正确。** 实测出现：`课程名称`、`上课时间`、`周次`、`任课教师`、`选课方式`、`学分`。
→ `courseInfoExtractor` 的关键字表 `任课教师` 可用；**不要改成「老师」**。

### 2. 课表页**没有学期下拉框**（`<select>` 为 0 个）

推翻 fog 里「学期参数待 #33 确认」的假设：
- 页面里学期信息是**纯文本展示**：「当前学期状态：2026-2027-…」「四川农业大学2026-2027-1学期课程表」。
- 换学期靠一个 **title="点击更改学期设置"** 的链接（带一长串数字 id），不是 `<select>`。
→ **`?term=` 参数不存在，课表只给「当前学期」**。#32 Q1「缓存键不带学期」的决定因此正确。
→ 若要历史学期，需另走该链接的页面，属新功能，不在本图范围。

### 3. 成绩页**没有分页**

`下一页` / `page` / `共N页` 全部 0 命中 → 一次请求返回全部成绩。
→ fog 里「成绩分页待确认」可关闭。

### 4. 成绩表头实测

`最终成绩`（不是「总评成绩」）、`学分`、`绩点`、`课程性质`、`成绩来源`、`成绩说明`。
→ 注意 `最终成绩` 命中 4 次而 `成绩` 15 次，说明列名含「最终成绩」组合词，`scoreInfoExtractor` 的关键字优先级 `成绩 → 总评成绩 → 最终成绩` 应把 `最终成绩` 提到更前，否则会被 `成绩` 先命中导致取错列。

### 5. 排名页表头

`加权`（6 次）、`排名`（7 次）、`专业`、`年级`、`班级`、`学号`、`姓名`。
→ 与 `rankInfoExtractor` 的 `["排名","加权","学号","姓名","专业","年级"]` 打分选表逻辑吻合。

### 6. 考试页表头

`考试时间`（2 次）、`考场`、`座位`。
→ 比 #31 记录的字段多了 **`考场` / `座位`** 两个列；`examInfoExtractor` 的契约里没有这两列，**属新增字段，需补进 #41 的 schema 或明确裁剪**。

### 7. 进度页表头

`学分`、`已修`、`必修`、`选修`、`要求`。
→ 与 `progressInfoExtractor` 的学分统计语义吻合。

### 8. 学籍页字段

`姓名`、`学号`、`专业`、`班级`、`年级`、`学院`、`性别`。
→ 与 `personalInfoExtractor` 的映射一致。

## 采集方法（可复现）

1. 取验证码：`GET https://auth.sicau.edu.cn/api/v1/captcha?appid=<webvpn appid>` → 用仓内 `schoolauth.DecryptYWTB(requestId, data)` 解密。
   **解密产物是 JSON 字符串包裹的 data URI**（`"data:image/png;base64,..."`），要先剥引号再 base64 解码。
2. 登录：`POST /api/v1/cas/login`，JSON `{appid, code, number, password, uuid}`；成功响应带 `go-admin-tgt`。
   **必须保留整套 cookie**，只带 tgt 换票会失败。
3. 拓页：`schoolauth.NewJiaowuSource(...).FetchPage(ctx, Credential{RawCookie: 整套cookie}, path)`。
   它内部完成：换票 → 三跳建会话 → 取页面。**不要手写 curl 走三跳**。
4. 探针的出站闸口要显式登记白名单：`platform.NewRealHTTPDoer(platform.RealHTTPDoerOptions{AllowedHosts: []string{"auth.sicau.edu.cn","jiaowu.sicau.edu.cn"}})`；
   否则报 `platform: outbound target denied`。
5. 页面是 **GBK**，落盘前用 `iconv -f GBK -t UTF-8` 转码。

## 一个坑（踩过）

验证码**一次性**：取一张新图会换 `uuid`，之前那张立即作废。因此「取码 → 看图 → 登录」必须连着做完，中间不能重新取码。
