### 2. 分层倒置根除

**问题**：`internal/platform/pgstore` 反向 import 了 content / message / skin / track / school 五个业务域——最底层依赖最上层。

**修法**：按域拆进各域 `store/` 子包，`pgstore` 整体删除。

```
platform/pgstore/announcement*.go  →  content/announcement/store/
platform/pgstore/post*.go          →  content/post/store/
platform/pgstore/message*.go       →  message/store/
platform/pgstore/skin*.go          →  skin/store/
platform/pgstore/track*.go         →  track/store/
platform/pgstore/fetchaccount*.go  →  school/jiaowu/store/
```

后续补完最后一块（11-19）：**身份仓储也归位到 `identity/store/`**。
原先 `PGIdentityStore` 留在 `platform/pg/`，是唯一没进 `<域>/store/` 的域。
搬迁的前置障碍是 `platform/pg/testschema.go` 用它建测试 schema——把该连接改成直接的
`*pgxpool.Pool`、DDL 辅助从方法改成独立函数后，障碍消除。

**这里刻意没有用别名转发**（其它下沉都用了）：转发会让 `platform` 反向依赖 `identity`，
正是守卫 `TestPlatformNeverImportsBusinessDomains` 要禁止的。8 处调用方直接改用
`identitystore.NewPGIdentityStore(...)`。设计取舍见 §五。

### 3. platform 按技术能力合并

原本 49 个文件全挤在根。按能力划分：

- `platform/model/` —— **零依赖叶子包**：共享值类型（User/Session/TicketRef）+ 哨兵错误
- `platform/pg/` —— 迁移、测试 schema、DDL 工具（**身份仓储已迁出**）
- `platform/redis/` —— 票据存储、会话热副本、连接选项
- `platform/cache/` —— 通用缓存、熔断、幂等锁
- `platform/mail/` —— 邮件、验证码、审计落库
- `platform/objectstore/` —— MinIO 实现
- 根（9 个文件）—— 契约接口、类型别名转发层、cipher/clock/http_doer/mock

**关键技术点**：根要做 `type RedisCache = cache.RedisCache` 之类转发，但不能 import 子包后子包又 import 根（成环）。解法是把共享类型下沉到零依赖的 `model/` 叶子包，子包只 import model，根 import 子包。

### 4. app 分层

- `app/bridge/` —— 5 个跨域适配器（教务会话桥、学校认证桥、网关票存储、帖子缓存、登录失败计数）
- `app/httpserver/` —— HTTP 外壳（超时配置、/status 观测、请求签名接线）
- 根（11 个）—— 只剩 `assemble*`、`repos*`、`app.go`、wiring

包名用 `httpserver` 而非 `http`：后者与标准库 `net/http` 撞名。

## 三、修掉的真实缺陷（均有实证）

### 1. 迁移漏同步 + 守卫盲区（P0）

`migrations/0008` 的 `jiaowu_fetch_accounts` 在**三处**手写清单里缺失：
- `testschema_ddl.go` 的 DDL 副本
- `internal/platform/migrate_test.go` 的 `migrationTables`
- `internal/app/app_migrate_test.go` 的 `migrationTables`

而 200 行的 DDL 一致性守卫**一直是绿的**——因为它按 `information_schema.columns` 逐列比对，整张表缺失时零列可比，结果相等。

**修法**：补齐三处 + 给守卫加「表名集合必须相等」断言（放在列比对之前）。
**验证**：临时注释掉 `skin_current` → 守卫报红；恢复 → 变绿。

### 2. `IsNotFound` 静默失效

原实现用裸类型断言 `err.(*notFoundError)`，任何 `fmt.Errorf("...: %w", err)` 包装都会让它失效。而平台层到处在用 `%w` 包装。改为 `errors.As`。

### 3. `caps_mock.go` 命名陷阱

文件名带 `mock`，实际装着**生产级 AES-256-GCM**（`MockCipher` = `AESCipher`）。且 `MockHTTPDoer` 在 `HTTPEnforce=false` 时是运行期实现，而它**没有 SSRF 防护**。

**修法**：拆出 `cipher.go` / `clock.go` 并显著标注命名陷阱与安全边界。

## 四、自动化守卫（防回退）

`internal/architecture/architecture_test.go` 四条：

1. `TestPlatformNeverImportsBusinessDomains` —— platform 不得 import 任何业务域
2. `TestDomainRootsNeverImportTheirOwnStoreOrAPI` —— 域根不得反向依赖自己的 store/api
3. `TestOnlyAppImportsApp` —— 业务域不得 import 装配层
4. `TestNoImportsOfRemovedPackages` —— 已删除的包（pgstore/pgx/pgutil/redisconn）不许复活

第 4 条做过回归实验：注入旧 import → 报红；移除 → 变绿。

## 五、明确「不做」的事项及理由

| 事项 | 理由 |
| --- | --- |
| `schoolauth` 按协议拆 CAS/TGT/ywtb/教务 | **实测确认双向耦合**：`jiaowu.go` 用 `TGTManager`/`EnsureFresh`，`tgt.go` 用 `JiaowuSource`/`ErrTicketRejected`。硬拆产生循环依赖。 |
| 内部测试包（`package xxx`）全改外部测试包 | `secondclass` 13 个内部测试共 2700+ 行，测的是私有实现（缓存键、schema、配方表）。改造需导出符号或重写，风险远大于收益。 |
| `identity.Code` 并入 `apperr` | identity 有 7 个专属错误码（`session_expired`/`bad_credentials` 等），被 `flow/handler.go` 做 HTTP 状态映射，107 处引用。合并会动登录/会话的错误码行为。两者语义不同（领域码 vs 跨域通用码），不是重复实现。 |
| 两条「建教务会话」路径合并 | 经核查**不是冲突**：`schoolauth/jiaowu.go` 走直连教务域、必须跟随 caslogin.asp 跳转拿 ASPSESSIONID；`jiaowu/webvpn.go` 走编码域、不需要任何 cookie。注释已说明差异与不可复用理由。 |
| 给身份仓储在 `platform` 根加别名转发 | **会重新引入分层倒置**：`platform` import `identity/store` 正好是守卫 `TestPlatformNeverImportsBusinessDomains` 禁止的。与 `cache`/`redis` 的下沉不同，那些是「platform 内部子包」，而 identity 是业务域。故 8 处调用方直接改用 `identitystore.Xxx`，不做兼容转发。 |
