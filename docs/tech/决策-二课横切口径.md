> **性质**：wayfinder map [#58](https://github.com/NongyuSystem/nongyu-backend-plus/issues/58) 子票 [决议：横切口径](https://github.com/NongyuSystem/nongyu-backend-plus/issues/63) 的决议产物。

> **事实底座**：本票撰写时**逐行核对了仓内代码**（见每条「依据」），未凭 #46/#51 的转述。

## 〇、先钉两处被改掉的前提

### 前提一：本票原题面的「读类契约 / 写类契约」已不存在

题干写「定『读类契约』与『写类契约』共用的横切口径，让两张契约票能并行」。但 [#69](https://github.com/NongyuSystem/nongyu-backend-plus/issues/69) 已把终点改为「读写都在客户端，后端只做请求配方下发 + 记录」，[#59](https://github.com/NongyuSystem/nongyu-backend-plus/issues/59) 已把范围收敛为「A+B 61 接口」。

**所以本票要统一的对象变了**：#61 与 #62 现在不是「读类 vs 写类」两张不对称的票，而是「**记录语义**」与「**配方形状**」两张对称的票。横切口径只需覆盖它们**共用**的那一层，不必再操心「读要走代理、写要走直连」的差异——因为**读写都不经后端**。

### 前提二：**`/status` 已不在 publicPaths**（题干与 #51 的旧说法作废）

题干第 3、7 条都说「`publicPaths` 五条与 `/status` 固定 5 字段不动」。**这正是需要更正的地方**：

- 题干引用的「五条」是旧清单：`/healthz`、`/status`、`/identity/login`、`/identity/mailcode`、`/identity/register`。
- **现状（`internal/server/revocable_auth.go:159-164`）只有四条**：`/healthz`、`/identity/login`、`/identity/mailcode`、`/identity/register`。
- **`/status` 已被刻意移出**，代码注释写得很清楚（`:156-159`）：

  > `/status` **刻意不在此清单**：它返回 objectStore/storage/breaker/依赖健康/埋点计数等内部配置，免认证可读等于把基础设施测绘面公开给任意外部调用方。

同理 `IsAppSignExempt`（`internal/server/appsign.go:177-184`）现在**只豁免 `/healthz` 与 `/admin/*`**，`/status` **已不再免签**。

**本票据此更新「不动清单」：不是「publicPaths 五条不动」，而是「publicPaths 现为四条、`/status` 保持免认证也免签的反例不得重开」。** 若照旧口径写进 Spec，会把一个**已经被修掉的安全问题**当成规矩写回去。

## 一、信封归一化

### 二课三套壳 → 本仓一套

| 二课壳 | 形状 | 出现场景 |
| --- | --- | --- |
| `BaseResponse<T>` | `{code:int, message:String, data:T}` | Rx 侧（二课主接口），`code=0` 成功、`code=5` token 失效 |
| `RespVO<T>` | `{code:String, data:T, message:String}` | `retrofit2.Call` 回调式接口 |
| `BaseRespVO` | `{code:String, message:String}`（**无 data**） | 部分写操作 |

### 决定

1. **本仓侧不复制任何二课壳**。二课的响应由**客户端**直接消费——后端根本不转发、不包装。
   本仓只在**自己**的端点（配方下发 + 记录）上使用既有信封：
   - **错误**：`apperr.ErrorResponse{code string, message string}`（`internal/apperr/gin.go:12-19`），camelCase，只出现在错误时。
   - **成功**：**不带 `code` 字段**（`apperr/gin.go:10-11` 明确说明「成功响应不带 code 字段（与既有端点一致）」）。

2. **配方载荷的字段名**：后端自定义（`target`/`address`/`method`/`params`/…），**不照抄二课字段名**。理由：配方是本仓的契约，不是二课响应的镜像；照抄会把二课的三套壳差异漏进本仓。

3. **二课 `data` 里的业务字段**（活动列表、学分等）：**后端完全不接触**。既不解包、不改名、不校验——那是客户端的事。**这一条是 Q1「后端零出站、零数据」的直接推论。**

4. **`code=0/5` 的语义不进入本仓后端**：`code=5` 是**客户端本地错误态**（#69 Q6 已拍板）。后端不会看到它，也就不该在自己的错误码表里给它留位置。

**依据**：`internal/apperr/gin.go:10-19`（信封定义与「成功不带 code」）、#69 决议（后端零出站）、[GLOSSARY.md](<GLOSSARY.md>) 第 ④ 段（请求配方定义）。

## 二、错误码与失败映射

### 两张表（沿用 #39 的做法，但内容要按本 effort 重写）

**表 A：后端 HTTP 码**（只覆盖后端自己会产生的错误）

| 场景 | HTTP | `code` | 说明 |
| --- | --- | --- | --- |
| 逻辑目标名不认识 | 400 | `target_denied` | 沿用既有 `school.CodeTargetDenied` 语义 |
| 未知配方名 / 不支持的 action | 400 | `target_denied` | 与上同码，不给客户端区分内部枚举细节 |
| 缺已认证身份 | 401 | `unauthorized` | 沿用既有 |
| 会话失效 | 401 | `session_expired` | 沿用既有 |
| 限流 | 429 | `rate_limited` | 沿用 `RateLimitMiddleware` |
| 内部错误 | 500 | `internal_error` | `apperr` 兜底，不回显细节 |
| 记录写入失败 | **不报错** | — | 记录是旁路，失败只计数（见 §四） |

**表 B：客户端本地错误态**（后端观测不到，只文档化，不实现）

| 场景 | 判定方 | 客户端动作 |
| --- | --- | --- |
| 二课 `code=5`（token 失效） | **客户端** | 跳 PU 登录，重新取 token |
| 网络不可达 / 超时 | **客户端** | 本地重试策略（本仓不规定） |
| 二课返回其它非 0 | **客户端** | 展示 `message` |
| GPS / 扫码失败的本地原因 | **客户端** | 本地提示 |

**关键决定**：**本仓不为 `code=5` 定义任何错误码**。理由：后端永远看不到二课的响应，定义一个自己永不产生的错误码是纯噪声，还会误导后来的实现者以为后端要处理它。

### 三层不可混（沿用 #35 正名，并按本 effort 补一层）

| 层 | 是什么 | 谁判定 |
| --- | --- | --- |
| **农屿会话失效** | 本仓自己的会话过期/被吊销 | 后端（`session_expired`） |
| **二次票据失效** | `wengine_vpn_ticket*` 失效（WebVPN 语境，本 effort **不涉及**） | — |
| **教务会话失效** | `ASPSESSIONID` 失效（#30 语境，本 effort **不涉及**） | — |
| **PU 平台凭据失效** | `x-access-token` 失效（`code=5`） | **客户端**（本 effort 新增的第四层） |

**依据**：`internal/apperr/gin.go`、`internal/server/auth.go`（限流）、[GLOSSARY.md](<GLOSSARY.md>) 既有「会话」条、#35 正名、#69 Q6。

## 三、鉴权 / 会话作用域

### 决定

1. **本 effort 新增的端点全部需农屿会话**，一个都不进 `publicPaths`。
   理由：配方是「个性化」的（涉及本人能看哪些活动、本人学院的规则），且下发配方本身要记审计（谁问了什么）。没有免登录场景。

2. **不新增 `publicReadablePaths` 条目**。该清单目前只装「公告/帖子列表与详情」这类产品上允许未登录者看的内容；二课数据**全部是本人视角**，不属此类。

3. **`publicPaths` 与 `publicReadablePaths` 都不动**（现为四条 + 内容清单），且**共用同一个 `IsPublicPath`**——沿用既有结构，不新增第三份清单。

4. **`userID` 只从 `CtxUserID` 取**（`internal/school/targets.go:5-8` 契约键），请求体/query 里的 `userID` 一律不生效。本 effort 的配方下发与记录都遵守此条。

5. **`/status` 保持现状：不在 publicPaths、不免签**。见 §〇 前提二。

**依据**：`internal/server/revocable_auth.go:159-164`（publicPaths 四条）、`:167+`（publicReadablePaths）、`internal/school/targets.go:5-8`（CtxUserID）、`internal/server/appsign.go:177-184`（IsAppSignExempt）。

## 四、盲区声明的固定措辞

### 必须写进 Spec 原文的措辞

> **后端对学校二课的全部请求均无观测能力。** 客户端持本人 PU 平台凭据直接向二课平台发起读写请求，这些请求不经过本仓后端；后端既不代发、也不转发、也不缓存其响应。因此：
> - 后端**无法**对这些请求限流；
> - 后端**无法**为它们记审计；
> - 后端**无法**判定其失败原因（含 `code=5` token 失效）。
>
> 任何文档、注释、对外说明**不得声称「所有二课请求均已限流」或「均已审计」**。后端的限流与审计只覆盖**它自己经手的交互**（配方下发、记录），不覆盖客户端直连段。

### 审计口径（只覆盖后端经手的部分）

- **action 命名**：`<域>.<动作>`，本 effort 为 `secondclass.recipe_issue`（配方下发）与 `secondclass.record`（记录写入，若记录走审计表则合并，见 §六）。
- **只记标识性字段**：`userID`、`action`、`target`（逻辑目标名）、`result`（结果码）、`occurredAt`、`requestID`。
- **绝不记**：PU token、GPS 坐标、扫码时间戳、二课响应体、二课业务数据内容。
- **记录写入失败不阻断主流程**（旁路，满则丢弃计数），沿用 `AuditStore` 既有语义（`internal/platform/mail.go:415-428`）。

**依据**：[ADR-0001](<docs/adr/0001-服务端代请求边界由新后端重写.md>) 第 4 条与其 2026-11-16 二课追加节、`internal/platform/mail.go:398-428`（AuditEntry 铁律）。

## 五、NY1 请求签名适用性

### 事实（已核对代码）

`IsAppSignExempt`（`internal/server/appsign.go:177-184`）当前只豁免两类：
- `/healthz`（唯一存活探针，无客户端密钥）
- `/admin/*`（浏览器调用，APK 密钥到不了）

**其余一律要签**——包括登录与发验证码（注释明说「那些是仿造请求的主要目标，必须签」）。

### 决定

| 端点类别 | 是否签 NY1 | 理由 |
| --- | --- | --- |
| 本 effort 的配方下发端点 | **签** | App 调用，符合 ADR-0003 威胁模型；不加豁免 |
| 本 effort 的记录端点（若有） | **签** | 同上 |
| **客户端直连二课那一段** | **与 NY1 无关** | NY1 只证明「请求来自持当前密钥的农屿客户端」；客户端打二课平台时用的是 PU 凭据，本仓没有也不该有任何介入 |

**不新增任何签名豁免**。二课端点走默认路径，`IsAppSignExempt` 不改。

**依据**：`internal/server/appsign.go:161-184`、[ADR-0003](<docs/adr/0003-安卓请求签名.md>)、#46 Q4（`/admin/*` 免签的理由）。

## 六、脱敏铁律落到本 effort

### 禁用清单（一律不得进日志 / 审计 / 埋点 / 错误信息 / 接口响应）

| 项 | 来源 | 说明 |
| --- | --- | --- |
| **PU 平台凭据**（`x-access-token`） | #69 | 后端**根本不持有**，所以更不该出现在任何输出里 |
| **GPS 坐标**（`signupLong`/`signupLat`/`signUpLong`/`signUpLat`） | #59 B 组写操作 | 客户端本地态，配方只给槽位不给值 |
| **扫码时间戳**（`qrCodeTimestamp`/`codeTime`） | #59 B 组签到 | 同上 |
| **二课响应体** | 167;ADR-0001 铁律 | 后端本来也拿不到 |

### 配方**可以**包含的字段（这是「允许出现在参数里」的白名单）

- 逻辑目标名（如 `secondclass`）
- 二课端点路径（注解里的绝对路径，**不含查询串里的个人数据**）
- HTTP 方法（`GET` / `POST`）
- **参数槽位描述**：参数名、是否必填、归属类型（`client_local` / `server_fillable` / `fixed`）
- **不含**：任何参数的实际值

**关键区分**：配方给的是「**槽位**」不是「**值**」。`actId` 作为槽位名是允许的；`actId=12345` 这种带具体值的只在客户端请求里出现，后端不生成、不记录、不下发。

### 特别提醒：三套壳的 `message` 字段

二课的 `Respsonse.message` 可能含上游错误详情。既然后端不转发，这条风险自动消失——**但如果将来有人想「后端代取再返回」，这条会立刻变成泄漏面**。已在 §一 第 3 条封死。

**依据**：[ADR-0001](<docs/adr/0001-服务端代请求边界由新后端重写.md>) 第 3 条与二课追加节、[ADR-0002](<docs/adr/0002-身份仓数据边界.md>)、`internal/platform/mail.go:398-399`。

## 七、不动清单（供 #64 收口时直接引用）

**逐条列出，Spec 必须原样收录：**

1. **`publicPaths` 现为四条**（`/healthz`、`/identity/login`、`/identity/mailcode`、`/identity/register`），本 effort **不增不减**。
2. **`/status` 不在 `publicPaths`、不免 NY1 签名**——它是内部基础设施测绘面，2026-11-16 前的「五条含 /status」说法已作废，**不得按旧口径写回**。
3. **`publicReadablePaths` 不新增条目**（二课数据全是本人视角）。
4. **两份清单共用同一个 `IsPublicPath`**，不新增第三份。
5. **`IsAppSignExempt` 只豁免 `/healthz` 与 `/admin/*`**，本 effort 不加豁免。
6. **不新增限流实现**：沿用 `RateLimitMiddleware`（默认 60/分钟，进程内滑动窗口）。
7. **中间件链顺序不变**：`RequestID → NY1（适用时）→ 鉴权 → AdminOnly（仅 /admin）→ 限流`。
8. **信封不动**：错误用 `apperr.ErrorResponse{code,message}`，**成功不带 `code`**，camelCase。
9. **`CtxUserID` 契约键与「只从上下文取身份」不动**。
10. **审计 `AuditEntry` 六字段不动**，不为其加字段。
11. **`/status` 的 5 个字段（process/postgres/redis/breaker/storage）不增不减**——只是它现在要签名+会话才能读。

## 八、被推翻/更正的三处（留痕）

| 题干原说法 | 实际 | 影响 |
| --- | --- | --- |
| 「定读类与写类契约共用的口径」 | 读写都已经在后端之外，不存在「读走代理 vs 写走直连」的差异 | 本票只需覆盖配方与记录共用层 |
| 「`publicPaths` 五条 + `/status` 不动」 | `publicPaths` **现为四条**，`/status` **已被移出**且不免签 | **照旧口径写入 Spec 会重开一个已修的安全问题** |
| 「`/status` 固定 5 字段不动」作为「不动清单」 | 字段确实没变，但**访问前提变了**（需签名+会话） | 不动清单要写清是「字段不动」而非「访问条件不动」 |
