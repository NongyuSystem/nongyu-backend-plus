## 1. WebVPN 地址解码（用于把抓到的网关地址还原成源地址）

网关地址形态：`https://webvpn.sicau.edu.cn/{scheme}/{KEY_HEX}{host_cipher_hex}{path}?{query}`

- `KEY = IV = "wrdvpnisthebest!"`（16 字节），AES-128-**CFB**
- `KEY_HEX = 77726476706e69737468656265737421`
- 主机名右侧用 `'0'` 填充到 16 字节对齐后加密，密文取前 `len(host)` 字节转小写 hex

本次实测样本（用户提供）：

```
密文段: 77726476706e69737468656265737421fafe409330252643770b88b9d65027203418e0
        └──────── KEY_HEX (16B) ────────┘└────── host cipher (19B) ──────┘
解密结果: jiaowu.sicau.edu.cn  （19 字节，正好 16 字节对齐）
源地址:   https://jiaowu.sicau.edu.cn/xuesheng/pj/pj/index.asp
```

仓库已有**编码**（`internal/school/encode.go`，带单测），**无解码**。
本次解码是一次性排查手段；若要复用，按维护者意见放 `tools/`，**不进后端业务代码**。

## 3. 课程评价列表（`GET index.asp`）

**纯服务端渲染的 HTML 表格，没有独立 JSON API。**

表格列（实测 `thead`）：

| 列 | 含义 |
| --- | --- |
| 序号 | 行号 |
| 学期 | 如 `2026-2027-1` |
| 课程 | 如 `大学物理实验A` |
| 教师 | 如 `张义` |
| 课程性质 | 必修 / 专业方向课 … |
| 开通否 | `已开通`（红字） |
| 评价否 | `未评价`（红字）/ `已评价`（浅蓝） |
| 评价结论 | 已评时可能非空（本次实测全空） |
| 教学建议 | 已评时可能非空（本次实测全空） |
| 评教 | 未评是链接，已评是纯文本「已评价」 |

**关键**：`未评价` 的行才有「我要评教」链接；`已评价` 的行该列是 `<font>已评价</font>` 纯文本，无链接。
因此「哪些还没评」可以只靠页面判断，不需要额外接口。

未评价行的链接形态（实测）：

```
baojia.asp?bh=19164703&jshi=张义&kc=大学物理实验A
```

- `bh` = 课程编号（8 位数字）
- `jshi` = 教师姓名
- `kc` = 课程名

**注意编码**：页面 `charset=gb2312`。实测在浏览器里链接是 UTF-8 展示的，但教务站本身是 GBK 系；
用 HTTP 客户端直接请求时，`jshi` / `kc` 需要按 **GBK** URL 编码（旧底稿 `教务学生端功能与查询参数清单.md:54`
对教师姓名的 GBK 要求有同样记载）。本次通过浏览器访问是浏览器自动处理的，未单独验证裸 GBK 编码的等价性。

## 4. 评教表单页（`GET baojia.asp`）

```
GET /xuesheng/pj/pj/baojia.asp?bh=<课程编号>&jshi=<教师>&kc=<课程>
```

页面是一张 5 行表格 + 提交按钮，`form method="post" action="pjsave.asp"`。

### 4.1 五个评价维度（实测完整文案）

| 字段 | 维度 | 指标内涵（原文摘要） | 选项 |
| --- | --- | --- | --- |
| `pj1` | 授课内容 | 教学内容深浅难易适度，符合学生发展需要；内容充实，理论联系实践，重点难点突出；教材选用符合要求 | 1=A.满意 2=B.基本满意 3=C.不满意 |
| `pj2` | 授课方法 | 教学组织严谨，普通话授课，用语精炼；课件设计合理或配有适当板书；多种教学方法结合，师生互动良好 | 同上 |
| `pj3` | 授课态度 | 遵守教学纪律，按时上下课，不随意调停课；衣着得体，精神饱满；辅导答疑耐心细致，责任心强 | 同上 |
| `pj4` | 课堂管理 | 爱护学生，师生关系良好；对课堂秩序进行有效管理 | 同上 |
| `pj5` | 授课效果 | 基本理论和基础知识清楚，有助于提高学生分析问题和解决问题的能力 | 同上 |

**选项取值是 1/2/3，不是 "A"/"B"/"C"**。语义方向：**1 最好、3 最差**（1=满意）。
这一点很容易搞反——如果按「分越高越好」的直觉映射成 5/3/1，会把「满意」提交成「不满意」。

### 4.2 配套字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `jy1`~`jy5` | textarea | 对应五个维度的「不满意原因或教学建议」，可空 |
| `jshi` | hidden | 教师姓名（回传） |
| `kc` | hidden | 课程名（回传） |
| `bh` | hidden | 课程编号（回传） |
| `cmdok` | submit | 提交按钮（`onclick` 有 `confirm('确定提交嘛？')`） |
| `cmdcancel` | reset | 清除按钮 |

**页面明确要求**：「评价"不满意"需说明理由」。

## 7. 对实现的约束（事实层面，不含方案）

1. **没有 JSON API**：全部是 ASP 页面 + 表单 POST，取数要靠 HTML 解析。
2. **列表与表单都是 GBK 页面**：解析前必须按 GBK 解码，否则中文乱码（旧底稿已踩过这个）。
3. **需要 WebVPN 会话**：校外不可直连（§0）。
4. **评教与其它教务功能的差别**：维护者明确「评教没有缓存」。这与既有 13 类
   （`internal/school/jiaowu/datatype.go` 的 `DataType`）都不同——那些是有 TTL 的读缓存。
5. **提交是有副作用的写操作**：与既有的全部「只读抓取」不同，需要单独考虑
   （幂等、重复提交、失败重试、是否允许客户端触发）。
