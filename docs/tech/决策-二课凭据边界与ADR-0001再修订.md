# 决策：二课凭据边界与 ADR-0001 再修订

> **性质**：wayfinder map [#58](https://github.com/NongyuSystem/nongyu-backend-plus/issues/58) 子票 [决议：ADR-0001 修订与 PU 平台凭据托管边界](https://github.com/NongyuSystem/nongyu-backend-plus/issues/69) 的决议产物。
> **不是实现方案、不产可运行代码**。ADR-0001 的追加节已同步落地（见 §五）。
> **拍板时间**：2026-11-16，六题逐项由维护者回答（Q1 选了与推荐不同的更彻底方案）。

---

## 一、问题

学校二课（PU / 口袋校园 / i川农定制版）要接入新后端。但它的两个 host（`jk.sicau.edu.cn` / `h5.sicau.edu.cn`）与鉴权方式（header `x-access-token`）**都不在 ADR-0001 第 1 条固定白名单**（只有 `jiaowu` / `auth` / `webvpn`），也不在代码内建 `targetHosts` / `outboundAllowlist` 里。ADR-0001 第 4 条还只放行「客户端直连的**只读**请求」，而二课要做的报名、签到是**写操作**。

 boarded 四层冲突（[调研底稿](<docs/tech/调研-学校二课一手契约与新仓接入现状.md>) §一）：

| 冲突层 | 内容 |
| --- | --- |
| 目标集合 | jk / h5 不在白名单 |
| 凭据类型 | `x-access-token` 是 PU 平台 token，不是 `wengine_vpn_ticket*` |
| 直连范围 | 第 4 条只放行只读 |
| 目标表达 | 二课 `@POST` 注解值本身是绝对路径常量；ADR 要求「只传逻辑目标名」 |

## 二、第一性原理：二课与 jiaowu 不同构

jiaowu 能「下发会话、不下发凭据」，前提是存在**派生关系**：

```
go-admin-tgt（凭据） ──换票──> ST ──回投──> ASPSESSIONID（派生会话）
```

所以后端可以把派生会话交给客户端，自己留下凭据。ADR-0001 第 5 条 2026-11-16 的放宽正建立在这条派生链上。

**二课没有这条派生链**。[研究：PU 平台 x-access-token 的来源/刷新/失效链路](https://github.com/NongyuSystem/nongyu-backend-plus/issues/68) 已证：

- `x-access-token` **就是**登录凭据本身（D 组 12 个 login 方法产出它）；
- 172 端点里**没有** refresh / renew / logout 端点（字符串池里的 `refreshToken` 属极光/厂商推送 SDK）；
- 也没有「用 token 换一个短命会话」的端点。

结论：二课不存在「下发派生会话」这个选项。凭据只能在「谁持有」上二选一，或干脆两边都不持。

## 三、六题结论（维护者拍板）

### Q1 凭据形态 → **读写都在客户端，后端零凭据**

**这不是「客户端持 token 直连」的简单版本，而是把后端职责收窄到两件事**：

| 谁 | 做什么 |
| --- | --- |
| 客户端 | 持本人 `x-access-token`；发起**全部读写**请求（含活动列表、学分、成绩单等读类） |
| 后端 | ①**发怎么请求**（下发请求配方：地址、方法、参数槽位）②**记录** |

**否决的三个候选与理由**：

- **纯 A（客户端直连写、后端承载读）**：会让「读类后端承载」名存实亡前功尽弃——它本身就是本图 Q3 的原口径，被本次决策推翻。
- **B（后端代持 token 代做读类）**：**加密存储能防住静态泄露，与 tgt 同级**——这一点必须说准，不能拿「库泄露」当理由（见 §三之补注）。真正的代价是两条：①**爆炸半径**——tgt 只能换票取学籍页，而 PU token 能调 154 个接口**含写操作**（报名/签到/评价/改活动/存成绩单设置），后端一旦持有它，「本人发起」这个技术边界即失效，哪怕代码只用于读；②**无法止损**——PU token 无 refresh / renew / logout，有效期未知（见 #68 待 HITL），泄露后只能等其自然过期；tgt 有 9 天 TTL 且换票带回新值可滚动续期，密码镜像有「清除我的农屿密码」入口，两者都有用户侧或系统侧的止损手段。
- **C（后端用密码镜像代登 PU）**：技术上可行（仓内已有密码镜像，`snoLogin` 就是账密登录），但会把 ADR-0002 已接受的那笔风险（「库泄即学校账号泄」）**外溢到一个我们无法审计的第三方平台**。明确否决。

**代价（明确接受）**：后端对二课**零出站、零凭据**，因此读类数据完全依赖客户端获取；后端若要有活动数据，只能靠客户端回传（见 §六 未决项）。

### Q2 目标集合 → **A 并列集合**

`jk` / `h5` 作为独立的「第三方业务平台」段加入，与「校内目标」段并列，各有各的约束。理由：两类在网络可达性、凭据类型、后端是否持凭据上三处根本不同，混成一个白名单会让后来人误以为约束相同。

### Q3 第 4 条扩项 → **A 按主体扩**

从「客户端直连的**只读**请求不经后端」改为「**已认证本人发起**的请求不经后端，不区分读写」。

理由：区分的目的是决定「谁生成参数」（GPS 坐标、扫码时间戳必须客户端产生），**不是决定网络路径**。写操作要直连的真正理由同样是「归属本人」。

### Q4 修订形态 → **A 追加一节**

追加「2026-11-16 再修订：第三方业务平台（学校二课）」一节，**不改五条正文的历史文字、不动 accepted 状态**。仓内已有先例（第 5 条的「2026-11-16 再修订」就是追加）。

### Q5 审计与限流退化 → **A 沿用 jiaowu 口径**

经后端的交互记审计 + 按用户分级限流；客户端直连段明确写「后端观测不到、无限流无审计」，**不得声称「所有请求均已限流」**。本期不做客户端回执上报。

理由：回执是**不可信上报**（可不报、可伪造），却容易被误读成「有审计了」，比诚实留白更危险。

### Q6 `code=5` 判定 → **A 客户端判定**

`code=5`（PU token 失效）由客户端自行判定并跳登录，在 Spec 里写成**客户端本地错误态**——与 jiaowu 的 `session_expired` 同一处理方式。后端只在自己经手的交互里映射错误码。

## 五、ADR-0001 追加节（已落地）

已在 [ADR-0001](<docs/adr/0001-服务端代请求边界由新后端重写.md>) 末尾追加「2026-11-16 再修订：第三方业务平台（学校二课）」，要点：

1. **目标集合分段**：新增「第三方业务平台」段（`jk` / `h5`）；调用方仍永不传 host 或完整 URL，SSRF 结构性排除不变。
2. **PU 凭据边界**：`x-access-token` 由客户端持有，后端不持有、不代管、不下发、不用密码镜像代登。
3. **直连范围按主体扩**：已认证本人发起的读写请求都不经后端。
4. **盲区与失效判定**：直连段后端观测不到、无限流无审计；`code=5` 由客户端判定。
5. **不改动清单**：第 1 条结构性排除、第 3 条票据下发口径、第 5 条 jiaowu 会话 Cookie 放宽、accepted 状态与历史文字。

## 六、遗留未决（不阻塞本票收口）

**「记录」的确切语义**：维护者说后端「做记录」，但记什么未定——是记「谁在何时请求了哪个配方」（纯审计流水），还是记「客户端取回的数据」（服务端持有数据副本）？二者差别很大：前者后端零数据，后者后端成为二课数据的只读副本（据此才能做「爬取二课活动在后端」这个原始诉求）。

这归 [决议：读类后端承载的端点契约与缓存语义](https://github.com/NongyuSystem/nongyu-backend-plus/issues/61) 改写后的新问题，**不在本票收口范围内**。

## 七、更正记录

**2026-11-16 更正「库泄露」表述**（维护者质疑：「加密存到后端的用户数据库不行吗，和 tgt 票一样」）。

初版否决候选 B 的理由写的是「托管到后端等于让『库泄露』升级为『二课账号泄露』」。**这个理由不成立**：仓库内 `TGTManager.Save` 就是先 `cipher.Seal` 再 `store.Put`（密钥 `cfg.TicketKey + ":tgt"`，与密码镜像、身份证各用独立密钥），加密存储能防住数据库被拖走后的静态泄露。PU token 完全可以照同样方式存。

**正确的理由换成了两条结构性差异**（已同步改到 §三 Q1 与本 ADR-0001 第 2 条）：

| | go-admin-tgt | PU `x-access-token` |
| --- | --- | --- |
| 能做什么 | 换票、取学籍页 | 调 154 个带 token 接口，**含写**（报名/签到/评价/改活动/存设置） |
| 止损手段 | TTL 9 天 + 换票带回新值可滚动续期 | **无** refresh/renew/logout，有效期未知，泄露只能等自然过期 |
| 用户侧清除 | — | 与密码镜像不同，token 本身无「清除」入口 |

结论不变（仍选客户端持有），但理由从「存不安全」改为「**爆炸半径更大 + 无法止损**」。前者可被加密解决，后者不能。

**记录这件事的意义**：维护者对「加密能否解决」的追问是对的。若沿用错误理由，将来若 PU 补上了 refresh/吊销（或我们愿意接受短 TTL + 用途硬限定），有人会以为结论仍成立，却不知原理由已失效。理由准确，结论才经得起重估。

## 八、证据等级

本笔记的凭据事实全部来自 `work/iciannong-apk/` 离线逆向产物（`network_profile.mode=offline`，2024-03 build，无动态抓包、无 Frida），标注沿用 [调研-PU平台token来源与身份域复用可能.md](<docs/tech/调研-PU平台token来源与身份域复用可能.md>) 的四级口径。**未做任何真实网络或真账号验证**；「172 端点无 refresh/renew/logout」是产物内静态判读，真实服务端行为待 HITL。
