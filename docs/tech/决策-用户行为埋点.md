# 决议：用户行为埋点的事件模型与端点契约

> 来源：[决议：用户行为埋点的事件模型与端点契约（脱敏硬约束）](https://github.com/NongyuSystem/nongyu-backend-plus/issues/45)（wayfinder map #43 子票），2026-11-12 收口（HITL grilling，Q1~Q6 全 A + 5 项派生项按推荐收敛）。
> 性质：**决策记录**，不是 Spec、不是实现。本票的 resolution comment 是决议正文；本文是给 [#54](https://github.com/NongyuSystem/nongyu-backend-plus/issues/54) / [#51](https://github.com/NongyuSystem/nongyu-backend-plus/issues/51) / [#46](https://github.com/NongyuSystem/nongyu-backend-plus/issues/46) 引用的稳定落点。

## 前置（已锁，不在本票重开）

- **Q4（六题全 A）**：本图**只新增「用户行为埋点」这一层**；运行日志（stdout/slog → 采集器 → ES，**应用不直连 ES**，#24 决议）与审计流水（PG `audit_log`，旁路）沿用既有，本图不重开。
- **三层区分（#[52](https://github.com/NongyuSystem/nongyu-backend-plus/issues/52) 已落 `GLOSSARY.md:69-79`）**：用户行为埋点 = 客户端采集上报的行为事件、用于产品分析；运行日志 = 进程运行期结构化记录、用于排障；审计流水 = 敏感动作的标识性记录、旁路。**三层互不替代**，本票只做第一层。
- **脱敏铁律**：ADR-0001 第 3 条（票据不落日志/埋点）、ADR-0002（密码、身份证号绝不出现在日志/审计/埋点/错误信息）。
- **架构硬约束**：`README.md:15` 模块化单体（一仓/module/进程）；`:45` 业务域只依赖 `platform` 接口；`platform` 现有 14 接口**无埋点接缝**。
- **一手事实**（[底稿](调研-六类常见功能的旧农屿一手契约与新仓现状.md):37-54）：旧 Track 是**独立服务**（Go 已 DEPRECATED → 现行 Node），信封 `{ok,data}`+snake_case、`/v1` 前缀、1MB Body、约 120 req/min、批量 1~100、`event_id` 幂等、部分成功、队列满 503 `QUEUE_FULL`、`props` 4KB 截断、7 种事件枚举、默认保留 30 天。**Go 版已下线、不是本仓现行依赖来源**（`README.md:84`）。

## 决议（Q1~Q6 全 A）

**Q1 形态 = 本仓内的一个业务域**（`internal/track`），**不做独立服务/独立端口/独立库**。理由：`README.md:15` 已锁模块化单体，旧 Track 分家是为从旧业务库剥离埋点，本仓起步无此包袱。已知代价：与业务同进程，**靠 Q3 的旁路隔离防止拖垮业务**，不享受独立服务的天然隔离。

**Q2 信封与命名 = 本仓既有 `{code:string, message}` + camelCase**，**不照抄旧 Track 的 `{ok,data}`/snake_case**。Spec 须写明：本域的「对齐旧契约」= **事件语义与幂等/批量/部分成功/上限语义对齐，不承诺信封与字段命名字面一致**（#44 Q5-A 全域口径在本域的应用）。依据：旧 Track 已 DEPRECATED、非现行依赖来源。

**Q3 落库 = PG 独立表**（如 `track_event`，**不是** `audit_log`——三层语义不同）。写入**复用审计的旁路模式、但强度更高**：非阻塞入**有界缓冲** → 后台**批量 INSERT**；**缓冲满时丢弃并计数**（暴露 `dropped`），**绝不让业务请求等埋点库**。与审计的差别：审计可全丢，埋点是分析数据源 → **独立上限 + 丢弃计数**（观测用），并保留关停前 flush。已知代价：仍可能丢（有界缓冲的必然）。

**Q4 事件模型**：对齐旧 **7 种枚举** —— `screen_view` / `button_click` / `perf` / `app_open` / `heartbeat` / `crash`（App 可报）+ `llm_proxy_fail`（**仅服务端内部写**）。**公共字段**沿用旧 `TrackEvent`：`event_id`(幂等键) / `event_type` / `event_name` / `client_ts_ms` / `session_id` / `app_version` / `platform`(`ios|android|web`)，并**服务端注入** `request_id` / `user_id` / `received_at`（`user_id` 取自已认证身份，**忽略客户端伪造**）。**业务字段 `props`**：JSON 对象、序列化后**硬上限 4KB 超长截断**；**本期不做逐事件 schema**（只做顶层形状校验），逐事件字段清单留 fog。

**Q5 上报端点**：`POST /track/events`（本域自己的前缀）；**批量 1~100**；**`event_id` 为幂等键**（重复计入 `duplicated`，**不算失败**）；**单条失败不整批拒绝**（计入 `rejected`，走**部分成功**）；响应 `{accepted, duplicated, rejected}`；**Body ≤ 1MB** 用 `http.MaxBytesReader`（沿用教务回传既有做法）；**限流复用 `RateLimitMiddleware`**（已认证按身份）；**缓冲满不返回 503**，计入 dropped 后**正常返回**（埋点属旁路，不应引发客户端重试风暴）。已知代价：客户端拿不到「已落盘」的强保证，`dropped` 只能事后观测。

**Q6 脱敏 + 最小读取口**：写入侧**白名单 + 黑名单双保险** —— ① 顶层只接受 Q4 列的字段，**未知键丢弃（不报错）**；② `props` 内对已知敏感键名（`password`/`passwd`/`pwd`/`idCard`/`id_card`/`token`/`ticket`/`cookie`/`authorization`/`code`）**剔除并计数**；③ **4KB 截断在剔除之后**做；④ ADR-0001/0002 脱敏铁律写进 Spec 验收。**最小读取口只留 `GET /track/events/summary`**（按 `event_type` + 时间窗的**计数聚合**，不含 props 明细），**不做明细查询、导出、看板**（Q4 已排除分析平台）。已知边界：`props` 敏感键靠键名匹配，**改名的敏感字段挡不住**（Spec 记录）。

## 派生项（票评「下一轮才问」的 5 项，按「按推荐」保守收敛，可回滚）

- **D1 保留期与清理**：**本期不拍天数**，Spec 留「按 `received_at` 删除超过 N 天的行」的运维口，**N 交 [#51](https://github.com/NongyuSystem/nongyu-backend-plus/issues/51)**；不照抄旧仓 30 天（旧仓是独立 SQLite，本仓 PG 容量语义不同）。
- **D2 `presence/offline`（在线态回写）**：**本期不在本域做**。旧仓该端点「必须回调 Node 置 `is_online=0`」，属**跨域写**；本仓若有在线态需求，应作为独立决策（本图未列），归 #46/#55 或另立。理由：本票是「用户行为埋点」，在线态是另一个语义，混入会重演旧仓「Track 兼管状态」的耦合。
- **D3 缓冲参数**：容量/flush 间隔/批大小的**具体值交 [#51](https://github.com/NongyuSystem/nongyu-backend-plus/issues/51)**；本票只锁「有界 + 非阻塞 + 满则丢弃计数」的形态。
- **D4 鉴权口径**：埋点端点是否需要 **NY1 请求签名**、是否进 `publicPaths` → **归 [#46](https://github.com/NongyuSystem/nongyu-backend-plus/issues/46)**，本票不裁（票面约束即如此）。
- **D5 SDK 事件名规范**：旧 `TRACK_WEB_INGEST_ALLOWLIST`（按 (event_type,event_name) 白名单，5 个 CWV + `screen_view/web_home`）**本期不做**，留 fog；本期只锁枚举 + 顶层形状。
