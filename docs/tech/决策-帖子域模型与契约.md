# 决议：帖子域模型与契约

> 来源：[决议：帖子域模型与契约（对齐广场 PRD）](https://github.com/NongyuSystem/nongyu-backend-plus/issues/49)（wayfinder map #43 子票），2026-11-12 收口（三轮 HITL）。
> 性质：**决策记录**，不是 Spec、不是实现。本票的 resolution comment 是决议正文；本文是给 [#48](https://github.com/NongyuSystem/nongyu-backend-plus/issues/48) / [#53](https://github.com/NongyuSystem/nongyu-backend-plus/issues/53) / [#54](https://github.com/NongyuSystem/nongyu-backend-plus/issues/54) / [#51](https://github.com/NongyuSystem/nongyu-backend-plus/issues/51) 引用的稳定落点。

## 前置（已锁，不在本票重开）

- Q5（六题全 A）：`帖子`、`公告` 各自独立域；通知 + 内部信合并为统一 per-user 消息域（含已读）。
- [GLOSSARY.md](../../GLOSSARY.md):95-101：帖子 = 用户发布的内容实体，可带回复与附件，与公告独立成域；`_Avoid_` 含公告、留言（回复由帖子域定）、反馈墙／大院（旧仓板块名）。
- [#44 决议](决策-公告域模型与作用域.md):24 **全域口径**：本 effort「对齐旧契约」= **产品语义对齐，不承诺 HTTP 路径逐字一致**；信封沿用 `{code:string, message}`。
- [事实底稿](调研-六类常见功能的旧农屿一手契约与新仓现状.md):76-95、:113-128：旧仓单表 `posts` + `post_type` 三值；`post_replies` 分 `admin_reply`(1:1)／`comment`(1:N)、**无嵌套（无 `parent_reply_id`）**；`notified_author` 是行级布尔位、**非 per-user 已读**；增强 PRD 的图片/编辑能力为**提案（无 ADR / 无下游 Spec / 旧 node-server 源码 0 实现）**。
- ADR-0002:76-83：作者姓名/学号属学校档案字段，只服务端写；管理端读须经 [#46](https://github.com/NongyuSystem/nongyu-backend-plus/issues/46) 鉴权并记审计。

## 决议（Q1~Q13 全部落定）

**Q1 板块模型与正名**：帖子域内用 **`board` 属性**区分两类用户内容（值沿用 `feedback` / `courtyard`，属实现细节不进 GLOSSARY）；**公告不再是帖子的一种**；**「广场」不作新仓正名**（旧仓 App 导航/页面名，GLOSSARY 不收 UI 概念）；可见性只做**板块级**，**不做「仅自己」**；状态只做 **正常 / 软删**，**不做审核态**。本域称「帖子域」。

**Q2 匿名性**：保留旧仓口径 —— 客户端列表/详情**不下发作者身份标识**；管理端经 #46 鉴权后可查实名并记审计。

**Q3 本期互动能力**：**做** 回复/留言（沿用 `admin_reply` 1:1 / `comment` 1:N 两类语义、**无嵌套**、作者匿名）、**点赞、收藏、24h 内本人编辑**；**不做** 富文本。24h 编辑窗口以**服务端 `canEdit` 判定**、回 `editedAt`。

**Q4 附件**：**本期做**；上限 **9 张 / 单张 5MB / `jpg|png|webp|gif`** 作为本期硬约束；**上传方式与对象 key 规范交 [#53](https://github.com/NongyuSystem/nongyu-backend-plus/issues/53)**，本票不重开 MinIO 选型。

**Q5 端点契约**：按新独立域写 **`/posts*`**（管理端 `/admin/posts`），语义对齐、不承诺路径逐字一致；列表用**游标分页 + `publishedAt` 倒序 + 按 `board` 过滤**；信封 `{code:string, message}`；**阅读量/覆盖率本期不展示**，旧仓 `post_reads` 表不迁移。

**Q6 通知与 `notified_author`**：**废弃** `notified_author` 行级布尔位与前台轮询；帖子域**不留通知位、不做轮询端点**；改由 [#55](https://github.com/NongyuSystem/nongyu-backend-plus/issues/55) 统一 **per-user 已读**承接（Q5 已锁）。

**Q7 端点补齐**：`POST/DELETE /posts/:id/like`、`POST/DELETE /posts/:id/favorite`、`PATCH /posts/:id`（24h 内、`canEdit` 服务端判定、回 `editedAt`）；「我的点赞/收藏」列表与点赞数展示**本期不做**。

**Q8 通知触发点（含追加）**：见 Q11 —— 除帖子级两条外，**评论被点赞、评论被回复也通知**。

**Q9 GitHub Issue 集成（修改后口径）**：**继承** `feedback` 帖 → 异步建 GitHub Issue（含编辑后同步），**但默认在 B 端关闭**。「默认关闭 + B 端可开」是本票锁定的唯一语义；**开关的存储形态、切换权限、关闭时的行为细节归 #46 与 #51 收敛**（增强 PRD 无此开关，属本 effort 新语义）。

**Q10 附件 B 的收口确认**：① 接受「**提案条款升格为本期硬约束**」——9 张/5MB/四格式写进 Spec 验收并**标注来源 = 广场发帖增强 PRD（提案，非既有决议）**，不得写成「沿用既有契约」；② 接受与 #44 Q8「公告本期不做图片」的**不对称**，**#44 不改**；③ 对象 key/上传方式交 #53，已在其票上加交叉引用，**不新增 blockedBy 边**（两票不共用文件、合拢由 #54 承担）。

**Q11 通知触发点精确清单（防递归）**：指认 **4 个触发点**，全部**无嵌套、深度 ≤ 2**：
1. 帖子被回复/留言（收件人 = 帖主）
2. 帖子被点赞（收件人 = 帖主）
3. 评论被点赞（收件人 = 评论作者）
4. 评论被回复（收件人 = 评论作者）

第 4 条按现有模型实现为「**顶层留言下的另一条顶层留言**」，**不引入 `parent_reply_id`、不做 N 层递归**（一手依据：旧仓 `post_replies` 本就无嵌套）。收件人计算、幂等键、去噪合并（同一帖子短时间多点赞）、「发给自己过滤」、编排落点**全部归 [#48](https://github.com/NongyuSystem/nongyu-backend-plus/issues/48)**。

**Q12 点赞/回复的靶子范围**：统一支持 **`target_type = post | comment`**；`comment` 作者按 Q2 匿名（`isMine` 自识）；**不引入嵌套回复**；「我的点赞/收藏」列表仍不做。按靶子维度加唯一约束（同一用户同一靶子只点一次）。

**Q13 缓存落点**：只给**高频读、非强 per-user** 的端点加短 TTL 缓存 —— **`GET /posts`**（键含 `board` + 游标）、**`GET /posts/:id`**（键含 id）；写操作（`POST/PATCH/DELETE`）删除对应 `board` 键；**per-user 的「我的帖子/点赞/收藏」不缓存**；**点赞数/收藏数不缓存**（Q5 本期不展示）。沿用既有 `RedisCache.Set/Delete` 与全站限流，**不新增 platform 接口**；新鲜度窗口与物理 TTL 分开（既有 pitfall）。本票只定「哪些接口缓存 + 失效语义」，实现交 `/to-spec`。

## 本票未裁定 / 留 fog

- **GitHub Issue 集成开关**的存储形态（配置 / DB）、切换权限、关闭时 `feedback` 帖是否仍写本地记录 → #46 / #51。
- **附件对象 key 规范与上传方式**（预签名直传 vs 后端中转）→ #53；两域附件差异由 #54 汇总。
- **阅读量 / 覆盖率 / 点赞数 / 收藏数**本期均不展示、不做统计（与 #44 Q7 同口径）。
- **缓存 TTL 具体取值与 `board` 键命名** → #51 Spec。
- **评论被回复的收件人边界**（留言作者 vs 帖主可能不同）与去噪策略 → #48。
