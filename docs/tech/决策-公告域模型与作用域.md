## 决议（Q1~Q5 全 A）

**Q1 发布者与读者范围**：仅管理端（`role` 1/2）可发布/编辑/撤回；读者 = **全员 + 按角色 + 按学院/年级定向**（受众条件存公告上，读列表时按当前用户 `StudentBrief` 过滤）；**不允许回复、点赞、评论**（互动归帖子域，GLOSSARY 已把两者分开）。代价已记录：定向需逐人判 `StudentBrief` 或新增受众条件表，角色定向与 role 三档的映射写进 Spec。

**Q2 时效模型**：状态机 **草稿 → 已发布 → 已撤回**（软删）；字段 `publishedAt` + 可选 `effectiveFrom / expiresAt` + 置顶标记 `pinned`；**过期公告移出默认列表**（`expiresAt < now` 不返回），但详情仍可按 id 查；列表排序 = 置顶优先 + `publishedAt` 倒序。状态机与过期判定写进 Spec 验收。

**Q3 端点契约与已读**：管理端 `POST/PATCH/DELETE /admin/announcements` + `GET /admin/announcements`（含草稿）；客户端 `GET /announcements`（按 Q1/Q2 过滤排序）、`GET /announcements/:id`、`GET /announcements/latest`。信封与错误码沿用本仓 `{code:string, message}`；`latest` = 已发布且在有效期内、置顶优先、`publishedAt` 倒序取 1 条，无则 `null`。**不做本域已读/确认表**：确需回执指向 [消息域模型](https://github.com/NongyuSystem/nongyu-backend-plus/issues/55) 的 per-user 已读（避免与 Q5 重复造轮子）。旧仓「阅读量/覆盖率」只作语义参照，本期不做统计（见 Q7）。

**Q4 通知触发点（只指认，不定义模型）**：指认 **1 个触发点**「公告**发布且对当前用户可见**」；收件人 = Q1 受众条件算出的集合；幂等键 `(announcement_id, user_id, publish_revision)`（`publish_revision` 由 Q2 状态机给，编辑重发不重复投递）。收件人计算、去噪/合并、编排落点（装配层）、失败是否影响主业务，全部归 [触发源与派生关系](https://github.com/NongyuSystem/nongyu-backend-plus/issues/48)。

**Q5 与旧端 HTTP 契约不兼容处（全域口径）**：按新独立域写 `/announcements*`，旧路径只作**产品语义参照**（首页通知栏、Admin 发布/编辑/软删、公告不轮询）。本 effort 对「对齐旧契约」的精确定义 = **语义对齐，不承诺 HTTP 路径逐字一致**（与「不复用旧代码/表结构/部署链路」一致）。此口径适用于其余各域票（#45/#49/#55），已登记进 map #43 的 Notes。
