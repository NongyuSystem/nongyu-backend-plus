### 1.2 关键判断：它含用户/会话维度，不能硬编码

第一版给过三条证据，**v2 复核后三条都成立**，并新增两条更强的：

1. **形态证据（保留）**：`dizhi`(352) / `o`(72) / `w1`(128) / `rul`(360) / `h`(72) / `bh`(24) 是超长纯数字串，远超正常参数长度，是典型的**服务端加密或签名后回填**形态；正常的时间戳或 id 不会这么长。[来源: 同文件:19-20]
2. **孤立证据（保留，已复核）**：对 `@OLD/packages/nongyu-tool-jiaowu/core/` 全量 grep `rig=` / `bh=` / `&rig` / `&bh`，**只在 `planInfo.ts:20` 一处命中，其他模块零命中**。若是通用常量（如校区 id），其他查询模块理应复用。`【实测 v2】` 重跑确认。[来源: 本会话 grep]
3. **无解密/无生成路径（保留，已复核）**：整个 `core/` 里唯一的解密函数是 `decryptCasData`（用于 CAS 响应体 AES 解密，`cas.ts:132,143,169`）；**没有任何针对 `dizhi/rul/h` 这类参数的解密或生成代码**，说明旧实现只是**原样透传**从页面抓到的值。[来源: @OLD/packages/nongyu-tool-jiaowu/core/login/cas.ts:132,169]

`【实测 v2】` **新增的两条证据**（第一版没有）：

4. **`w1` 内部包含 `id` 的值**：在 `w1`（128 位）第 96 位偏移处能找到 `90548091`，上下文 `…5504892390959054809197862519…`；其余 7 个长串**均不含** `id` 或 `rig`。→ `w1` 是**由 `id` 派生**的串，不是独立字段。
5. **`wid` / `vrul` 是等长（各 23 项）的平行掩码**，`wid` 全 `1`，`vrul` 前 22 项 `y`、**仅第 23 项（索引 22）为 `n`**。结合 `planInfoExtractor.ts` 的列注释「`0:序 1:课程编号 … 22:执行学期 23:课程简介`」（共 24 列，`课程简介` **不被提取**），23 = **跳过 `序` 列后的其余列**，末位 `n` 正好对应「`课程简介` 列被隐藏」。→ **推断（有印证）**：这一对是培养方案表格的**列选择/列可见掩码**，与具体学生看到的列集有关，**不是随机数**。[来源: planInfoExtractor.ts:126-129,131-158]

`【实测 v2】` **一条重要的反证**（用来收紧第一版的措辞）：

6. **全串不含学号**：旧仓 `@example` 与 `test.ts` 里出现的学号 `202308596` 在整个串中**不出现**；串里也**没有任何 9 位独立数字 token**；也没有 `2025-2026` 之类可读学期串。
7. **`selw`/`sel1w` 即使像时间戳，也没有被用于时效校验**：它们在源码里是**写死的常量**，从 2026-06-18 首次提交至今**一字未改**（`git log -S 'selw=1759000867099842'` 只命中 `b3f7460`）。若服务端对它们做时效校验，这套代码一次都不可能成功。→ 这两项**可以**在抓到后被原样复用，{但不能理解为「值固定」}——它们仍是页面下发的值。

### 1.3 结论：不能静态化（第一版结论成立，理由收紧）

> **`PLAN_FIXED_PARAMS` 不能做成静态常量。** Go 侧必须先 `GET` 一次 `jjihua.asp?title_id1=1` 拿到页面，从 HTML 里提取隐藏域，再拼第二次请求。**这一条推翻了票 #31 初稿的假设「能否用静态常量替代」——答案是不能。**

`【实测 v2】` 必须一起读的一条**仓规**：`TECH.md` 在登录链路上写死了全包通用口径——

> 「禁止冻抓包里的 Cookie / sign / hour_key。**解析失败不得回退固定值**。」[来源: @OLD/packages/nongyu-tool-jiaowu/TECH.md:46]

`PLAN_FIXED_PARAMS` 的形态（1370 字符、88% 是不透明数字串、含记录 id 与列掩码）**正属于「抓包里冻下来的值」**，按仓规不该以常量形式存在。

`【实测 v2】` **另一条必须说清的诚实边界**：**仓内没有任何证据证明 `getPlanInfo` 曾经成功过。**
- 包自带的联网自测脚本 `test.ts` 里，培养方案那行**从首次提交起就是注释掉的**：`// await safeTest("培养方案", getPlanInfo);` [来源: test.ts:146；`git show b3f7460:packages/nongyu-tool-jiaowu/test.ts` 同一行为 `// await safeTest('培养方案', getPlanInfo);`]
- 仓内不存在它的任何真实输出记录、无夹具、无断言。
- 因此「它能不能跨用户重放」的诚实答案是：**代码形态表明它对每个用户发出的都是同一份串**（`getPlanInfo()` 无入参），但**既无成功证据也无失败证据**。

**若串里确实含用户维度**（`wid`/`vrul` 列掩码最可疑），后果是**取到别人的列集/方案页且不报错**——因为 `extractPlanInfo` 的成功判据只有「存在 `class=tablebody` 的 table 且扫到 `g_body_[12]` 行」，**任何符合 class 的表都能让 `success:true`**。[来源: planInfoExtractor.ts:70-79,98-121]

### 1.4 可施工做法（v2 补充实现细节）

1. **两段式请求**：`GET .../jihua/jihua/jjihua.asp?title_id1=1`（不带附加参数）→ 抽隐藏域 → 拼第 1 页 → 只改 `y=2` 得第 2 页。
2. **隐藏域抽取照抄仓内先例**（`extractHiddenInputValue` 的双正则策略：name 在前 / value 在前各一条，都取不到返回 `null`）：[来源: @OLD/packages/nongyu-tool-jiaowu/core/login/index.ts:130-144]
   ```go
   reNameFirst  = regexp.MustCompile(`(?i)name\s*=\s*["']` + name + `["'][^>]*value\s*=\s*["']([^"']+)["']`)
   reValueFirst = regexp.MustCompile(`(?i)value\s*=\s*["']([^"']+)["'][^>]*name\s*=\s*["']` + name + `["']`)
   ```
3. **必须动态、禁止缓存成常量的键**：`selw`、`sel1w`、`id`、`rig`、`w1`、`wid`、`vrul`。
4. **抽不到隐藏域时**：返回显式错误（如 `CodePlanNoHiddenFields`）+ 日志「抽到 0 个隐藏域」，**不回退到 1.1 那串常量**（仓规 `TECH.md:46`）。
5. **`success` 不能只看 `courses.length > 0`**：至少再加一条形状校验（`title != ""`，或「每门课 `courseCode` 非空」——后者本身已是旧仓的有效门，见 `mapRowToCourse` 的非空早退）。[来源: planInfoExtractor.ts:131-136]
6. **页数别写死 2**：旧仓硬编码「只有 2 页」，若教务变 3 页会**静默丢课**。Go 侧应抓到最后一页再停，或至少记「已取 2 页、是否还有下一页」的诊断。[来源: planInfo.ts:120-134]

### 2.2 会脆断的具体情形

由于判据是 `> 6`（而非 `=== 7`），**任何 ≥ 7 列的行都会被当成「有分类标签」而左移一格**。第一版列了 3 条，`【实测 v2】` 把每条都跑了一遍，并**订正了第 1 条的后果**：

**脆断 A：教务新增一列（7 列 → 8 列…按「6 列表头 + 7 格数据行」计）→ 整行左移，`type` 变成学分数字**

`【实测 v2】` 构造样本 `必修课,160,120,40,0,75%,120/160`（7 格）：

| 字段 | 应得 | 实测得到 |
| --- | --- | --- |
| `type` | `必修课` | **`160`** |
| `required` | `160` | `120` |
| `earned` | `120` | `40` |
| `diff` | `40` | `0` |
| `transfer` | `0` | `75%` |
| `progress` | `75%` | **`120/160`**（新列的值） |

`【订正 v2】` 第一版说「`progress` 落到不存在的下标取到 `undefined`」——**不准**。因为 offset 变 1 后 `offset+5 = 6` 恰好是新列的下标，所以 `progress` 取到的是**新列的值**，不是 `undefined`。

**这比第一版描述的更危险**：整行**每一位都错，但没有一位是空的**，所以 `:73` 的有效性门槛 `type && (required||earned)` **照样放行**，`success` 仍为 `true`。这是本解析器**最危险的失效模式：静默、无空值、无异常、可被缓存**。

**脆断 B：某行因 `rowspan` 少一格（6 列 → 5 列）→ `progress` 变成 `undefined` 并**从 JSON 里消失**

`【实测 v2】` 构造 `必修课,160,120,40,0`（5 格）→ `{type,required,earned,diff,transfer}`，**无 `progress` 键**。
下游 `ProgressScreen.tsx:57` 把 `item.progress` 直接喂给 `parseProgressPercent`，而该函数 `progress.match(...)` **无空值保护** → 收到 `undefined` 时 **TypeError**。[来源: ProgressScreen.tsx:57；utils/parseProgressPercent.ts:4-5]

**脆断 C：`colspan` 合计行 → 正确性依赖 colspan 恰好等于被吞掉的列数**

`【实测 v2】`（合计行用**单个** `td` 带 `colspan`）：

| 合计行形态 | `parseTable` 格数 | offset | 结果 |
| --- | --- | --- | --- |
| `colspan=2` + 5 值 = 6 格 | 6 | 0 | `{type:"合计", required:"200", earned:"140", diff:"60", transfer:"0", progress:"70%"}` —— **碰巧正确** |
| `colspan=3` + 4 值 = 5 格 | 5 | 0 | `{type:"合计", required:"140", earned:"60", diff:"0", transfer:"70%"}` —— **整行左移，`progress` 丢失** |

**脆断 D（第一版未提）`【实测 v2】`：`<br>` → `\n` 原样保留，且下游只清洗 2 个字段**

`stripTags` 把 `<br>` 换成 `\n`。[来源: html.ts:47] 实测 `必修课<br>公共必修` → `type:"必修课\n公共必修"`；`160<br>120` → `required:"160\n120"`。
下游只对 `type` 与 `earned` 做了 `replace(/\n/g," ")`，**`required` / `diff` / `transfer` / `progress` 都没有**。[来源: ProgressScreen.tsx:55,57,58,71]

**脆断 E（正面结论）：表头上方多一行说明，`progress` 反而比 `exam`/`rank` 稳**

`【实测 v2】` 在表头之上加一行 `学分统计（截至2026-07）`（1 格）→ 进度表**照常正确**。原因：该行 1 格 < 5 被 `:59` 过滤，且选表打分看前 3 行仍在窗口内。**对比 `exam`/`rank` 用「第一个非空行当表头」，同样情形会让它们直接错**（见 ④.2 风险 A）。

### 2.3 Go 侧避免脆断的做法

**核心：不要把「列数」当分类标签的信号。**

1. **用表头关键字定位列**（与 score/exam 一致），而不是下标偏移。表头行已被 `课程性质`/`应修` 规则单独识别，可直接对表头做 `findIdx` 得到每个字段的列号。这样 8 列/9 列/列序变化都不会错位。
2. **分类标签列单独判定**：语义特征是「该格文本命中已知分类集合」（`必修`/`选修`/`限选`/`公选`/`任选`/`合计`），用**文本判定 + 非纯数字**双重确认，而不是靠宽度。
3. `【实测 v2】` **加一条一行就能挡最危险失效的校验**：**若 `type` 全是数字，直接判错位**（脆断 A 的 `type="160"` 就是判据）。
4. **必须显式展开 `colspan`**：解析 `<td colspan="N">` 并把该格复制 N 份（或标记该行为合计行后单独处理）。旧仓不展开 `colspan` 是脆断 C 的根因。[依据: html.ts:105-111 只按 `td` 出现次数计数]
5. **`<br>` → 单个空格**，在解析层一次 `strings.Join(strings.Fields(s), " ")`，不要留给下游各自 `replace`。
6. **形状校验兜底**：`required/earned/diff/transfer` 应是数值形态（允许 `--`、空）；某字段取到非数值文本时判 `parse_failed`，不静默下发——与「解析失败不写缓存」口径一致。
7. **字段类型别用裸 `string`**：Go 用 `*string` 或显式 `HasProgress bool`，避免重演 JS `undefined` 被 `JSON.stringify` 悄悄丢键。**成功判据也别照抄**：旧仓找到表就 `success:true`（`:75-78`，`【订正 v2】` 实为 `:75-78` 区间内的无条件返回），需加形状校验。
8. **合计行别混进 `items`**：若 `type` 含 `合计`/`总计`，单独归到 `total` 字段。旧仓是混在一起的（实测输出里就有 `type:"合计"` 那一项）。

### 3.3 `【实测 v2】` 关键新证据：这些成分**不能总能抽出来**

第一版只列了「可抽出的正则」就收尾，**没有回答「有没有抽不出的形态」**。v2 补上——最强证据是**客户端已经在用正则硬抽它**：

`writeWidgetSchedule.ts:25-35` 的 `normalizeExamStartTime`：

[来源: @OLD/apps/nongyu-rn-app/src/modules/course/widget/writeWidgetSchedule.ts:25-35]

把这段正则原样跑在 8 种形态上（`【实测 v2】`）：

| 形态 | 客户端正则结果 | 判定 |
| --- | --- | --- |
| `@example` 原文（日期在前） | `2026-07-02 09:00` | ✅ |
| `【考试时间：2026-7-2 09:00—11:00】雅安校区 10-A303` | `2026-07-02 09:00` | ✅ |

**所以「是否总能抽出」的答案是**：
- **日期**抽不出（→ 整条时间信息丢失），只要出现「无日期的周次形态」就会发生；
- **时间**能抽出但**可能取到错的那个**（到场时间 vs 开考时间），**无任何信号**；
- **周次 / 星期 / 时段**：`examTime` 本身**没有对应的结构化字段**，旧仓从未提取过；客户端也没提。这三项**仓内未找到任何提取代码**，目前**只以散文形式存在**。
- 另有一个语义空洞：`@example` 里**同时**有 `【考试时间：2026-7-2】`（日期）与 `上午(09:00—11:00)`（时段）**两处时间信息**，`请08:45到考场`是第三处。**三者不一致时以谁为准，仓内没有任何说明。**

### 3.4 `【实测 v2】` 一条容易忽略的下游事实

`examTime` 在下游**既被当纯文本展示、又被当「可解析」输入**：
- 纯展示：`ExamCard.tsx:48`、`ExamScheduleList.tsx:27` 直接 `{item.examTime}`；
- 搜索：`useExamSchedule.ts:22-29` 把 `examTime` 作为 `matchSearchQuery` 的字段之一（子串匹配）；
- 解析：`writeWidgetSchedule.ts:80-81` 喂给 `normalizeExamStartTime` 写桌面小组件快照。

**即：原文一字不能改**（改了破坏用户按原文搜索 + 卡片上认得的文案），**但也不能只有原文**（已有 3 处在用正则硬抽，且会静默出错）。

### 3.5 结论（可施工）

- **原样字符串必发**（`examTimeRaw`，逐字保留含 `\n` 与多空格），结构化字段**可选 + 省略**，**不能填零值**：存在只有部分成分的形态，正则抽不出来时**省略该字段**而不是填 `""` 或 `0`。Go 用 `*T` 或 `omitempty`。
  - 理由（v2 加强）：`""` 与「抽不出来」在 JSON 上**不可区分**，而两者对下游含义完全不同（前者「教务就没填」，后者「我方没解析出来」）。旧仓 `normalizeExamStartTime` 抽不到返回 `""` 恰好把两者**合并成一个**。[来源: writeWidgetSchedule.ts:26-28]
- **不要**在解析失败时把 `examTime` 清空——原样串是唯一保真的信息。
- **`—` 是 U+2014**，Go 正则应写 `\x{2014}` 或直接匹配字符串 `"—"`；用 ASCII `-` 会匹配失败。**且只在括号内做区间匹配**，因为 ASCII `-` 同时被用作日期与时段分隔，全局匹配会有歧义。
- 月/日**不补零**，解析用 `\d{1,2}` 并自行补零。
- **取时间必须锚定区间**，不要取「文本里第一个 `HH:MM`」——那正是 3.3 里「到场时间在前」静默取错的成因。
- **建议抽取顺序（按可靠性）**：`date`（锚定 `【考试时间：`）> `start/endMin`（锚定 `(—)`）> `arriveMin`（锚定 `请…到考场`）> `weekNo` > `weekday`（**必须同时支持数字与中文**）> `periodName`。后三项**按可选出**，缺失是常态。
- **一致性冲突给信号**：`date` 与 `weekNo` 推算冲突、或 `arriveMin` 晚于 `startMin`，记诊断而不是静默取一个。

```

数据: 1    | 雅安 | 114      | 物联网工程 | 2023 | 202308596 | 唐磊 | 物联网202301 | 81.71 | 在读
输出: { major: "114", majorRank: "114", ... }
```

**成因**：`major: findIdx(["专业"])` 用 `includes`，**先命中的是「专业排名」这一格**；`majorRank: findIdx(["专业排名","排名"])` 也命中同一格。[来源: rankInfoExtractor.ts:148,154]

**关键洞察（第一版只说「关键字过宽」，v2 说清结构）**：`weightedScore` 因为用了**更长关键字优先**（`"有效必修加权成绩"→"加权成绩"→"加权平均成绩"`，`:153`）而没被抢；**只有 `major` 没做「更长优先 / 排除」保护**。新仓 `schoolauth/academic.go` 已经踩过同一个坑并用 `lookupExcluding` + 按长度排序解决了，可直接抄。[来源: @NEW/internal/school/schoolauth/academic.go:143-211]

**风险 C（v2 实测复现）：排名页真的有多行 → 静默只留第一行**

`【实测 v2】` 构造同一学号两行（81.71/114 与 79.20/130）→ 只返回第一行，第二行**完全丢弃，`success` 仍是 `true`**。若教务按学期给多次排名（`@example` 的 `majorRank: '114'` **看不出是哪一学期**），现实现**只取网页第一行且不知道丢了什么**。

**风险 D（v2 新增）：类型注释与 `@example` 自相矛盾，需点出**

- `RankItem.majorRank` 注释写「专业排名（**如：1/120**）」，暗示「名次/总人数」形态 [来源: rankInfoExtractor.ts:21]；
- 但 `rankInfo.ts` 的 `@example` 给的是 **`majorRank: '114'`**（纯名次，无分母）[来源: @OLD/packages/nongyu-tool-jiaowu/core/jiaowu/rankInfo.ts:41]；
- 下游 `RankScreen.tsx:47-48` 渲染成「第 **114** 名」，即**当作纯名次**。

→ **实际形态是纯名次**，`1/120` 只是注释里的愿望。Go 侧按**纯名次**建模，不要按 `1/120` 拆分子分母。

### 4.3 页面本身是「单人单行」吗？

**仓内未找到排名页真实 HTML**（底稿 ④.2 已确认无夹具；本会话再次全仓检索 `*.html`，`core/extractor/__fixtures__/` 仍只有通知片段）。

源码侧能说的：
- URL `zytongbf.asp` **无任何参数**，取「当前登录学生」的排名 [来源: `@OLD/packages/nongyu-tool-jiaowu/core/jiaowu/rankInfo.ts:11,60]；
- `@example` 只给一个学生、一个 `index:'1'` [来源: rankInfo.ts:31-43]；
- 排名页文案是「专业排名（**有效必修加权**）」[来源: RankScreen.tsx:30]；
- 规格文档明确说排名页**是单卡、无列表、不适合加搜索**。[来源: @OLD/docs/nongyu-rn-app/specs/专业排名页UI优化.md 第 2-3 节]

→ **推断（有较强旁证，但不是一手证据）**：页面大概率「单人、单行、单学籍状态」。仓内没有任何排名页 HTML、没有「多行是否存在」的探测记录。**而代码的早退使得「万一有多行」永远不可见。**

### 4.4 结论（可施工）

- **保持单对象 `RankItem`**（与旧契约一致，客户端已按单对象消费）。但注意理由**不是**「页面只有一行」（那是推断），而是「旧仓是单对象、`RankScreen`/`RankCard` 都按单对象渲染、改数组会破坏线协议」。
- Go 侧**内部**必须**先把所有有效行都解析出来**，再取第一行返回；命中多行时**记审计/日志 + 诊断字段**（`droppedRows`、`headerRowIndex`——后者 > 0 即说明表头上方有说明行，是风险 A 的预警信号）。这样上游真改成多行时我们能**发现**而不是静默丢弃。
- 挑行规则要比旧仓严：
  - **拒绝「值等于表头文字」的行/字段**——这一条就能挡住风险 A；
  - **至少要求 `studentId` 或（`name` + `weightedScore`）非空**，而不是「4 字段任一非空」。因为 `majorRank` 单独有值极易被表头/说明行满足（风险 A 正是靠它放行的）。
- 列识别改为**最长关键字优先 + 全等优先**，并给 `major` 加**排除**：`专业排名` 必须从 `major` 的候选里排除。可直接照搬新仓 `academic.go` 的 `lookupExcluding` + 长度排序先例。[来源: @NEW/internal/school/schoolauth/academic.go:143-211]
- `weightedScore` 同理：`有效必修加权成绩` > `加权平均成绩` > `加权成绩` 顺序尝试（旧仓已是此序，保持）。
- **`success` 不要照抄**：旧仓「找到表就 `success:true`」，但风险 A 证明 `success:true` 可能是 `{major:"序号"}`。Go 侧 `Found/success` 应等价于「**取到了一条通过形状校验的行**」，而不是「找到了一张表」。
- **若未来要多学期**：**新增字段**（如 `ranks []RankItem`）而不是改现有单对象字段名——旧仓/App/agent 三处都按单对象消费，改形状是破坏性的。

## 5. 四条结论速查（建票/写码时直接引用）

| # | 问题 | 一句话结论 |
| --- | --- | --- |
| 1 | `PLAN_FIXED_PARAMS` 能否做常量 | **不能。** 1370 字符 / 26 键里 88% 是不透明数字串，含 2 个记录 id（`id`/`rig`）、1 个由 `id` 派生的串（`w1`，内部含 `90548091`）、1 个 23 位列掩码对（`wid`/`vrul`）；全串**不含学号**（`202308596` 不出现）；**仓内从未有过它成功的证据**（`test.ts:146` 从首个提交起就是注释）。Go 必须「先 GET 页面 → 抽隐藏域 → 再带上去请求」，抽不到就**报错，不回退常量**（仓规 `TECH.md:46`）。 |
| 2 | progress 行宽启发式 | 入池 `>= 5`（`:59`），偏移条件是 **`> 6`**（`:63`，不是 `=== 7`，8/9/10 列都只 offset=1）；offset=1 时六字段落 `row[1..6]`。断裂点：**8 列 → 整行左移、`type` 变成学分数字、`progress` 取到新列值，且仍 `success:true`**（最危险）；**5 列 → `progress` 变 `undefined` 并从 JSON 消失**（下游 `parseProgressPercent` 会 TypeError）；**`colspan≥3` → 左移丢列**；`<br>` 在 `required/diff/transfer` 无人清洗。Go 侧改用「表头关键字定列 + 行首剥 `rowspan` 标签列 + 展开 `colspan` + `<br>`→空格」，并以「`type` 全为数字即判错位」做校验。 |
| 3 | `examTime` 要不要结构化 | **原文必发 + 结构化字段可选省略。** 真实形态：日期不补零、`【考试时间：】`、`第N周`、`星期` 后是**阿拉伯数字**、时段 `上午/下午/晚上`、区间分隔符是 **U+2014**、`请HH:MM到考场` 前置多个空格。**不能总能抽全**：无日期形态会让客户端现有正则整条丢弃；「到场时间在前」时旧正则**静默把 08:45 当开考时间**。周次/星期/时段**仓内从未被提取过**。抽不出来时用**指针/`omitempty` 省略**（`""` 与「抽不到」不可区分）并带诊断位；取时间必须**锚定 `(—)` 区间**，不要取「文本里第一个 HH:MM」。 |
| 4 | rank 单对象还是数组 | **保持单对象，但内部扫完所有行。** 「只取第一行」是 `for` 里的**早退**（`:100-102`），不是页面约束（单人单行是**推断**，仓内无 HTML 证据）。已实测三种失效：**表头上方有说明行 → 返回 `{major:"序号", majorRank:"序号"}` 且 `success:true`**；**`专业排名` 列在 `专业` 之前 → `major` 被写成排名数字**（只有 `major` 没做最长优先，`weightedScore` 做了）；**真有多行 → 静默只留第一行**。Go 侧要「拒绝等于表头文字的值」「`major` 用最长优先 + 排除」「加 `droppedRows`/`headerRowIndex` 诊断」；`majorRank` 按**纯名次**建模（注释的 `1/120` 与 `@example` 的 `114` 矛盾，以下游「第 N 名」实际用法为准）。 |
