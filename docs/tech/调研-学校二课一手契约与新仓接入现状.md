## 一、二课目标与凭据，以及与 ADR-0001 的冲突

### 1.1 二课的一手目标与凭据（DEX 静态）

- **BaseURL `https://jk.sicau.edu.cn:443/`**：证据是 `Api.getRxApi()` 的 `const-string v2, "https://jk.sicau.edu.cn:443/"` → `Retrofit.Builder.baseUrl(...)`；`getGsonApi(prefix)` 用 `StringBuilder("https://jk.sicau.edu.cn:443/").append(prefix)`，prefix ∈ `/act/ /user/ /group/ /msg/ /query/`。【DEX 静态】[来源: work/iciannong-apk/REPORT.md:29-35]
- **H5 `https://h5.sicau.edu.cn`**：样本身份表把应用标为「PU / 口袋校园 二课平台（四川农业大学定制版 i川农）」，host 证据即 `jk.sicau.edu.cn:443` 与 `h5.sicau.edu.cn`；H5 页面走 **query token**：`https://h5.sicau.edu.cn/apply_gt/apply/#/credit?token=`、`/cover/#/cover?token=`、`/gth5/#/appeal?token=`。【DEX 静态】[来源: work/iciannong-apk/REPORT.md:14,55]
- **鉴权是 header `x-access-token`，值是 PU 平台 token，不是 CAS / WebVPN 票据**：由 Retrofit `@Header("x-access-token") String token` 注入（`annotations2.py` 直解注解，非推测）；取值链 `Session.getLoginInfo(mContext) → LoginInfoVO.getToken() → Api.getXxx(token,...)`，5 个二课 presenter 完全一致，IL 逐指令可核。【DEX 静态】[来源: work/iciannong-apk/REPORT.md:43-50,85-97; work/iciannong-apk/dump/sc_final/tiangong.com.pu.module.secondclass.presenter.CreditRulePresenter.txt:11,13]
- 全部 172 接口统一 `@Header("x-access-token")`、全为 `POST`（`FormUrlEncoded` 用 `@Field`），响应壳 `BaseResponse<T>`；`Api$1` 追加的 7 个设备头（`pu-version` / `client-dev-brand` / `client-dev-type` / `client-os-type=android` / `client-os-version` / `client-long=0` / `client-lat=0`）**只挂在 `getGsonApi`，Rx 侧二课接口不带，只有 `x-access-token`**。【DEX 静态】[来源: work/iciannong-apk/REPORT.md:52-53; work/iciannong-apk/dump/ALL_API.md:5,7]
  - 例外（诚实标注）：少数接口不带 token——B 组 `getGpsR`（无参）、`getImportMemberResult(uuid)`、`getUploadResult(uuid)`，D 组登录 / 重置 / 基础字典类（详见 §三、§四）。「统一 Header」是总口径，不是逐条无例外。【DEX 静态】[来源: work/iciannong-apk/dump/ALL_API.md:173,176,185,932-935,949-955,960-963,966-976]

### 1.2 与 ADR-0001 的冲突（仓内一手）

- ADR-0001（accepted）**第 1 条固定白名单**：「仅 `jiaowu.sicau.edu.cn` / `auth.sicau.edu.cn` / `webvpn.sicau.edu.cn`。调用方**永不传入 host 或完整 URL**，只传逻辑目标名，由后端映射为具体 URL」。【仓内一手】[来源: docs/adr/0001-服务端代请求边界由新后端重写.md:25]
- 落地代码同口径：`school.targetHosts` 只有三项 `TargetJiaowu/TargetAuth/TargetWebvpn` → 三个 host；`Resolve` 只认逻辑目标名，未知名（含把 URL 当名字）返回 `CodeTargetDenied`。【仓内一手】[来源: internal/school/targets.go:29-36,70-79]
- 装配层出站白名单 `outboundAllowlist` 内建 **4 项**（比 ADR 文本多 `xsgz.sicau.edu.cn`，2026-11-13 实测补漏），仍**不含 `jk.sicau.edu.cn` / `h5.sicau.edu.cn`**；`HTTP_ALLOWLIST` 配置可在部署时追加。【仓内一手】[来源: internal/app/app.go:879-896; internal/config/config.go:40-45]
- **冲突摊开（三个维度，均须拍板）**：
  1. **目标 host 冲突**：`jk.sicau.edu.cn`（API）与 `h5.sicau.edu.cn`（H5）**都不在** ADR-0001 第 1 条的固定白名单，也不在代码内建 `targetHosts` / `outboundAllowlist`。要接二课，要么**扩展 ADR-0001 的目标集合**（并同步 `targetHosts` + `outboundAllowlist` + 守卫测试），要么**新增一类「非 WebVPN 的直连出站目标」边界**。【仓内一手 + DEX 静态】[来源: docs/adr/0001-服务端代请求边界由新后端重写.md:25; internal/app/app.go:888-896; work/iciannong-apk/REPORT.md:29,14]
  2. **凭据类型冲突**：ADR-0001 第 3 条管的是 `wengine_vpn_ticket*`（WebVPN 票据，可下发本人客户端直连、不落日志）；二课的 `x-access-token` 是 **PU 平台自有账号 token**，不是 WebVPN 票据、也不经 CAS 换票。因此「票据下发本人客户端直连」这条**不覆盖**二课；接入要**新托管一类 PU 凭据边界**（获取 / 加密外置 / 续期 / 失效 / 脱敏 / 退出登录清除），不能套用 WebVPN 票的现成口径。【仓内一手 + DEX 静态】[来源: docs/adr/0001-服务端代请求边界由新后端重写.md:27-28,40-45; work/iciannong-apk/REPORT.md:43-50]
  3. **结构做法冲突**：ADR-0001 第 1 条要求「调用方只传逻辑目标名、永不传完整 URL」；而二课 `@POST` 注解值**本身就是带模块前缀的绝对路径**（如 `/act/credit/v1.0.0/getApplyCredit`），Retrofit 对前导 `/` 从 host 根解析，`Api.BASE_URL_*` 只用于选实例、不参与 URL 拼接。即二课的「路径」是客户端侧常量拼出来的，不是后端逻辑名映射——两套目标表达方式不同。【DEX 静态 + 仓内一手】[来源: work/iciannong-apk/REPORT.md:37; docs/adr/0001-服务端代请求边界由新后端重写.md:25]

### 2.2 token 的实际载体与「能不能复用学校统一身份认证」

- **token 读取链已实证**：二课 presenter 的 IL 是 `Session.getLoginInfo(Context) → module/account/login/LoginInfoVO.getToken() → String`；即 token 存在 PU 的 `LoginInfoVO` 里，由 `Session` 持有。【DEX 静态】[来源: work/iciannong-apk/REPORT.md:45-50,97; work/iciannong-apk/dump/sc_final/tiangong.com.pu.module.secondclass.presenter.ApplyPeriodPresenter.txt:11,13]
- **`code=5` → `TokenException` → 全局跳登录，`Session.getLoginInfo` 是唯一 token 来源**。【DEX 静态 / 真实响应未验证】[来源: work/iciannong-apk/REPORT.md:62,233]
- **诚实边界**：登录端点返回的是 `module/account/login/LoginRespVO` 与 `LoginInfoVO`，但 `dump/vo/`（151 个 VO）只收 `data.vo.*`，**未收 `module.account.login.*` 的字段清单**；产物里只有一个 `data.vo.LoginUserVO` 带 `token` 字段（`// FIELD ... token`，`getToken()`），**它不是登录响应类**。故「login 响应里 token 的精确字段名 / 有效期 / 刷新方式」**APK 产物里未见**，不能据 `LoginUserVO` 臆断。【DEX 静态 / 仓内未找到】[来源: work/iciannong-apk/dump/vo/tiangong.com.pu.data.vo.LoginUserVO.txt:36,176; work/iciannong-apk/dump/ALL_API.md:1279,1326,1334; work/iciannong-apk/REPORT.md:249-256]
- **判断：不能复用身份域已有的 CAS 换票链路，须新托管一套 PU 凭据（或找到未证实的桥接）**。依据：
  1. 二课登录是 **PU 平台自有账号体系**：`snoLogin(sid, loginName, password)`（学号/学校 id + 登录名 + 密码）、`mobileLogin(mobile, password)`、`thirdPartLogin(unionId, authtype)`、`bindPu(sid, loginName, password)`，全部 POST 到 `jk.sicau.edu.cn`，**不带** `wengine_vpn_ticket*` / CAS `ST` / `CASTGC` / `auth.sicau.edu.cn` 任何形态。【DEX 静态】[来源: work/iciannong-apk/dump/ALL_API.md:925,960,966-967,1323-1337; work/iciannong-apk/REPORT.md:29,43]
  2. 全仓 APK 产物 grep `webvpn|wengine|CASTGC|auth.sicau|jiaowu.sicau` 命中的 `SSO*` / `SSOAuthorizeActivity` 等均来自 Mob/ShareSDK 第三方登录库字符串，**不是川农 CAS**；`webLoginFromApp(uuid)` 是 PU 自己的登录换态端点，不是 CAS 端点。【DEX 静态】[来源: work/iciannong-apk/dump/str/all_strings.txt:17782-17783,25643-25646; work/iciannong-apk/dump/ALL_API.md:976,1402-1408]
  3. 新仓身份域的站点目录 `SiteProfiles`（10 站：jiaowu / ywtb / webvpn / xsc / zjc / cwc / lib / xsgz / opac / ecology）**不含 `jk.sicau.edu.cn` / `h5.sicau.edu.cn`**，身份域的「登录方式」词条是「学校统一身份认证（账密/微信/电话）/ 农屿账密 / 农屿邮箱验证码 / 身份证后四位加姓名拼音首字母」，与 PU 的 `snoLogin/mobileLogin/thirdPartLogin` 不是同一套。【仓内一手】[来源: internal/school/cas/exchange.go:72-113; GLOSSARY.md:43-49]
  4. `bindPu` 参数含 `sid`（学校 id）说明 PU 账号与学校有关联，但它是**带 x-access-token 的登录后绑定**；「PU 底层是否与学校统一身份认证打通、能否用 CAS 票换 x-access-token」**仓内未找到／APK 产物里未见**，须真账号 / 真网络 HITL，不得推测。【仓内未找到／待 HITL】[来源: work/iciannong-apk/dump/ALL_API.md:925,1005-1011; internal/school/cas/exchange.go:72-113]

### 3.5 用户点名的「报名 / 申诉」——诚实核查结果

### 5.2 HTTPDoer / Service.Address / 白名单 school.Resolve 能否直接承载 jk.sicau.edu.cn

| 接缝 | 现状 | 能否直接承载 `jk.sicau.edu.cn` |
| --- | --- | --- |
| `school.Resolve` | 只认 3 个逻辑名 `jiaowu/auth/webvpn`，`targetHosts` 三项；传 `jk` 或 URL 返回 `CodeTargetDenied` | **不能**，且二课注解路径是绝对路径常量，不是逻辑名（§一.2 冲突③） [来源: internal/school/targets.go:29-36,70-79; work/iciannong-apk/REPORT.md:37] |
| `Service.Address` | 签名 `(ctx, userID, name, path) → AddressResult{Target, Address}`，产出**经 WebVPN 编码的地址**且「绝不发起任何出站请求」 | **不能**：二课是公网 HTTPS 直连 `jk.sicau.edu.cn:443` + `x-access-token`，不走 WebVPN 编码 [来源: docs/tech/回传端点契约-现有能力底座.md:170-178; work/iciannong-apk/REPORT.md:29,37] |
| `HTTPDoer` 出站闸口 | `Enforce=true` 时 `req.URL.Hostname()` 不在 `AllowedHosts` → `ErrTargetDenied` **零出站**；内建白名单 4 项（jiaowu/auth/webvpn/xsgz），`HTTP_ALLOWLIST` 可配置追加 | **不能「直接」**：`jk.sicau.edu.cn` 不在内建清单，直连会被拒；只能走 `HTTP_ALLOWLIST` 追加或改内建清单 [来源: internal/platform/caps_mock.go:329-358; internal/app/app.go:888-896; internal/config/config.go:40-45; docs/tech/回传端点契约-现有能力底座.md:162] |
| 站点目录 `SiteProfiles` | 10 站逐站实测目录，不含 `jk/h5` | 身份侧也无二课 host 登记 [来源: internal/school/cas/exchange.go:72-113] |

即：**三个现成接缝都不能直接承载**；接入要么扩展 `HTTP_ALLOWLIST`（纯出站闸口配置），要么按 ADR-0001 第 1 条新增逻辑目标 + `Resolve` 映射（若要 WebVPN 编码），更本质的是「新增一类出站目标 + 新托管 PU 凭据」（§一.2）。【仓内一手 + 静态判读】

### 5.3 响应信封差异（新仓 `{code,message}`+camelCase vs 二课三套壳）

- **新仓**：统一错误响应 `ErrorResponse{Code string \`json:"code"\`, Message string \`json:"message"\`}`，**成功响应不带 code 字段**；字段名 camelCase；Spec「不动清单」明确「响应信封统一 `{code: string, message: string}` + camelCase，不照抄旧 Track 的 `{ok,data}` / snake_case」。【仓内一手】[来源: internal/apperr/gin.go:10-17; docs/tech/决策-Spec收口方式.md:12,51; docs/specs/spec-六类常见功能.md:58-60; internal/school/jiaowu/handler.go:49-53]
- **二课三套壳并存**（DEX 字段级证据）：
  1. `BaseResponse<T> { int code; String message; T data }`（`common.component`，Rx 侧二课接口走这套；`code=0` 成功、`code=5` token 失效 → `TokenException`）【DEX 静态】[来源: work/iciannong-apk/REPORT.md:60-67; work/iciannong-apk/dump/ALL_API.md:7]
  2. `RespVO { String code; Object data; String message }`（`data.vo`）——**code 是 String**【DEX 静态】[来源: work/iciannong-apk/REPORT.md:65; work/iciannong-apk/dump/vo/tiangong.com.pu.data.vo.RespVO.txt:3-5]
  3. `BaseRespVO { String code; String message }`（`data.vo`）——**无 data 字段**【DEX 静态】[来源: work/iciannong-apk/REPORT.md:65; work/iciannong-apk/dump/vo/tiangong.com.pu.data.vo.BaseRespVO.txt:3-4]
- **四处差异**：① `code` 类型 `int`（BaseResponse）vs `string`（RespVO/BaseRespVO/新仓）；② 二课有泛型 `data` 载荷且三套壳并存，新仓成功响应各端点自定义、无统一 `data` 包裹；③ 二课 `code=5` → 全局跳登录的语义，新仓 `school.Code` 五个常量（`ticket_expired/session_expired/campus_unreachable/blocked_redirect/target_denied`）与 identity 十个码都**没有 token 失效对应码**；④ 二课 VO 字段本身是 camelCase（如 `totalHours/appealCount/goodFaithValue`，与「服务端给什么显示什么」一致），与新仓 camelCase 对齐，但「统一信封」口径不同。【DEX 静态 + 仓内一手】[来源: work/iciannong-apk/REPORT.md:173-206,221; internal/school/targets.go:44-50; internal/identity/identity.go:35-53; work/iciannong-apk/dump/ALL_API.md:7]
- 另：`previewReportCard` 是**相对路径**（无 `/act/` 前缀、`retrofit2.Call`），与其余「绝对路径注解」不同；代请求复刻须逐条保留前缀形态。【DEX 静态】[来源: work/iciannong-apk/REPORT.md:146; work/iciannong-apk/dump/ALL_API.md:38,125-131]

## 新仓约束清单（跨六问题，长期不可破）

1. **README 五条架构约束**：①业务域之间不互相 import、协作走 `internal/app` 装配层；②业务域只依赖 `internal/platform` 接口，不直接 import 数据库驱动 / S3 SDK 等实现；③进程无状态，状态外置 DB/缓存/对象存储；④域内自带 handler/service/repo 接口；⑤不提前建 `pkg/utils`、`common` 垃圾场包。【仓内一手】[来源: README.md:42-48]
2. **SDD 流程**：PRD → Spec → 技术方案（按需）→ 实施计划 → 编码 → 人工 Review；「业务接口开发前须先补 PRD 与 `docs/specs/` 下的规格，禁止无规格直接写业务代码」；仓内先例是「一个 effort 一份 Spec」。【仓内一手】[来源: README.md:77-80; docs/tech/决策-Spec收口方式.md:11,16-17]
3. **ADR-0001 是 accepted 硬约束**：第 1 条固定白名单、第 2 条每请求归属已认证用户、第 3 条票据下发本人且不落日志、第 4 条「客户端直连学校的只读请求不经后端，后端无法限流也无法审计」是被显式接受的盲区、第 5 条不跟随真站 302 / 不回显非必要 Set-Cookie。二课接入若改目标集合或新增凭据边界，须走 ADR 修订而非代码里偷加。【仓内一手】[来源: docs/adr/0001-服务端代请求边界由新后端重写.md:21-31,40-45]
4. **脱敏铁律**：票据/密码（含学校密码镜像）/身份证号/验证码/上游响应体一律不得进日志、审计、埋点、错误信息、接口响应；`AuditEntry`「只允许放标识性字段，绝不添加票据、密文、验证码、上游响应体」。PU `x-access-token` 作为新凭据须同样受此约束。【仓内一手】[来源: docs/adr/0001-服务端代请求边界由新后端重写.md:27; docs/adr/0002-身份仓数据边界.md:21-23,28-45; internal/platform/mail.go:398-399; docs/tech/持久层结构.md:62]
5. **`HTTPDoer` 是「后端有没有权发外部请求」的唯一闸口**：业务域不得绕过它直接用 `http.DefaultClient`；`Enforce=true` 强制白名单 / 超时 / 不跟随真站 302 / 剥离 Set-Cookie，白名单外零出站（连 tcp 都不建）。【仓内一手】[来源: internal/platform/caps_mock.go:329-358; docs/tech/回传端点契约-现有能力底座.md:162; docs/research/六类常见功能-旧农屿一手契约与新仓现状-结论.md:68]
6. **信封不动清单**：`{code:string, message}` + camelCase、成功不带 code、不照抄 `{ok,data}` / snake_case；二课三套壳若要映射，映射层须放在接入边界、不改全仓口径。【仓内一手】[来源: docs/tech/决策-Spec收口方式.md:48-54; internal/apperr/gin.go:10-17]
7. **收口范式**：参照 `docs/specs/spec-教务查询与缓存.md`（Problem Statement → … → Testing Decisions → Out of Scope → Further Notes）与 `docs/tech/决策-Spec收口方式.md`（pending 分四层：①阻塞开工须写死 ②施工期可定 ③留后续 effort ④需实测须标注未验证）；结论笔记只收结论与索引、不粘贴全文，末尾列「仓内未找到／待 HITL」。【仓内一手】[来源: docs/tech/决策-Spec收口方式.md:21-39,48-55; docs/specs/spec-教务查询与缓存.md:1-60; docs/research/六类常见功能-旧农屿一手契约与新仓现状-结论.md:3-6,74-83]
